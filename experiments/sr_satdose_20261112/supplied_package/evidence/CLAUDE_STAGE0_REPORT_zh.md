## 2. 简短结论

1. 【包内复算】GPT 的数字和 Claude 的绝大多数数字都能从包内精确复现。两处分歧都来自口径：
   - α 的编码。GPT 的 α = −1.151 是 ±½ 编码。按它自己写的 0/1 编码，α = **−1.609**。
   - G−R、D−R 的加权方式。逐回答加权时为 +3.69/+2.27pp（GPT），root 等权时为 +4.84/+3.59pp（Claude）（`out/taskA_authority8.txt`；`out/taskB_noise.txt` B2）。
2. 【包内复算】起点 b0 R24 有强烈的清单先验。规则指定图表时，选 chart 集合 16/48，选 list 集合 28/48。规则敏感性的点估计为正（Δ = +16.7pp，γ = 0.92），但 root bootstrap 95% 区间都包含 0：Δ 为 [−4.2, +37.5]pp，γ 为 [−0.30, 2.46]；不一致的 root 是 7 对 2，符号检验 p = 0.18。b0 父模型（Δ = 33pp，区间 [17, 54]）和 b1 的规则敏感性则明确存在。
3. 【包内复算】评估与训练都使用公共随机数（CRN），这是本次最重要的新发现。
   - 评估：生成 seed 只取决于 (parent, panel, root, draw)，不随 arm、step、view 变化（`LOCAL/build_plan.py:20,128`；`LOCAL/audit_frozen.py:106`）。b0 R24 两个 seed 在 176 题冲突面板上有 88.6% 的 A 相同；同一检查点的两次独立 draw 只有约 64% 相同。
   - 训练：同一 seed 下，R、G、D 的题目和 group seed 相同。共享提示的 rollout 指纹在第 17–24 步仍有 91–94% 完全相同（`out/taskB_training_crn.txt`）。
   - 所以 12 条路径实际上是 4 条几乎相同的轨迹加上局部扰动。六路径 SD 1.82pp 不是 A/A 估计。
4. 【包内复算】噪声先验。同臂跨 seed 的 6 对差值，在 176 题面板上的 RMS 为 2.39pp（df = 6，95% [1.54, 5.26]），与 root bootstrap 抽样 SE 2.71pp 相当，检测不到额外的路径级方差。建议：单个 T1−T0 对比的 run 级 SD 按 3pp 规划，敏感性分析取 0 和 5pp；前提是 T0/T1 沿用同一套评估 seed（第 4.B 节）。
5. 【包内复算】J 的优势从不与"选对授权集合"反向，所有分层中方向为负的组为 0。但实测有效剂量明显低于独立同分布模拟。两父合并的 D/LIST 冲突组：
   - signal 组 44/64 = 0.69，模拟为 0.98；
   - 每组定向剂量 1.88，模拟为 2.76；
   - 差距来自题目异质性，组内 ICC 约 0.24（选择）和 0.44（选对时的 J）；
   - 在 signal 组内，η² = 0.67，与模拟的 0.61、闭式解的 0.57 接近（`out/taskC_training.txt` C(c)；`out/taskE_icc_training.txt`）。
6. 【包内复算】证书与来源选择在争夺优势方差。b0 D/LIST 冲突组（训练时 q = 0.56）中，来源选择解释 0.46，授权回答内部的证书差异再解释 0.51，两者合计 0.97。标准 TIES 题（b0 R）上，证书解释约 0.81，来源只解释 0.19。在 SR-ORD-TRAIN 中，J 主要在教证书（`out/taskC_training.txt` C(d)）。
7. 【包内复算】R_source 相对 J 的"纯增量组"是 J 全 0、来源却有混合的组。b0 D 的 LIST 有 6/32，REPORT 有 10/32；两父合并为 7/64 和 15/64。这些组里 R_source 新奖励的授权回答，**证书 100% 不充分**，A 和 B 的正确率为 93–100%。R_source 带来的新信息与它的目标错配落在同一批回答上（`out/taskC_jsilent_composition.txt`）。
8. 【简化模型】T1 剂量预测。起点 p = 0.34、q = 0.79，采用训练中测得的异质性，预测每条路径约 205 个 signal 组，定向剂量总和约 630。这约为 SR-ORD-TRAIN 中 b0 D 路径冲突剂量（约 38）的 17 倍。独立同分布模拟给出约 265 组、约 820，高估约 30%。异质性模型在已有训练组上回检，误差约 10–14%（`out/taskE_icc_training.txt`）。
9. 【包内复算】主终点 transfer8 的操纵没有按设计生效。
   - 完整逆字母序列举只有 0.3–0.8%；conflict 视图的 A 反而比 aligned 高 19.0pp（26 个端点合并）。
   - 2 选 1 平局中，选择主要受"字母序在前"支配：conflict 视图 72%，aligned 视图 45%。
   - b0 R24 的 conflict 视图里，平局块有 86% 按要求的逆字母序列举，但选择没有跟随，自列举耦合只有 43%（`out/transfer8_summary.txt`；`out/taskD_transfer8_2c1.txt`）。
10. 【包内复算】起点的机制基线（176 题冲突面板，两个 seed 合并，共 352 条）：
    - 平局块按清单序列举 275/352 = 78%。其中选清单集合 199/275 = 72%，选图表集合 59/275 = 21%。
    - 按图序列举的回答，选图表集合 60/61 = 98%。
    - prefix 颠倒后跟随前缀：严格评分 29/64，补括号敏感性分析 42/64；严格评分下 UNKNOWN 为 28/64。
    - b1 与 b0 的差别主要在列举习惯：按图序列举 152/352 对 61/352。两者的耦合程度相近（`out/taskD_joint_table.txt`）。

### A. authority8 四分类与 α、γ

**结论**

### B. 冲突面板、版本差异与噪声先验

**面板构成**：context8/list_conflict 24 + swap8/p0l1 64 + swap8/p1l0 64 + authority8/chart 24 = 176 条/端点。四块分别的计数见 `out/taskB_noise.txt` B1。

**两种算法的差异来源**（第 24 步，单位 pp，`out/taskB_noise.txt` B2）

| 加权 | b0 G−R（11031、11032、均值） | b0 D−R |
|---|---|---|
| 逐回答（GPT） | +3.41、+3.98、**+3.69** | +1.14、+3.41、**+2.27** |
| root 等权（Claude） | +5.62、+4.06、**+4.84** | +2.50、+4.69、**+3.59** |
| 只看 context8/list_conflict（24 条） | +8.33、+8.33 | +8.33、+12.50 |
| 只看 swap 冲突（128 条） | +1.56、+3.91 | +0.00、+2.34 |

- root 等权时，swap 的每个 root 有 4 条回答，context8/authority8 的每个 root 只有 1 条，于是后两块被加重。而 context8 恰好是差值最大的一块。
- 两种算法都对，只是估计量不同。我推荐逐回答加权，因为它与冻结的 analyze 口径一致。
- root 配对 bootstrap（两个 seed 合并）：G−R 为 +3.69pp，SE 1.80，95% [0.00, 7.10]；D−R 为 +2.27pp，SE 1.82，95% [−1.14, 5.68]。
- b1：G−R −0.85pp，D−R −1.42pp，方向与 b0 相反。

**解码设置与 draw**（代码事实，来自 `out/taskF_code_facts.md` §6，关键行已抽查）
- 训练与评估都是 temperature 1、top_p 1、top_k 0、do_sample、max_new_tokens 1536。
- transfer8 和 swap8 每个 (root, view) 有 draw 0 和 draw 1，是同一 input、不同 seed 的两次独立采样（`seed_semantics = independent_per_draw_torch_generator`）。
- 评估 seed = `seed_for(2026110301, 'eval', parent, panel, root, draw)`，**不含 arm、step、train_seed、view**（`LOCAL/build_plan.py:20,128`；`LOCAL/audit_frozen.py:106`）。所以同一 parent 的 13 个端点之间是 CRN。
- 训练 draw seed 由 group_seed 派生，在 R、G、D 之间共享（`LOCAL/build_plan.py:91`）。

**方差分解**

1. **生成抽样噪声**（同一检查点、两次独立 draw，B3）：b0 第 24 步六条路径，swap 冲突视图上 A 不一致 140/384 = 36.5%，即单题伯努利方差约 0.18。
   - 如果两个端点各自用**独立** seed 生成，176 题面板上路径均值的生成噪声 SD 约 3.2pp，差值的 SD 约 4.6pp。
   - 实际上各端点共用 seed。b0 R24 两个 seed 的 A 一致率为 156/176 = 88.6%，而同一端点两次 draw 的一致率约 64%（B3b）。所以端点之间的生成噪声被 CRN 大幅抵消了。
2. **同臂跨 seed 差值**（B4）。这是现有数据里唯一的独立训练重复：两个 seed 的训练 root 完全不重叠（0/2304），rollout seed 也不同。它同时包含训练随机性和生成噪声，所以是上界。

   | 第 24 步 | d（pp） | 该差值的 root bootstrap SE |
   |---|---|---|
   | b0 R / G / D | 0.00 / −0.57 / −2.27 | 2.15 / 2.46 / 3.49 |
   | b1 R / G / D | −2.84 / −4.55 / 0.00 | 2.17 / 3.03 / 2.73 |

   - 6 对的 RMS(d) = **2.39pp**（df = 6，χ² 95% [1.54, 5.26]）。b0 三对为 1.35pp（[0.77, 5.04]），b1 三对为 3.09pp（[1.75, 11.54]）。
   - 平均 SE² 对应 2.71pp。超出抽样的方差为负，所以总体层面的 run SD 点估计约 0；用 RMS 的上界估算，最大约 4.5pp（`out/derived_arithmetic.txt`）。
   - 第 12 步的结果相同（RMS 2.38pp）。
3. **root 级离散**（B5）：b0 R24 的 80 个 root 上，root 均值 A 的 SD = 0.379；A = 0 的 root 有 38/80，A = 1 的有 12/80。
4. **训练层面的耦合**（`out/taskB_training_crn.txt`）：同 parent、同 seed、同 step、同槽位、同 draw 时，R 对 D 在共享提示的槽位上指纹完全相同的比例：第 1 步 100%，第 17–24 步 91.4%。提示不同的槽位为 13–28%。

**建议的噪声先验**（用于 T1−T0 单次对比）
- 在 176 题级别的冲突面板上，**沿用同一 seed 公式（CRN）** 时，单个起点内 T1−T0 差值的总 SD 约 2.4–2.7pp，其中包含题目抽样。
- 总体层面的 run 级 SD 规划值取 **3pp**，敏感性分析取 0 和 5pp。f22 的网格与此一致。
- 自由度为 6（3 + 3）。
- 假设：
  - seed 对之间的差值，与"同一起点、不同训练数据的两条路径"在零效应下可以互换；
  - T1 若真的改变了行为，方差可能更大；
  - T0/T1 的评估沿用同一 seed 公式。
- 不能支持的推断：
  - b0 R24 分叉路径在训练种子总体上的方差；
  - 有效应时的方差；
  - 换 parent 后的情形。
- 如果评估**不**沿用 CRN，生成噪声本身就会让单个差值的 SD 增加约 4.6pp。

### F. 训练目标的代码事实

全文见 `out/taskF_code_facts.md`。由子代理撰写，我抽查了带 ✓ 的条目。

- **损失**：`loss_i = mean_t[−w·min(A·ratio, A·clip(ratio, .8, 1.2))] + 0.02·mean_t[expm1(ref−cur) − (ref−cur)]`。逐条执行 `(loss_i/128).backward()`，128 条等权累加，每条先在序列内取 token 均值。✓ 见 `LOCAL/execution/historical_readonly/native_source/src/sr_f6/objective.py:13-14,63-81`；`LOCAL/adapter/training.py:248-249,283`。
- **优势**：(J − 均值)/总体 SD，不加 epsilon，零方差组为 0（`LOCAL/adapter/training.py:38-48`）✓。零方差组 3038/4608 = 65.9%（`out/misc_checks.txt`）✓。这些组仍计入 1/128 的分母，并且仍贡献 KL 梯度。
- **PPO 裁剪**：`old = current.detach()`，所以 ratio 恒为 1，裁剪从不生效 ✓。
- **TIS**：权重为 min(2, exp(train − sampler))，截断比例在 288 次更新中全部为 0（`out/misc_checks.txt`）✓。
- **KL**：在 loss 里，系数 0.02，k3 形式。参考策略是路径起点的父 LoRA，整条路径固定。
- **Mask**：只有生成的 token 参与。prompt 和 prefill `{` 只作上下文；采到的 EOS 计入；上限 1536。
- **优化器**：AdamW，lr 1e-5，wd 0，常数学习率，每条路径新建。全局梯度裁剪阈值 1.0，但裁剪前最大范数只有 0.375，从未触发。只训练 496 个 LoRA 张量（r = 8），FP32。
- **第 24 步 checkpoint**：按代码 schema 和回执中的 hash，含 LoRA 策略、AdamW state_dict、调度器、RNG、sampler_state，不含 reference 张量。Adam 内部键名需要打开 state.pt 才能确认，标为未确定。评估加载时只恢复策略。
- **干跑方案**：见该文 §8。要点：
  - 复用 `objective.sequence_loss`，并把 native 项和 KL 项分开反传；
  - R_source 的优势按同一公式另写；
  - 取裁剪前的梯度；
  - 精度必须 FP32、eager、关闭 TF32；
  - 计算范围限于 496 个 LoRA 张量；
  - 恢复第 s−1 步的策略，并配上父模型 reference；
  - 绝不在没有 hook 的情况下调用 `update()`。

**为什么不能构造连续终点**
- 只知道被采样那个类别名 token 的概率，不知道另一个平局成员的概率。
- 在 `selected` 中写某个类别时，竞争者还包括尚未写出的 B 成员（顺序无关），所以 1 − p 不等于另一个平局成员的概率。
- 唯一能算的是单侧量：被采样选项在决策位置的概率。对 2 选 1 平局，它只给出 log-odds 的下界，而且与来源方向无关。

**怎样才能得到连续终点**【待验证】
- 需要对冲突题做 teacher-forced 前向打分：在决策位置分别代入图表首选和清单首选的类别名 token，读出两者的 log p。
- 这不生成、不更新参数，但要加载模型、占用 GPU，超出本次范围。
- 它可以和第 8 节第 1 项的干跑共用同一套前向代码（`LOCAL/adapter/training.py` 的 teacher probabilities 路径）。

## 5. 逐条回答 GPT 的八个问题

### Q1 公式：η² = q(1−p)/(1−pq) 何时成立？更可靠的经验对应量是什么？

**结论**：这个公式描述的是"给定一组既是 J 混合又是来源混合时，优势方差中来源选择占多少"。在 signal 组内，它与实测接近，偏差在 ±0.15 以内。它的主要缺陷不在 η² 本身，而在两处：
- 把"有多少组是 signal 组"当成接近 100%；
- 把每组剂量当成 i.i.d. 值。

更可靠的经验量有三个：signal 组占比、每组定向剂量 Σa(c − c̄)，以及 signal 组内的 η²。三者都可以在真实的组内标准化下直接测量。

**支持证据** 【包内复算】
- D LIST 两父：signal 组内 η² = 0.67，闭式解 0.57，同 p、q 的 f22 模拟 0.61。b0：0.48、0.38、0.44。
- 但 signal 组占比为 0.69（模拟 0.98），每组剂量 1.88（模拟 2.76）（第 4.C 节 c）。
- 成立条件：
  - 跟随捷径者的 J 恒为 0。实测 LIST 1/157、REPORT 0/308，基本成立。
  - other 和 inadmissible 也算作 J = 0 的"非授权"。实测 J 为 0/53 和 1/10，所以把它们并入 c = 0 不会产生方向错误的信号；η²_cls 与 η²_bin 相等。
  - 题目同质、回答独立。**不成立**：选择的 ICC 约 0.24–0.27，J|选对的 ICC 约 0.44。

**反证**：q 很低时（b0 REPORT，q = 0.40），实测 η² = 0.72，远高于闭式解 0.35。原因是 signal 组被筛选成"刚好有人既选对又过了证书"的组。所以在稀有成功时，η² 在 signal 组上的条件均值会偏高，不能单独拿来当门槛。

**不确定性**：分层组数少（每层 32–64 组），η² 的四分位距很宽（见 tab 中的 q1、q3 列）。

**建议**：准入用"每个计划组的期望定向剂量"（E[dose] = signal 占比 × signal 组内剂量），并直接在干跑的 64 组上测。【待验证】

### Q2 奖励：R_source 在 J 全 0 而来源混合的组里能加多少？怎样避免错配？

**结论**：
- 有增量，而且集中在 REPORT 渠道：b0 D 为 10/32 组，两父为 15/64；LIST 为 6/32 和 7/64。
- 但增量与错配是同一件事。这些组里，R_source 新奖励的授权回答证书 100% 不充分（LIST 20/20，REPORT 31/31），A 和 B 的正确率为 95–100%。
- 如果给 R_source 加上"证书充分"的门槛，这些组的增量就消失，R_source 退化回 J。如果只加"A 正确且 B 正确"的门槛，几乎不会损失增量，但证书错配完全保留。

**支持证据** 【包内复算】
- 第 4.C 节 e 和 `out/taskC_jsilent_composition.txt`。
- 在全部 R_source = 1 的回答中，A 错 0–5%，B 错 0–5%，证书不足 25–60%（b0 D LIST 为 58/131，b0 D REPORT 为 30/50）。

**反证**：λ 较小时（0.25），J + λR_source 与 J 的优势相关仍有 0.87–0.93（LIST）。符号改变主要发生在 J 沉默的组里：那些回答原来优势为 0，现在变成非零。混合组里的排序基本不变。

**不确定性**：这些都是奖励层面的量。增量能否转化为参数更新上的来源方向，需要干跑。【待验证】

**怎样避免**：
1. 用 J + λR_source，不用纯 R_source。J 保证证书仍然占主导；λR_source 只在 J 沉默时提供方向。
2. R_source 只奖励 exact 授权集合，不奖励"没跟清单"。实测 other 和 inadmissible 在冲突组中占 9–14%，"反清单"奖励会误奖它们。
3. 事先登记 unknown 记作 0 还是整组排除。两种处理的结论相同（UX 与 U0 的差别不超过 2 组）。

### Q3 梯度：J 梯度与来源状态梯度的余弦能否预测训练差异？

**结论**：只能作为局部的一阶诊断，不能预测多步训练的差异。代码事实使这个诊断比一般情形更干净：
- ratio 恒为 1，裁剪不生效；
- TIS 权重约等于 1；
- 全局梯度裁剪从未触发；
- 所以 PG 项就是 (1/128)·Σ A_i·(1/T_i)·Σ_t ∇logπ。

**各项怎么处理**（代码事实来自 `out/taskF_code_facts.md`）
- **标准化**：两种奖励都用同一个组内公式（总体 SD，零方差为 0）。R_source 需要另写函数，因为 `native_j_advantages` 只接受二值 J。
- **PPO 裁剪**：在 `old = current.detach()` 的写法下无效。如果干跑时换用别的 old，就会引入原训练中没有的裁剪。
- **KL**：不依赖奖励，系数 0.02。比较方向时必须把它从两种梯度中都去掉，或者单独报告，否则会人为抬高余弦。
- **token mask**：只算生成的 token，序列内取均值，每条等权。不能改成全局 token 均值。
- **估计噪声**：按组做 split-half，得到两种梯度各自的自余弦作为下限。
- **Adam**：真实的 Δθ 经过 Adam 预条件。若新路径从新建的优化器开始，第 1 步约为 lr·sign(g)，方向与 g 不同。如果要预测更新方向而不是梯度方向，需要恢复 Adam 状态。代码 schema 显示 state.pt 存有该状态，但键名未确认。

**只能等干跑的**：
- 余弦本身。奖励层面的优势相关为 0.56–0.70（冲突组），但每条回答的梯度向量 h_i 在同一组内高度相关，所以梯度余弦不等于优势相关。
- split-half 噪声下限。
- 对保留集上来源对数几率的一阶预测。

**不确定性**：单步梯度只看初始方向。真实训练中 q 会上升（q 从 0.20 到 0.78 只用了 24 步），η² 随之改变，所以余弦本身也是步数的函数。【待验证】

### Q4 authority：现有数据是否说明已有规则敏感性？T1 之后 α 与 γ 的变化如何解释？

**结论**：
- 父模型 b0 和 b1 都有规则敏感性，Δ 分别为 33pp 和 33–38pp，区间不含 0。【包内复算】
- 起点 b0 R24 的点估计为正（Δ = 16.7pp，γ = 0.92），但 24 个 root 下区间包含 0（第 4.A 节）。
- 起点同时有很强的清单先验：0/1 编码下 α = −1.61，即规则指定清单时 P(chart) = 0.17；规则指定图表时 P(list) 仍为 0.58。

**T1 之后的判读**（前提：Δ 差值的 SE 在现有面板上为 5.6–15.7pp）
- **α 上升、γ 不变**：固定的图表偏好提高了，是策略替换。T1 能直接训练出来的就是这一种。
- **P(chart | 规则=清单) 上升**：表示模型在规则指定清单时也开始选图表，即"总选图表"，是对清单权限的覆盖。此时指定来源准确率不升反降。authority8/list 视图的主要价值就是检测这一点。
- **γ 上升**：T1 从不训练"清单有权限"的题，所以这一结果出乎设计预期。在现有功效下，小于约 15–30pp 的 γ 变化看不见，不应把它当作成功指标。
- **γ 下降**：可能是先验压过了规则，也可能只是噪声。需要扩大面板才能区分。

**反证 / 不确定性**：
- 父模型到 R24 的 Δ 点估计从 33pp 降到 17pp。普通 J 训练可能已经在削弱规则敏感性，但这个下降本身同样不显著。
- 12 个 b0 训练端点的 Δ 全为正，但它们共享评估 seed、训练轨迹也几乎相同，不能当作 12 次重复。

### Q5 统计：怎样得到可辩护的 run 级噪声先验，而不虚构 seed 数量？

**结论**：只用同臂跨 seed 的差值，共 6 对（每个 parent 3 对）。不用六路径 SD，也不用臂间差。

**支持证据** 【包内复算】
- 臂间差：R/G/D 在同一 seed 下共享训练题和 group seed，rollout 91–100% 相同。臂间差衡量的是"32 个不同组"的效应，不是独立重复。
- 跨 seed 的差值：训练 root 完全不同，rollout seed 也不同。

**数值**：RMS(d) = 2.39pp（df = 6，95% [1.54, 5.26]），与 root bootstrap SE 2.71pp 相当。

**先验**：单个 T1−T0 对比的总 SD 约 2.5pp（含题目抽样）。总体层面的 run SD 规划值取 3pp，敏感性分析取 0 和 5pp。两个起点合并后的总 SE 约 sqrt(SE_item² + s_run²/2)，其中 SE_item 约 1.8–2.3pp。

**必须满足的条件**：T0/T1 的评估沿用同一 seed 公式（CRN），否则生成噪声会让单个差值的 SD 增加约 4.6pp。

**不能支持**：
- b0 R24 分叉路径的训练种子总体方差；
- 有效应时的方差；
- 换 parent 的外推。

两个起点只剩 1 个自由度，这一点不变。先验是借来的，必须在报告中写明。

### Q6 Stage 2：纯 R_source 会不会牺牲答案与证据？J+λR_source 对 J+λR_shuffled 是否更有因果解释力？最低预算怎么设计？

**结论**：
- **答案（A）和绑定（B）**：纯 R_source 基本不会牺牲。R_source = 1 时 A 和 B 的正确率都在 95% 以上。
- **证书**：会系统性地牺牲。R_source 奖励的回答中 25–60% 证书不足；在它唯一提供增量的那些组里，这个比例是 100%。纯 R_source 对 J 的比较，实际上是"要不要奖励证书"的比较，混淆了两件事。【包内复算】
- J+λR_source 对 J+λR_shuffled（在组内打乱 R_source 标签，保持组内正样本数和奖励幅度不变）更有解释力：它把"额外的奖励方差或密度"与"奖励指向正确来源"分开。【简化模型】

**最低预算设计** 【待验证】
- 渠道：J 沉默而来源混合的组，在 REPORT 渠道占 23–31%，在 LIST 渠道占 11–19%。增量预测在 REPORT 渠道最大，LIST 渠道几乎冗余。
- 起点在 R24 时，q 约 0.79，J 全 0 的组会更少（预测为 27%，第 4.E 节），增量更小。
- 若只有两个训练臂，用 J 对 J+λR_source（λ = 0.25–0.5），放在 REPORT 冲突题上，或放在权限在图表与清单之间变化的题上。
- 先用本数据写下预测：每个 J 沉默的组增加多少剂量，乘以组数，得到预测差异，然后才决定是否开跑。
- 缺少 R_shuffled 臂时，结论只能是"奖励总量与方向的合并效应"。

### Q7 贡献：如果 Stage 1 只改变列举习惯，是否仍值得继续？哪些主张必须放弃？

**起点的机制水平与可检测的变化**（【包内复算】，第 4.D、4.H 节）

| 机制 | 起点水平 | 可检测的 T1−T0 变化（约 2 倍 SE） |
|---|---|---|
| 列举习惯：按清单序列举 | 78.1%（SE 3.5pp） | 约 10pp |
| 自列举耦合 | 72–73%（SE 5pp） | 约 12pp |
| prefix 翻转（严格） | 45%（SE 7.2pp） | 约 20pp |
| authority Δ | 17pp（SE 11pp） | 约 30pp（独立情景） |

**要点**：如果 T1 改变了列举习惯，"列举 ≠ 图序"的子集会缩小，自列举耦合的分母随之萎缩，耦合率就更测不准。prefix10 是唯一不依赖列举习惯的耦合测量。

**仍值得继续吗**：值得，但贡献要降级。只改列举习惯也说明两点：RL 能移动这个行为；RL 走的是最便宜的路线。这正是 Claude 的预测；b1 与 b0 的差别也主要在列举习惯（第 4.D 节）。这本身是一个可报告的机制结论。

**必须放弃的主张**：
- RL 解除了"选择跟随自身列举"的耦合；
- RL 提高了按权限条件化选择的能力；
- 诊断驱动的训练修复了"上游机制"。只能说它修了表层的列举顺序。

【待验证】T1 是否只改列举习惯。

### Q8 资源：只有四条路径时，是否减少迁移面板，把预算转给 prefix 与 authority？

**结论**：是。优先级如下。
1. **主终点**：清单渠道冲突准确率。用 context8/list_conflict 加 swap8 冲突视图，保持现有规模和 CRN 评估。T1−T0 的 SE 约 1.8–2.5pp。
2. **prefix10**：扩到 96–128 个 root（现有 32）。它是唯一不依赖列举习惯的耦合检验；扩大后，T1−T0 差的 SE 从约 10pp 降到约 5–6pp。必须同时登记严格评分和补括号敏感性分析（严格评分下 UNKNOWN 占 44%）。
3. **authority8**：扩到 72–96 个 root，每个视图 2 个 draw；在独立情景下，Δ 差的 SE 约为 7–8pp。主要用途是检测"总选图表"，即 P(chart | 规则=清单) 上升，而不是 γ。
4. **一致视图与 retention8**：维持最小规模，用来守住一致题表现和非劣性。
5. **transfer8**：缩减或移除。它占每个端点 384/1024 条预算，但操纵没有核验通过（第 4.D 节），在 T0/T1 中也没有设计角色。

以上是【包内复算】给出的功效数，加上【简化模型】的规模外推。
