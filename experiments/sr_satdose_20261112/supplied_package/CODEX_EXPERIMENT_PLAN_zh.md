# SR-SATDOSE-1：面向 Codex 的最终执行计划

版本：2026-11-12 / v1.0。用途：新实验的实施、验收、有限训练与可解释交付。

**基本原则：不能保证训练一定改善模型；必须尽可能在长实验之前排除错模型、错任务、错奖励、错梯度、无有效信号、测不到目标行为和统计口径错误。**

本包的“已测试”仅指 `verification/` 中有真实运行记录的本地 CPU 项目。GPU、模型张量和生产 adapter 未在当前会话运行；须由 Codex 在实际服务器完成下述门禁。CPU PASS 不能替代 GPU PASS。

## 1. 研究问题与本轮边界

### 1.1 唯一问题

对已有 b0 R24 模型，保持原生 J、优化器设置和更新预算相同，**将训练从“清单始终与图表一致”改成“75% 清单冲突”后，模型在新图表的冲突条件下，是否更常选择题目授权的正确集合？**

这里的“授权”在正式训练中始终指图表印刷位置；清单只列出类别，不授权它决定平局次序。

SATDOSE 是本实验代号。“高剂量”指预先设计的大幅增加定向曝光，**不意味着已经证明达到生物学/优化意义的饱和剂量**。

### 1.2 暂时不做

不做 D 对 G、不训练 b1/b2、不加新奖励、不训练 REPORT/前缀/名单权限、不换模型、不调学习率、不加步数、不自动进入语义奖励 Stage 2。不再用未经有效验证的逆字母序作为主终点。

### 1.3 为什么这轮值得做

历史包的独立核查结果：

- 36,864 条训练记录、4,608 个 G8；26,624 条评估回答。
- b0 D 的 LIST 冲突组，两 seed 合计 32 组，21 个同时有 J 和正确选择差异；平均定向剂量约 1.574/组。
- b0 D 的 REPORT 冲突组平均约 0.780/组；本轮不再混入这个较弱渠道。
- 历史存在 14 条 J=1 但选择不正确的回答，不能假设 J 严格嵌套于 S。

这些数字由本包 `tools/audit_historical.py` 重新核对，见 `verification/HISTORICAL_AUDIT.json`；不需要相信前面讨论中的口头总结。它们只支持“原处理弱、值得做有门禁的剂量检验”，不预测本轮一定成功。

| 项目 | 决定 |

| 起点 | b0-11031-R step24、b0-11032-R step24 |

| 更新 | 每路径24步，每步16个不同root，每root 8次采样 |
| 正式生成 | 每路径3,072条，合计12,288条；96次正式优化器更新 |

### 2.1 起点精确身份

完整 SHA 和历史服务器路径已写入 `config/source_bindings.json` 及 `config/experiment.json`。

| 起点 | 原 state.pt SHA256 | policy tensor SHA256 |
|---|---|---|
| R24 / 11031 | `af1876069f9c9a5c7fc1d0b237162f5511b86b0462f3c796c13fbf3b8359bda1` | `bf54236906035d295d2616cc00d9ddf27094c6b572ddee8be3cc1b7c1a243fb6` |
| R24 / 11032 | `a4fd2b6a85d1cf1b84f67ef4b4d76f8b7426c27a46a46fb0d37b1550a623f1a5` | `0cea8f988f9fc99647bd8f8e1d8f733e20000e71ec26b504058b080cccb55ced` |

原 b0 reference tensor SHA256：
`0d7979e13ce408a0501fcd774a26c7643527433de10c64b2b199b695a66d1fb4`。

必须先核验原 state 文件，再从其中提取 policy；不能按“最近修改的文件”找模型。新实验 step0 的文件 SHA 会因新身份/新优化器而不同，但其 policy tensor SHA 必须等于对应 R24。两臂起点逐张量相等。

**加载顺序：先装载并冻结原 b0 reference，再把 R24 policy 覆盖到可训练 policy。** 不能在覆盖后把 R24 克隆成 reference。R24 与原 parent 不同，因此新实验的首步 KL 不要求为零。

### 2.2 数值协议

AdamW：lr=1e-5，betas=(0.9,0.999)，eps=1e-8，weight_decay=0，foreach=False；常数学习率；全局梯度裁剪1.0。KL=0.02，TIS cap=2.0，aux=0。

FP32、eager attention、deterministic、TF32关闭、dropout=0；只训练原496个LoRA张量。microbatch=1，每条回答先取completion token均值，再对128条回答等权平均。G8优势使用总体标准差、无epsilon；全同奖励组优势为0，**仍留在128分母并保留KL项**。

生成：temperature=1、top_p=1、top_k=0、do_sample=True、num_beams=1、max_new_tokens=1536。原 token 路径与 sampler logprob 必须原样保存。不得 retokenize 后冒充原轨迹。

## 3. 数据：先证明“只改清单”，再调用模型

### 3.1 训练槽位

`config/training_slots.jsonl` 已由 `tools/build_schedule.py` 确定性生成并测试，包含1,536个路径组、768个不同训练root、12,288个唯一request_id。

四种结构：2_choose_1、3_choose_1、3_choose_2、4_choose_2。每步各4组，覆盖 largest/smallest × sum/mean。T1 每种结构每步3冲突1一致，一致位置随步数轮转；24步后每个细分cell恰有18冲突6一致。

两个起点使用不同新root；同起点内两臂共享同一数值世界、图像、查询、名字、顺序和采样seed。一个root每路径只出现一次。不根据模型成败挑题。

### 3.2 生成器与渲染器

复用服务器旧 `package_v2` 中实际生成8类别TIES的函数；本地包只有10类别probe生成器，**不能直接将其误当8类别训练生成器，也不能靠从旧评估集抽题凑数**。Codex需在新wrapper中显式导入/只读复制已有8类别构造函数，冻结源SHA。

只允许结构性拒绝采样：边界平局有效、冲突选集不同、所有合法边界候选的Beta聚合结果互异、无跨split数值世界重复。拒绝原因逐次记录，不能调用模型后决定是否保留。

T0保持原图序清单；T1的冲突槽使用预先冻结seed随机排列，在“按名单取边界前r个会改变集合”条件上拒绝采样；最多1,000个候选，失败即HOLD，不偷偷换root。T1一致槽与T0公开输入**逐字节一致**。两臂冲突槽也只允许公开类别清单的排列不同。

### 3.3 必须自动验证的内容

1. 独立sort oracle与枚举k子集oracle在每个任务上一致；选集、绑定、数值答案都比对。
2. 枚举全部边界候选，确认不同候选的聚合答案不同。这减少数值抵消，不消除“selected与answer自相矛盾”的可能。
3. 两臂同槽图像SHA、world、query、名字集合、prefill一致；公开prompt删除唯一清单数组后完全相同。
4. T1冲突槽的chart-set与list-set确实不同；一致槽确实相同；不得只检查清单文本顺序不同。
5. 私有gold、类别标签“冲突/正确答案”、source classification不得进入模型prompt、图像元数据、prefill或工具返回。
6. TRAIN / DRY / DEV / PREFIX_CALIB / MAIN各split在去掉名字后的world-query hash上互斥；同时排除历史训练和已见公开评估中的重复数值世界。
7. retention面板是明确允许重复的旧**公开DEV**，不能读取历史封存TEST。其他新root不例外。
8. 图像逐张结构检查；随机种子固定选32张人工可视检查，覆盖结构/方向/聚合/边界位置。不能只验证PNG能打开。
9. 保存图像数量、尺寸、字体与渲染源码SHA；字体只在服务器引用，交付不附字体文件。

结构检查完成后写 `DESIGN_FREEZE.json`：配置、代码、所有请求manifest、private cases、public inputs、图片索引及oracle报告的SHA。它必须早于第一次模型调用。后续 `ADMISSION_INPUTS.json` 只是汇总实测证据，不能代替事前冻结。

## 4. 零正式更新的准入：DRY 与 GPU 检验

### 4.1 不更新参数的样本

两个R24起点各：64个冲突root × 8回答，另加16个一致root × 8回答，共1,280条生成。

64个冲突root按16个结构×方向×聚合cell各4个；16个一致root每cell1个。两个起点可以共享这80个校准root，校准root不能再用于正式训练或MAIN。

每个起点的64个冲突组分母固定，未知回答不能删掉，J全0组不能删掉。逐回答保存raw/token、native J、native S known、exact authorised、来源类别、证书、完成方式和身份。

**采样失败/OOM/未完成写盘属于技术问题，不能写成 J=0。** length是一次真实已完成采样尝试，其评分按原生定义保留。

### 4.2 组级定向剂量

对G8中的原生J计算

\[
a_i=(J_i-\bar J)/\sqrt{\tfrac18\sum_j(J_j-\bar J)^2},
\]

标准差为0时整组为0。令c为exact authorised选择指示（未知为0并另报未知率），定义

\[
d_g=\sum_{i=1}^{8}a_i(c_i-\bar c).
\]

这是**奖励优势与目标行为的关联统计量，不是真实参数梯度，也不是可跨渠道线性预测效果的通用剂量单位**。eta²、q、J静默且S混合组都报告，但不以eta²≥0.5单独决定开跑。

### 4.3 本轮固定的工程门槛

每个起点都必须满足（这是预算准入标准，不是学习成功定理）：

| 条件 | 门槛 |
|---|---:|
| 冲突组覆盖 | 64完整G8，512条，不多不少 |
| J与c同时混合的组 | ≥32/64 |
| 全64组平均d | ≥1.25 |
| 按root重采样的平均d 95%下界 | ≥0.75 |
| 净方向比例 Σd/Σ|d| | ≥0.95 |
| native S未知率 | ≤5% |
| J=1中c=0的比例 | ≤5%，并逐条列出 |
| 全80组length比例 | ≤2% |

这个平均剂量门槛对应288个冲突组的点规划≥360、保守规划≥216。对照历史b0 D每路径LIST+REPORT合计约37.67，约为9.6倍/5.7倍；**这只是初始状态下的规划外推，不声称后续每步相同**。报告真实累计剂量。

门槛未过即 `HOLD_DRY_SIGNAL`。不允许从80组里挑“好学的”组，也不允许临时加样本直到通过。若起点本身已接近正确率上限，应记录“目标在该分布上缺乏改善空间”，而非硬凑更多梯度。

### 4.4 梯度方向检验

只复用真实生产loss，不用新写的近似GRPO替代。细节见实施文档。

固定使用12个冲突组+4个一致组组成128条训练型探针batch；从其余冲突组预先选16个root作为独立目标梯度的witness，不能按回答是否正确来挑。完整batch与两半的映射在模型调用前冻结。

分离J policy-gradient、source-only诊断gradient、KL gradient；比较PG时不混入共同KL项。用实际fresh AdamW计算一次**影子更新向量**，包含KL与裁剪，但不写回正式policy。

held-out目标梯度采用独立witness上“exact authorised概率”的score-function估计，不能把已采样token的logprob冒充完整候选答案概率。使用leave-one-out组内基线与完整completion的logprob之和；不因生产loss按token均值就把这个概率导数也随意长度归一化。

要求：J/source PG余弦>0；各自split-half余弦>0；两个witness半集上，目标梯度与实际影子更新向量的内积都大于重复计算数值误差底线。两个起点都通过。否则 `HOLD_DIRECTION_UNCERTAIN`，不称“行为不可学习”。

这是一阶方向诊断，不是显著性检验，也不保证24步成功。不得将少量不稳定梯度符号用作搜索超参数/换题的借口。

### 4.5 GPU与影子更新验收

- 同backend、同tokens、同累计顺序下，复制生产J forward/backward，与探针结果逐张量一致；若有差异，先定位，不能改成一个宽泛容差掩盖。
- 496个张量全集一致；完整128条和1536-token压力样本可运行；单卡OOM不能改成bf16或缩短输出。
- 优先沿用经审计的两卡无损saved-tensor backend；单卡与两卡的等价仅在实际测试范围内声明。
- `native PG + 0.02 KL` 与总梯度重组一致；全J0时PG为0、KL仍在；原子更新只有一次。
- 两起点各做“直接一次影子Adam更新”和“恢复同起点后重放同一次更新”的相等性验证，最多4次影子optimizer.step；结果全部丢弃，不作为训练起点，也不新增rollout。
- 原R24 policy/reference/optimizer文件只读，影子试验结束后hash不变。
- raw sampler/teacher数值门槛沿用原native contract；见实施文档。

## 5. 前缀机制面板先校准，避免花推理预算后才发现无法解析

PREFIX_CALIB：16个新10类别root，四结构各4；P_STABLE/P_REVTIE/P_PLACEBO各1 draw，2个起点，共96条。沿用已经验证过的原强制证据前缀，不训练这些题。

预先保留两套读法：

- 严格：原文+真实finish，不修改。
- 单右括号敏感性：仅在EOS、严格JSON解析失败、原文**追加唯一一个`}`**后整体能按相同严格解析器解析时记录；拒绝重复键、非有限数、尾随文本，绝不修改其他字符，不补selected内容。

每起点每view严格或限定补括号后S_known至少14/16；STABLE正确至少12/16；STABLE相对REVTIE的全分母S差至少4/16。否则 `HOLD_PREFIX_MEASUREMENT`，先报告为什么机制面板不具备解释条件；不得悄悄换格式后继续使用原预登记。

这些是小面板可用性检查，不是对机制的确认性检验。正式prefix报告严格全分母结果、限定敏感性结果、覆盖率、unknown差异以及缺失最坏界。条件于“可解析”而得出的率不能单独支撑去耦。

## 6. 正式训练的分段放行

### 6.1 只允许先走前两步

`check_admission.py` 读真实DRY原文，使用SHA绑定的native scorer重新评分，重算剂量，再检查真实GPU证据。通过也只生成 `ADMITTED_FIRST_TWO_STEPS_ONLY`，权限为四路径各至step2。

它不是训练启动器；Codex的新生产wrapper必须再次核对该回执的config/registration/GPU报告SHA，不能只看一个PASS字符串。

### 6.2 前两步必须验证

四路径都从规定起点出发；每步16组、每组8回答。确认：

- step1从R24采样；step2从各自step1的新policy采样。不能训练更新后生成器仍拿缓存旧权重。
- 参数更新非零、reference不变、梯度和KL有限；未改变vision/base参数。
- optimizer与scheduler各一次，step计数正确，COMMIT与state/raw/token/UPDATE闭合。
- 保存step2，退出进程后重新加载；policy、reference、optimizer、scheduler、RNG身份与不中断状态一致。
- 用原tokens teacher-forward验证恢复后的logprob，不需要额外生成评估回答。
- 故障注入测试：Adam前中断不提交；提交后再运行同事务不得重复更新；无法判断是否已生成/已提交时必须HOLD，不能重抽回答。

通过后写独立 `CANARY_RESUME_PASS.json`（含真实文件和hash），才允许24步预算的其余部分。这是工程canary，**不要求step2正确率显著提高**。

### 6.3 后续按8/16/24步封存

尽量四路径分块前进，而不是第一条先跑满。每步记录：真实冲突数量、p/q、J全0/混合/全1、native S、全分母定向剂量、证书、生成长度、数值诊断、policy/reference hash、token数、耗用资源。

DEV固定面板在step2、8、16评估；不重用MAIN。不能因为DEV上的某个检查点更好而把它替换为主要终点。

### 6.4 什么时候暂停

任何身份/源SHA/错题/错图/重复请求/不完整G8/NaN/TIS门槛/未提交状态异常，立即技术HOLD。

预登记的行为风险HOLD只有两类：

1. **信号实际消失且目标未解决**：在T1连续两个4步窗口中，冲突组平均d<0.75、exact authorised训练率<0.80，且最近DEV冲突S<0.80。暂停全部路径，报告 `HOLD_SIGNAL_NOT_DELIVERED`。训练率已高时，d下降可能是学会了，不能误停。
2. **严重能力崩塌**：同一路径在两个连续预定DEV检查点上，一致/无清单合并S比自身起点下降≥20pp，暂停全部路径，报告 `HOLD_SEVERE_REGRESSION`。这是预算安全规则，不是正式非劣性检验。

没有涨分、曲线不单调、单次损失抖动、单个G8全0都不是停止理由。若所有门禁正常但24步无收益，结果是有定义、有剂量证据的阴性实验，不是再追加步数的理由。

HOLD后只允许只读诊断/技术恢复；不自动改变科学处理。如无法恢复，交付部分结果，主终点标“未完成”，不能把缺失路径记0，也不能另换seed补成好看的四路径。

## 7. 评估：只保留能回答问题的面板

### 7.1 正式完整面板（每端点1,952条）

| 面板 | 新root/历史root | 视图×draw | 条数 | 作用 |
|---|---:|---:|---:|---|

| swap8 | 32新root | 图位×清单四格 ×1 | 128 | 改图时应变、只改清单时不变 |
| authority8 | 96新root | 图表权限/名单权限 ×2 | 384 | 检测“一律按图”的替代策略 |

## 8. 统计与成功/停止解释

### 8.1 主估计量

每root先平均2个draw；每起点计算T1−T0；再等权平均两个起点；四个结构等权。128个root为统计重采样单位。

唯一主要终点：step24、list8/conflict、S_hit、T1−T0。另报告T1−自身step0的绝对变化，防止只因T0变差而出现“相对成功”。

在每个结构内按root配对bootstrap 10,000次，同一次重抽携带两起点、两臂、所有draw。95%区间只条件于这四条已训练路径，不推广到训练seed总体。两个起点分别列出，不把生成回答数当独立训练重复。

### 8.2 修正此前讨论里相互重叠的判定规则

不再用“下界>5pp就是成功，同时上界<10pp又算失败”这种会重叠的分类。固定SESOI=10pp：

| 区间 | 标签 |
|---|---|
| 下界≥10pp | 有达到实用阈值的条件证据 |
| 下界>0、上界<10pp | 可检测的正向变化，但低于实用目标 |
| 下界≤0、上界<10pp | 在固定路径条件下排除≥10pp效果；不等于证明精确零效应 |
| 下界>0、区间跨10pp | 正向证据存在，实际大小未确定 |
| 其余 | 未确定 |

同时列两个起点的相对差与绝对增益。后续是否值得投入，至少综合主点估计、条件区间、两个起点方向、T1绝对增益、A/J/保持与机制面板；**本轮无论得到什么标签都不自动启动Stage2**。

### 8.3 训练噪声只作敏感性，不伪装成估计精确的CI

借用0/3/5pp作为“单个起点T1−T0额外run噪声SD”的假设，给出在bootstrap上额外加入Normal(0,s/√2)的敏感性区间。3pp不是本轮估出的真实方差；旧6对差异并非足以支持精确新run方差估计，也不能在结果出来后挑最有利的SD。

step8/16的曲线仅描述训练轨迹；累计定向剂量与效果的相关关系不是随机化剂量—反应因果曲线。不要把list渠道的斜率外推成REPORT/新奖励的效果预测定律。

### 8.4 三种行为变化分开写

- 列举顺序改成图序，而选择仍跟自己列举：列举习惯改变。
- 列举仍乱，但强制前缀对选择的影响减弱：支持特定顺序依赖降低；仍不直接证明唯一内部机制。
- authority不同规则下行为能正确切换：条件化规则使用的额外证据；T1未训练名单权限，属于迁移，不得说它在设计上“不可能改变γ”。

alpha使用0/1编码时是logit P(chart|list-rule)；若用居中编码必须另名alpha_mid。它们不可混用。互信息高也不保证遵循正确规则，不能用互信息替代授权正确率。

只在“列举不等于图序”的回答子集计算耦合会受到训练后分母变化影响，必须同时给边际分布与完整联合表；不把条件相关直接称为因果中介效应。
