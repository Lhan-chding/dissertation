# 02｜题组：每种变化为什么存在，怎样避免混杂

## 2.1 题目单位与输入输出
一张图的事实世界记为 world；root 是共享基础世界及受控变化的一组谱系；一个 root 固定四题 variants。模型每次只看**当前图像和当前问题**，从不看到隐藏事实表、正确集合、答案、root身份、相邻题答案或题目生成元数据。

同root四题分别各采G8，形成四个独立优势组，不把32条回答混在一起归一。一个训练step放4个完整root×4题×8回答=128条。这保持题组曝光完整，同时避免跨题难度混入组基线。不同题独立上下文，不沿用KV cache到另一题。

## 2.2 公共世界约束
- 6或8个无天然顺序的商品标签（Mug、Lamp、Desk、Vase、Chair、Clock、Tray、Book），印刷顺序随机；不使用月份、星期，也不以P01、P02的编号顺序暗示区间顺序。
- 两列Alpha/Beta，范围[10,90]；主要数据的数值取12,18,…,84，任务只含已支持的TOPK/INTERVAL、sum/mean、Alpha/Beta/Alpha−Beta。
- 柱状图纵轴0–100，至少3源像素/值单位，无逐柱数值标签；主图区分度来自不小于6的格点，不靠1像素排序差制造“语义难度”。检查模型processor缩放后的最小标签像素和柱间距，而不是只检查原PNG。
- 主任务的均值答案构造成整数或有限小数；不是改变精确评分。非终止小数和离格点数值放入单列压力测试，防止分数书写学习掩盖主机制。
- 格点只是构造手段，不能作为充分证据验证器的隐藏推理前提；判定器只能使用公开范围、题意与实际提交事实。

## 2.3 六个家族的明确职责
|家族|四题如何构成|要探查什么|避免的错误解释|
|---|---|---|---|
|BINDING|在同世界交叉排名列与取值列A→A、A→B、B→A、B→B|是否把“按哪列选”和“用哪列算”分开|两列恰好选同一集合不等于真的理解绑定；记录集合重叠|
|IMPACT|Q0基础；Q1改一个被选对象的取值+6；Q2改未选对象+6；Q3被选对象−6，排名列不动|选择错误的数值碰撞、相关性与不相关性|只改Beta/取值列，不能同时改变排名；逐题oracle确认选择不变|
|TIES|边界同值；交换并列成员印刷位置；分别改变所选对象取值|是否执行明确的印刷顺序破同值|交换并列对象通常会改变正确集合，不可误标为不变性|
|SIGNED|同世界，k=2/3的有符号差，sum与mean配对|选对象与数值聚合分离；负数、差值与除数|只用最终答案不能声称定位执行；直接声明集合与答案分开评分|
|INTERVAL|中性类别、明确印刷位置区间，四种端点包含组合；部分root另加Alpha>Beta筛选|两阶段“区间→条件筛选”的最终集合|不得把候选区间当最终集合；不再混入日历语义|
|K_DIRECTION|k=2/4与最大/最小组合|数量与方向是否按题改变|数组长度正确不等于选择正确；结构校验不提前奖励k正确|

实现参考 `generator.py`。每个构造失败只能因**预先定义的数学约束**（越界、空集、主面板非有限小数、禁用组合）有限重建，记录attempt及理由；绝不因父模型答错/信号弱而逐题拒绝采样。最多128次，失败则开发异常而非换一个未经登记seed。

## 2.4 IMPACT 的可核查推导
固定按Alpha选k个对象，再对Beta求sum或mean。选择集合I只由Alpha与印刷顺序决定。若修改Beta_j增加δ且不改Alpha，则I不变。

sum: y'−y = δ·1[j∈I]。
mean: y'−y = δ/|I|·1[j∈I]。

Q1/Q3修改被选项，Q2修改未选项。只在oracle确认集合完全不变时标为上述关系。每第三个基础root人为令边界内外两个对象的Beta相同，构成**预先设计的碰撞子层**；另外两个root不强制造成碰撞。碰撞root及其后代全部留在同split，报告分层而不把富集分布解释为自然发生率。

若模型两题都带相同偏差，也能满足差值关系，因此同时报告绝对答案、关系一致和四题联合全对。关系分不能替代主答案分。

## 2.5 正式未见组合：必须全局扫描，不只是换新数值
COMPOSITION固定6种保留连接：
1. Beta排名 + Alpha取值 + mean。
2. Alpha排名 + diff取值 + smallest + mean。
3. 排名边界出现同值 + smallest。
4. diff取值 + k=4 + mean。
5. INTERVAL + positive_only + mean。
6. k=4 + smallest + mean。

训练中**任何家族、任何变体**满足任一保留谓词都不能进入训练。测试每个对应root的四题都必须满足其登记目标谓词。`heldout_tags`是可执行定义，不靠文件名声称OOD。

各原子（两列、mean、smallest、diff、k4、过滤、端点等）在训练中出现；并不自动声称每一个二阶子组合都已覆盖。正式构建输出 `FACTOR_COVERAGE.json`，列原子/二阶/高阶出现次数。若论文要声称“只缺一个高阶组合、所有低阶已见”，必须额外满足相应覆盖证明；本轮不预先作这种更强表述。

保留组合是分布定义，CPU可验证。开发普查只生成允许的支持组合，不用COMPOSITION模型结果选参数。

全部旧F4-C测试题及已公开病例均归开发知识。新确认测试不复制这些具体世界；用已知失败机制构造新分布是允许的，但需承认它是问题导向基准。

## 2.7 接口与数值压力面板
每root使用同一个基础查询，四视图：v0新协议基准；v1只换登记渲染样式；v2同图同题改用旧自然工作/最终标签接口；v3只对一个选中值做+1离格点修改，并重新算gold。

v3可能引入非终止分数，用冻结精确分与预先定义的数值近似诊断并列，不回填主分。v2没有selected字段，S记NOT_APPLICABLE，而非UNKNOWN或FAIL。四视图分别报告；不要用其混合均值解释单一原因。

## 2.8 生成与图像验收
两个oracle使用不同选择实现：排序 vs 枚举满足排名条件的集合。必须逐题一致，包括目标集合和分数值。人工/视觉检查不能替代程序证明，程序几何检查也不能保证真实模型看得清。

每家族至少抽8张开发图，覆盖6/8类别、同值、负差和端点；保存实际processor处理后的图/分辨率、文字框、最小间距。审核来源记录human/vision_model/program，不虚构人工确认。开发普查中的P只是提交事实的真实性，不足以证明所有视觉信息都已读对。
