# 给 Codex：执行入口与不可省略事项

你收到的是**设计与实施规范**，不是“马上执行全部训练”的命令。用户要求每部分缜密闭合；正确的执行顺序和真实门控记录属于任务本身。

1. 阅读本目录 README，以及 docs/00、01、02、03、04、05、08。列出原仓库真实对应模块与本包要求的差异，写入 `IMPLEMENTATION_MAP.json`。
2. 保留旧结果、旧 J scorer、旧协议及旧 checkpoint。新分支 `sr-f5-semantic-j-v1`、独立运行根；不复用 F4-C 的训练后权重作父模型。
3. 复跑 CPU 测试，调用历史 scorer 做投影等价验证。检查 `qa/` 是交付者的本地回执，不能代替你服务器环境回执。
4. 优先实现新协议与可靠 selected 读数。不把 Claude 宽容解析器用于训练标签；不以 gold 帮助选择应抽取哪一段文本。
5. 实现 6 类构造与全局 holdout predicates；在全部训练家族扫描禁用组合。正式 root、所有变体、重渲染、反事实后代不得跨 split。
6. 先跑 G2 父模型普查，再跑 G3 开发先导。每次模型调用记录用途、配置、数量、抽样身份；不得把训练预算补贴给看过正式测试后的调参。
7. 数值稳定性先核真实采样 token、上下文和概率语义；不把 reference/current 与 sampler/train 混同，不自动增加 KL 截断或删除极端 token。
8. G0–G4 全部有真实回执后，再启动预登记 45 路径。共享的是问题计划和随机数定义；策略更新后，各臂必须自行 on-policy 生成。
9. 发布所有臂和所有重复的末步结果、失败路径、保持结果与机制计数。不得只保留最佳父模型/种子/家族；不得用奖励分上升替代答案或组合泛化。
10. 最终交付 `REPORT_ZH.md`、`SUMMARY.json`、门回执、完整评测评分与可定位原文、逐步信用和数值日志、图像/任务清单、精确 config/commit/环境标识。
