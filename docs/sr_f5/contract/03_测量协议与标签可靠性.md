# 03｜测量：先定义行为，再定义如何读出来

## 3.1 为什么不把旧宽容解析器直接投入训练
旧原型存在等号截断、取第一个列表、把候选池当最终集合、规则正确与集合正确混同等问题。补正则不能解决所有语义消歧。下一轮采用更简单的**外层最终 selected 数组**，不强制字符串内嵌两段JSON，不要求完整rule/COMPUTE对象，也不强制教师工作步骤。

这是一项新的可观察接口，必须所有臂共享。它并不等于证明自由文本中的内部选择，更不意味着历史宽容标签已被修复成金标。

## 3.2 完整输出契约
```json
{"evidence":[{"series":"Alpha","category":"Vase","value":72}],
 "work":"Optional concise working in any natural style.",
 "selected":["Vase","Lamp"],
 "answer":42}
```
例子仅示意格式，不是某道题的充分证据或正确答案。正式examples包含与oracle对应的完整案例。

- evidence保留历史真实充分证据语义；不强制固定数量，不把最终selected当作证明所需证据的替代。
- work可选、内容自由，不检查特定语法；不会因多写算式而使S UNKNOWN。
- selected表示全部条件之后最终采用的对象；不是候选池；数组排列无意义；比较时只规范化两端空白和大小写，不进行拼写猜测或语义补全。
- answer沿用精确标量/分数；主任务构造已尽量去掉非终止分数负担。
- 一个JSON对象，不接受代码围栏或对象外文字；重复key直接无效，不选择“最后一个看起来对的字段”。

契约文字只出现一次；绝不拼接相互矛盾的“work必须/可选”。可提示选定字段含义，不提供本题gold、目标名单、答案或定制教师示例。

## 3.3 结构有效与语义正确严格分开
V只检查字段存在、类型、可解析、允许字段和完成。selected允许空数组、错误数量、重复类别或未知类别字符串通过结构类型检查，随后S FAIL。否则“必须选k个正确标签”的结构规则会把部分语义条件偷偷送入J。

数值值域/类别是否存在的具体处理须与历史证据scorer分开：证据fact键非法使证据判定失败/弃权；不能从这推断感知错误类型。保留 `P`, `certificate_truth`, `certificate_sufficient`, `A`, `V`, `finish`, `J_M3` 全部原始分量。

## 3.4 双阶段接口
`parse_response(raw_text)`：只接收原文，不接world/query/gold；输出原对象、selected字符串数组、其**原文字符跨度**和原因。
`verify_selection(extraction, gold_set)`：比较集合、重复项等，返回PASS/FAIL/UNKNOWN。

任何根据gold从多个候选列表中挑一个“最合理”的抽取器禁止用于训练。自然文本中的额外名单不覆盖最终selected。若额外文本明显与selected冲突，记录独立 `adoption_conflict` 诊断，不把它自动解释成内部机制。当前主S专指最终声明集合；任务外显真实性需配对泛化验证。

## 3.5 不强行测当前协议无法可靠测到的东西
S_rule不强制报告，不把它与S_set混合。O/E只在有明确可核验操作数/等式时作诊断，其余UNKNOWN。主方法没有使用这些标签，因此不能写“本轮已完善感知→选择→执行整条链”。

P几乎全部PASS，只能说明已提交事实通常为真；未提交事实、完整读图和关系理解不能由P推断。本轮取消P必须已知的共同门，避免一个饱和/缺失的证据维度阻断可靠S。

## 3.6 字符到采样token，不允许重新编码猜位置
存真实采样token IDs与decode配置、prefill、原全文。逐前缀decode验证稳定增长，恢复每个token覆盖的字符区间。仅完全落在selected数组值区间的token进入局部mask；跨边界、prefill、EOS/特殊控制token、evidence、work和answer不进入。

发生prefix不稳定、全文不一致或没有完整内部token时，`mask_ok=false`，该条辅助信用0；记录S仍可为KNOWN。DENSE、LOCAL、SHUF用同一个mask可用性条件，避免它们实际使用不同样本。

真实tokenizer必须测ASCII标签、转义字符串、Unicode正文、合并边界token、空数组、重复key、截断、无selected、多个JSON、自然work中的假selected字段。CPU字符token测试只证明算法逻辑，不能代替真实tokenizer。

## 3.7 验收不是“与旧判定器一致99%”
旧已知子集上高一致不验证新增覆盖，也不验证金标语义。验收包含：
1. 两个oracle独立一致；反例和边界夹具100%符合预期。
2. parser不接gold，调整gold不能改变抽取结果。
3. 确定字段在标点、空白、work包含等号与候选池时保持抽取不变。
4. 新父模型实际输出分层抽查360条：3父模型×6家族×20唯一回答，按(qid,full_text)去重；审核各字段和字符/token跨度。不把复制的四臂文本算独立样本。
5. 每条审查标注reviewer类型与依据。程序可验证结构，不冒充人审；复杂自由文本未审定就保留UNKNOWN。审核样本不能进入正式测试。

如果360条全部无误，可给出对该抽样口径的误差率上界作为诊断，仍不能保证新策略未来无误。后续第12/36/72步同样抽查新增文体；发现系统性错标则版本化修复并报告受影响范围。
