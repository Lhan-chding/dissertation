# SR-F4 数据实施决定

以执行包 `03_DATA_AND_SPLITS_zh.md` 的具体数量表和固定曝光方案为准。§1 中“C 保持曝光也只能从这里抽”解释为 C 每步 4 道旧任务保持题只能来自旧 `TRAIN_RL`；其余 12 道题按照 §5–§6 来自明确登记的 384 个新 `C_TRAIN` 世界。该句不解释为取消后文的新训练池，不新增实验臂或预算。

新数据共 880 个世界、1,696 道题：B_DEV 128/200、B_CONFIRM 32/56、C_TRAIN 384/768、C_DEV 96/192、C_CONFIRM_ID 120/240、C_CONFIRM_TRANSFER 120/240（世界/题目）。生成阶段只生成题目、图像和程序 gold，不生成或查看确认集模型回答。

`sr_f4.task_contract` 明确支持两个新字段：TOPK 的 `selection_series=Alpha|Beta` 和 INTERVAL 的 `include_end=True|False`。旧查询完全调用旧评分器；新增查询保留旧输出解析、格式、finish 和二元 J 合取规则，仅显式扩展依赖查询含义的正确答案及证据充分性。Beta 排序的充分性要求实际报告全部 Beta 排序事实，不能借隐藏真值补全缺失证据。原 SR-F3 源文件不变。

C_TRAIN 使用旧图表支持的 4/6 类别、[10,90] 整数、两种图型和 main 样式；TOPK 分别 k=2/k=3，INTERVAL 候选区间长度 4，排除两端后仍至少 2 项。六个 cell 的训练聚合为 sum/mean。TRANSFER 的四层固定为：新措辞、novel 样式、6 类别的更长区间或 k=2 组合、以既有 range 聚合与六种选择关系组合的留出模板。最后一层属于原算子范围内的新组合；不声称出现了原任务体系从未支持的运算。清单生成时逐项检查相应属性没有进入 C_TRAIN。

B 诊断对仅排除当前受控目标程序值相等的情况；B 代表性世界不按答案、碰撞或 undefined 筛除。C 的训练/开发/确认对也不筛数值答案碰撞，仅遵循已登记的定义性和集合规模要求。每对保留两个独立 gold 程序、目标集合、字段变化和精确预期关系，不能以“答案不相同”替代关系验证。

固定 C 日程沿用执行包参考实现：每个 repeat 对每 cell 的 64 世界独立排列，32 步各见一次；两个 repeat 选同世界的相反分支；各臂共享日程。B0 固定为每父模型 1,280 回答，B2 DEV 为 200 个 G8 组，C_TRAIN 探针为 48 个 G8 组。所有实际调用和生成种子由生产执行器记录。

实际旧清单已完成一次无渲染构建：保留 1,024 道 OLD_TRAIN 和 2,688 道 OLD_REGRESSION，合并后 5,408 道题。9 个针对性 CPU 测试通过，覆盖原评分不变、Beta 排序、右端点排除、独立 gold、分割数量、受控字段、日程和探针预算。该结果仅表示数据实现和清单已准备，不表示 GPU 实验已完成。
