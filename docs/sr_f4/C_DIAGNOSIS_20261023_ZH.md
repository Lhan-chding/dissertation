# C 阻断根因与推进方案（2026-10-23）

结论：判定器覆盖不足与数据/资格筛选不匹配同时存在。未发现额外奖励公式或差异计数把有效信号算成零的实现错误。当前结果没有检验到 C 的学习效果，不能据此否定选择语义的价值；LZ 是否优于均匀采样与 C 的启用条件无关。

本诊断只使用已生成的 B0、B2_DEV、C_TRAIN_PROBE、历史 RL 重放，以及 C_TRAIN 探针原文。没有用 B_CONFIRM 或终点评测挑规则，没有重标原结果、填写 HUMAN、增加模型调用或启动 C。原报告和归档保留原状态。

## 1. 无法判定主要发生在选择关系解析

实际 C 探针包含 48 题（INTERVAL/TOPK 各 24 题、各 12 个独立 world），三个 block 共 144 个 G8 组、1,152 条回答。

| 维度 | PASS | FAIL | UNKNOWN |
|---|---:|---:|---:|
| P，非空证据读数真实性 | 1,105 | 15 | 32 |
| S，最终采用的对象集合 | 12 | 3 | 1,137 |

S 的 UNKNOWN 占 98.70%。其中 955 条没有被解析器提取出唯一最终集合，154 条进入“冲突或不支持的选择声明”分支；剩余为 23 条不安全/不可解析文档、4 条未完成/技术性生成、1 条没有 work。前两类合计 1,109 条，但不能把它们全部直接改为已知标签：其中既有支持不足，也有真实歧义。

生产提示词只要求可选自然语言 work；实现却主要识别 `selection=...` 等少数句式，或字面的 `operands=[...]`。自然语言选择说明、按月份列算式、带括号解释、初始判断后更正等支持不足。O 也依赖固定 reducer/operands 写法，因此 O 的低覆盖不能解释为模型完全没有运算过程。

CPU 最小复现（同一正确选择集合，非模型新采样）：

| work | 当前 S |
|---|---|
| `final selection=Feb,Mar` | PASS |
| `Feb and Mar are selected.` | UNKNOWN |
| `The selected categories are Feb and Mar, giving (10+14)/2=12.` | UNKNOWN |
| `Initially selected: Jan,Feb,Mar; final selection=Feb,Mar` | UNKNOWN |
| 上一句增加 `correction:` 后再写最终集合 | PASS |

第四例暴露了明确的最终声明处理缺口：先前暂定声明被放入 rejected，继而使明确 final 声明一起弃判。原规范要求处理撤回与最终采用关系，不能仅靠几个更正关键词。但真正矛盾、映射不唯一、无选择证据的回答仍必须保留 UNKNOWN，不能从正确答案反推选择正确。

真实原文也有同类情况：`C_TRAIN_PROBE-b0/s000/g00001/d00` 明确列出 February、March、April，并逐项计算，却因自由句式未被识别；`b0/s000/g00015/d04` 最后明确排除 April、保留 January/February/March，但数值答案错误，S 仍 UNKNOWN。这说明至少有应继续开发解析的真实材料，并非所有回答都没有可观察过程。以上是开发诊断案例，不是独立人工盲核标签。

## 2. 第二个瓶颈先于 S：合格失败层太小

现行 C 只在同组至少两条回答满足 J=0、格式合法、完成、证据充分、任务有定义时比较 P/S；其中任一 P/S 未知，整组额外奖励归零。

| 逐层筛选 | INTERVAL | TOPK | 合计 |
|---|---:|---:|---:|
| 全部回答 | 576 | 576 | 1,152 |
| J=0 | 81 | 204 | 285 |
| 再要求格式合法且完成 | 66 | 177 | 243 |
| 再要求证据充分、任务有定义 | 48 | 4 | 52 |
| 再要求 P 已知 | 48 | 4 | 52 |
| 再要求 S 已知 | 3 | 0 | 3 |
| 含至少两条合格失败回答的组 | 10 | 0 | 10 |

144 组中，134 组因失败层不足两条被排除，剩余 10 组因未知标签弃用。没有一组进入完整的已知标签比较阶段。

TOPK 最明显：177 条格式合法、完成的 J=0 回答中，173 条不满足证据充分性；这 173 条中有 170 条数值答案正确。它们主要是“答案正确，但证据列表不完整”的失败，不应一概叫作选择错误。

真实例 `C_TRAIN_PROBE-b0/s000/g00024/d01`：模型正确选择 Alpha 最大的 April(89)、June(68)、January(59)，正确求其 Beta 总和 49+59+87=195，但 evidence 仅列这三个对象，未列出其他候选的 Alpha，不能按当前模板排除遗漏竞争者，因此 sufficient=0、J=0。另一条同题回答列出全部 Alpha，却把 Beta 只写在 work，仍不能作为 evidence 中的充分证据。

这个充分性判定符合当前实现和事前规则，不能为了过门直接改成通过；但把“完整答案证据充分”作为“选择语义是否能得到信用”的统一前置条件，会排除很多局部过程可观察的回答。这是 C 资格设计与当前模型输出分布的匹配问题。

此外 TOPK 数值正确为 546/576（94.79%），当前探针本身也很少出现答案错误。INTERVAL 的 576 条中已有 495 条 J=1。成功样本不参加失败层额外信用，同组可比较错误因而更少。不能把这一现象归结为整个训练池绝无机会：本诊断覆盖的是固定先导探针。

## 3. 为什么不是修好解析器就能启动 C

即使把所有 P/S 都理想化为已知，保持现有资格条件不变，INTERVAL 最多只有 10 组、5 个 world 可参与比较；TOPK 仍是 0 组。

进一步保持当前已经确定的 P 标签，仅放宽 S 的可判定性：其中两组的合格回答 P 全为 FAIL，所以 P*S 恒为零，任何 S 标签都不能产生 SELECT−EVID 差异。于是潜在上限只剩 INTERVAL **8 组、4 个 world**，TOPK **0 组**。按 block 的组上限为 3、2、3。实际能产生差异的数量可能更少，这只是宽松上限，并非补标后的结果。

原门槛是两题族各至少 24 个非零增量组、各至少 8 个独立 world，每 block 至少 8 组。当前探针在标签未知之前就不具备足够机会，单独修 S 不可能过门。

## 4. 奖励计算检查

冻结公式为 EVID=.5P，SELECT=.5P+.5PS，在合格失败层内居中后乘 β=.25。因此二者最终优势之差为：

`SELECT − EVID = .125 × (P*S − mean_F(P*S))`

合格层不足两条、任一标签未知、或者 P*S 在组内恒定，都会得到零差异。这与生产重放代码一致。本轮的 144 组全部在前两项被阻断，不是观察到了充足、可靠的语义差异后学习却无效。C 训练根本尚未运行，不能称“加奖励训练后没有效果”。

48 个 C 探针题目的主执行器与独立答案实现一致；结合原文检查，目前没有发现会解释此阻断的题目答案生成错误。两实现一致不等于对一切题型的正确性证明。

## 5. 推进 C 的具体修订草案

目标保持为直接比较 J、EVID、SELECT、SELECT_SHUF，研究新增选择信息的学习价值；A/LZ 结果不决定是否推进此目标。

1. **先修测量接口。** 在独立 verifier 版本中开发明确最终集合、明确撤回/更正、类别绑定算式与最终聚合的解析。以原文证据定位为准，保留真实歧义；不从最终数值答案倒推过程。保持当前提示词先修解析，以免同时改变模型输出分布。若仍需结构化过程字段，作为另一项公开协议修订，四臂同样使用，并记录额外 token/格式影响。
2. **先用现有开发回答重放修订候选。** 原始 J 和原结果不动。分别量化解析改善后覆盖、各资格条件造成的损失，以及同组 P*S 是否真的有差异。不要只选出能通过的组。
3. **解决机会不足，需要明确修订研究设计。** 两条路径需区分：保留原充分性条件，则需在不看确认结果的前提下重新登记更合适的训练分布/探针；或研究“答案证据不完整时，可验证的局部选择关系是否仍应获信用”，将答案充分性与过程可判定性分开。后者改变资格条件，须定义新版本、共同资格层与对应人工审核，不能悄悄当作原 C 已满足。诊断目前不足以保证哪条路径能获得足够信号。
4. **冻结修订后再做真正的盲核。** 当前没有独立人工记录，也没有实际正额外信用候选可满足富集审核，不能直接给现有 120 条代表样本填完标签就宣布过门。先产生可审的正信用候选，再按规范抽样；开发中已看过的案例不得冒充新的独立验证。
5. **重新隔离确认用途。** 原 B_CONFIRM 已在 A/B 终点评测中打开，不能用于此次解析器和资格规则调优。修订后的 C 确认评测需另行事前登记未见数据；沿用旧集合时只能明确称既有集合回归分析。
6. **新门控通过后才运行完整 C 四臂。** 维持从原父模型开始，不用 LZ 终点代替，不通过缩减臂、伪造人工审核、降低原门槛来报 RUN_C。

这是一份可审查的推进草案，尚未修改冻结资格规则或申请新增 GPU 实验。当前可直接继续的是独立测量版本的开发与已有开发数据重放；涉及新增数据/采样预算、资格公式或确认集合的研究修订须明确记录后执行。

## 6. 复现与产物

新增只读程序 `src/sr_f4/c_diagnosis.py`，从冻结 `GROUP_REPLAY.jsonl.gz` 汇总分母、逐层筛选、未知原因和机会数量上限，显式拒绝 B_CONFIRM 输入。不产生新标签、不打开门控。

```bash
PYTHONPATH=src python -m sr_f4.c_diagnosis GROUP_REPLAY.jsonl.gz DIAGNOSIS.json
```

本地诊断目录：`artifacts/sr_f4_c_diagnosis_20261023/`。`DIAGNOSIS.json` 为完整计数，`PARSER_REPRODUCTIONS.json` 为上述固定字符串复现，`C_PROBE_COMPACT.jsonl` 和 `C_TASKS.jsonl` 保留原文及题目。私有原始数据不提交 Git。当前报告的数值是既有输出统计，不是修订 parser 后的性能评估。
