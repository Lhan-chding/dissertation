# C_LOCAL 小批 GPU 接续调度修订

2026-10-24 用户授权：四卡排队较久，先用一两卡启动，后续有资源再补；实验预算、评测口径不变，禁止重复提交。

## 调度变化

- 每个新 GPU 租约最多 2 张 PRO6000；共享额度仅余 1 张时，原调度器允许提交 1 张。仍使用老师 QoS `soujanya-poria-startfund-2026-03`、account `rose`、partition `cluster02`、LH 前缀，单次租约 6 小时。
- 共享 QoS 运行、排队和未知预约合计最多 8 卡；本用户所有 QoS 的提交作业合计最多 5 个，CPU 控制器也占一个名额。
- 当其他任务占 4 个名额时，可暂时停止本试验的零 GPU 补交控制器，把唯一可用名额用于 GPU 租约。已有 worker 独立领取同一任务池的训练和就绪评测，不依赖 CPU 控制器常驻。等待资源期间也不同时重建 CPU 控制器挤占第六个名额。
- 暂无常驻控制器期间，由本线程每 5 分钟核对配额。若已有 GPU 租约且至少一个名额空出，再恢复唯一 CPU 控制器；其每 150 秒检查和补交后续一至两卡租约。恢复控制器后监控回到每 30 分钟。
- 若 GPU 租约已结束且有可执行任务，但只空出一个名额，优先按原调度器直接补交 GPU 租约；只有名额足够兼顾 GPU 与控制器时才恢复控制器。禁止对同一未知提交重试。

## 无重复切换

先持有本试验 SUBMIT 锁，记录切换前状态，设置 pool/STOP 让原控制器停止补交；只终止已核验属于本试验的零 GPU 控制器。确认 Slurm 离队、终态及 CONTROLLER 锁释放。四卡作业 223543 仅在仍为 PENDING 时撤销（使用 Slurm 状态筛选）；若已开始运行则保留，禁止为调宽度中断真实训练。确认待排作业离队和终态后，保存取消记录，移走本次 STOP 标记，再调用原池 submit 接口以最多两卡补交。提交前重新统计全账号作业和共享 GPU 预约；超额则等待，不碰其他任务。

所有操作保留原池作业历史及独立 SCHEDULING_AMENDMENT_SMALL_LEASES.json 回执。新的控制器脚本部署到独立目录；运行模块与所有 GPU worker 继续使用原不可变代码快照 `sr_f4_c_local_code_bf31b86`，不热换模块。
