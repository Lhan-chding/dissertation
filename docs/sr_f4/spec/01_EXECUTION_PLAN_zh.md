# 01 实验总体设计与执行顺序

## 1. 研究对象与可证伪假设
当前目标任务是可控图表问答，模型在已有 J 下进行 on-policy RL。重点不是抽象地定义全部“能力”，而是测量图表读数与题意要求的对象选择，并检验新增选择信息能否改善未见数据、表述和关系组合的表现。

H_A：在相同每步回答数与更新次数下，LZ 的成功率分层采样整体配方优于均匀采样；不分离 G、曝光权重与在线更新的单独贡献。
H_B：冻结模型的外显回答中，P/S 可可靠、可追溯地测量，并且部分同 J 失败回答具有超出 P 的选择差异。
H_C：固定题目日程与基础训练机制后，正确对应到回答的 S 能带来超出 J、相同 P 基线及打乱 S 对照的终点改善。
反证包括标签不可靠、S 不改变实际优势、SELECT 不优于 EVID/SHUF、只改善测量器分数但不改善独立答案、收益伴随明显旧任务退化。任一种都必须报告。

## 2. 本包的明确取舍
接受 Claude REV2 的 A/B 分工与修正后的 LZ。保留 B1 四维诊断，但首个训练检验仅使用读数 P 与选择 S，避免一开始给未成熟的 O/E 解析器赋予奖励权力。
新增 C：小型、固定、成套的语义信用比较。它不是下一轮待讨论的模糊建议；其数据、公式、种子、更新次数、对照与启动条件均在本包确定。
不启动 STATIC-LZ、ANCHOR、TGT-native、GOLD/EXEC 扫 γ、多模型比较或综合自适应控制器。若 C 信号不足，本轮停在明确的 BLOCK_C 结论和可用的测量产物，不擅自转成新采样论文。

## 3. 阶段依赖（字母对应轨道，不对应优先级）
S0 输入/代码/生产一致性审查 → S1 数据清单与第一层冻结。
S1 → B0 冻结父模型普查；B1 验证器开发和盲核；B2 受控题组开发普查。
B0 + A 生产门禁 → A：6 路径。
B1 + B2 + C 训练池固定探针 → B3：真实优势重放 → C_GATE。
C_GATE=RUN_C → C：24 路径；C_GATE=BLOCK_C → 不运行 C，交付原因。
A/B/C 所有设计和固定检查点确定后 → E：一次性开放确认集 → 完整报告。
M 工作区分支检查仅为已知病例的可选机制诊断，不阻断 B/C，不据其结果重写输出协议。

## 4. 固定规模
A：3 blocks × 1 新重复 × 2 arms × 64 updates × 128 answers = 49,152 条训练回答，384 次总更新。
C（通过门禁才运行）：3 blocks × 2 新重复 × 4 arms × 32 updates × 128 answers = 98,304 条训练回答，768 次总更新。
合计最大 147,456 条 on-policy 训练回答、1,152 次更新；生成长度、训练 token、墙钟和 GPU 小时另记，不声称算力完全相同。初始探针及终点评测不计入训练回答。
不因同组全对/全错补采额外回答。A 是 LZ，不是 DAPO 的过滤补采实现。技术失败重试次数与成功更新分开记录。

## 5. 父模型、种子与 checkpoint
父模型沿用 `SRF2_J6_s71001/71002/71003`，对应 b0/b1/b2；底模保持 Qwen3.5-9B。父模型可能含已有 LoRA，须复用原更新方式，不重新随机初始化一个新 adapter。
A master seed=2026102201；C repeats 的 master seed=2026102211、2026102212。生成种子从 (master, block, repeat, step, group_index, qid, draw) 派生，不含 arm 以保持配对随机流，但模型分化后不要求文本一致。sampler、rollout、dropout、shuffle、eval、bootstrap 使用隔离流。
C 每个 (block,repeat) 的四臂都从该父模型同一权重和相同优化器初始化策略开始。不从 A 的 RL/LZ 终点开始，不按父模型探针分数挑种子。
A checkpoints：0/16/32/48/64。C：0/8/16/24/32。主结果只用 64 或 32；中间 checkpoint 不参与选模。

## 6. 模型/训练常量
保留 LoRA r=8、lr=1e-5、KL coefficient=.02、TIS cap=2、微批1、结构化 v2。其他 optimizer、target modules、dtype、image resolution、generation length、temperature、top_p、clip、梯度累计、reward std/epsilon 和 loss reduction 必须从原训练配置取值并锁定，不能从端点评测参数倒推训练设置。
A 的均匀臂与 LZ 臂必须通过同一个训练函数；C 四臂只在传入 policy loss 的 advantage 上不同。KL 参考均为各自冻结父模型。
若原 loss 不是序列等权平均，不为贴合文稿而静默改动：本轮 A/C 一律继承原归约，发布完整公式；相应“G32 占四倍权重”的表述改为实际有效权重描述。新归约的算法比较不在本轮。

## 7. 两级冻结，防止测量与假设互相污染
F0：此包的目标、候选、数据生成范围、数量、种子、主要对照、β、人工核验方案和 gate 全部先冻结。
F1：只填实测可解析的 native 参数、路径、数据哈希、验证器版本、人工核验结果和 RUN_C/BLOCK_C；不因开发准确率改变主公式和主阈值。F1 必须在任何 A/C 更新前各自发布；C 的 F1 可以晚于 A，但不得根据 A 的终点效果挑选 C 方法。
验证器严重 bug 的修订限于开发/未看确认集时期，需新版本、全量重跑开发标签和重新验证；不能用旧标签继续 C。
