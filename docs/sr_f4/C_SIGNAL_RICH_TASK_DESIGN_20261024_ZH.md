# C 的题目重设计：让选择与执行产生可观察、可学习的分歧

日期：2026-10-24。状态：**设计稿与开发题例；尚未冻结为实验，尚未测量自然回答信号率。**

本稿回答的问题是：怎样设计题目，才能让 C 更经常遇到“看到了正确事实，但采用了不同选择方法”的回答，并使选择正确的部分有机会在训练中被保留？目标最终仍是新题正确率与保持能力的改善，不是把残差或失败数量做大。

已交付可复算的 [24 道题与完整题解](examples/c_signal_rich_20261024/QUESTION_BOOK_ZH.md)、[机器可读题组](examples/c_signal_rich_20261024/QUESTION_BANK.json)、[CPU 核对记录](examples/c_signal_rich_20261024/CPU_CHECK.json)。它们包含 9 个事实世界、6 个共同构造谱系。全部属于公开的设计开发材料，不能再当未见确认集或测试集。

## 1. 核心判断

**应该把题目做成“选择竞争 × 后续计算”的可控题族，而不是继续把柱高差缩小。**

理想的同题回答组中，应自然出现以下几类回答：

| 回答路径 | 最终答案 | 对 C 的作用 |
|---|---|---|
| 事实、选择、运算均正确，证据与格式合格 | 正确，J=1 | 保留任务成功目标；原生 J 已能学习 |
| 提交事实真实、采用集合正确，后续运算出错 | 错误，J=0 | C 有机会保留正确的选择部分 |
| 提交事实真实，但采用错误集合；沿该集合计算自洽 | 通常错误，J=0 | 与上一类构成有意义的选择比较 |
| 事实或选择声明不足、互相冲突 | 不确定 | 保留 UNKNOWN，定位测量问题 |

第二、三类需要出现在**同一道题的 G8 回答组内**。题库里一批题总是选对、另一批题总是选错，并不能产生组内选择比较。一个图表下的四道关联题也不能拼成一个 GRPO 组：每道题仍各自生成 8 条回答、各自计算优势。

还要避免把“证据漏写导致 J=0”当作主要成功机制。那可能只是在缺证回答中重新分配信用，并没有获得我们想研究的“推理做到一半仍值得学习”的信号。

## 2. 上一轮训练实际暴露了什么

以下来自已完成 F′ 的最终 `ANALYSIS/SUMMARY.json → training_mechanism`，只使用训练机制诊断，不按终点测试哪格效果好来挑新题。

SELECT 共 768 个 G8 训练组、6,144 条回答。768 组来自 128 道训练题、两次暴露、三个父模型块；不是 768 个独立世界。

| 按门控顺序互斥的状态 | 组数 | 占全部组 |
|---|---:|---:|
| 合格 J=0 回答不足 2 条 | 425 | 55.34% |
| 有至少 2 条合格失败，但 P/S 已知的不足 2 条 | 161 | 20.96% |
| 已知失败至少 2 条，但占候选失败不足 75% | 83 | 10.81% |
| 满足 active 条件，但 P=PASS 子集内没有 S 正反混合 | 81 | 10.55% |
| 满足 active 条件，且有真正的同组选择混合 | 18 | 2.34% |

“合格失败”还要求协议有效、完成且问题有定义。因此第一行不能全部解释成题目太容易；后三种技术条件也会影响候选数。

几个直接影响设计的事实：

- 1,651 条候选失败中，仅 743 条 P/S 均已知，覆盖率 45.00%。全体回答 S UNKNOWN 为 3,001/6,144，即 48.84%。两种分母不可混用。
- BOUNDARY 和 SEPARATED 各 384 组，**都只有 9 个选择信号组**。边界题候选失败更多，1,031 对 620；但候选已知覆盖率更低，33.75% 对 63.71%。更难并未转化成更多有效选择信号。
- T8 比 T6 的信号多，14 对 4，但来源随父模型改变：b0/b1 偏 T8-BOUNDARY，b2 偏 T8-SEPARATED。不能据此宣布某个格稳定最优。
- 99 个 active 组中，81 个仍没有选择混合。仅把 parser 补齐，也不能保证有学习机会。
- SELECT 的 45 条正残差失败全部被记录为证据不充分，其中 20 条最终答案错误。这不是“45 条都算错了”。另一个独立计数是 20 条失败获得正的最终总优势，两者不能因为数量相同就视为同一集合。
- 63 个全 J=0 组中，只有 6 个出现选择信号。残差总 L1 / 原生优势总 L1 约 0.127%；这是信用量级描述，不是梯度占比。

因此，新题要同时改善三个环节：**可用的失败、可观察的选择、同题内不同的选择结果**。三个环节需要分别报告，不能用一个“题目更难”概括。

## 3. 题目设计绕不过的信用分配限制

当前 F′ 固定 G=8、β=0.25，先计算二元 J 的组内标准化优势，再给合格失败加入中心化选择残差；不做第二次归一化。

设一个组有 m 条 J=1，且 1≤m≤7。忽略代码中极小的数值稳定项，任何失败回答的原生优势是：

\[
A_J(\text{failure})=-\sqrt{\frac{m}{8-m}}.
\]

最接近零的情况也约为 −0.378。选择分数位于 [0,1]，中心化后乘 β，任何正残差都小于 0.25。因此，**只要组内出现成功回答，正确选择的失败回答仍不可能获得正的总优势**。它的主策略项可以减轻负向权重，但仍持负优势。这里不能进一步断言更新后该回答的净概率如何变化：KL、共享参数、其他回答与裁剪都会影响实际更新。离线脚本对 m=1…7 按现有代码含 epsilon 的结果进行了数值核对。

只有全 J=0 组原生优势为零时，正选择残差才有机会成为正总优势。这意味着：

1. 仅增加“选错”的回答不够；还需要一些“选对了但后续没做对”的自然路径。
2. 不应反过来故意让所有题都失败。那会损失任务成功锚点，可能训练出善于解释错误答案的模型。
3. 新题是否产生更多正总优势，必须实际报告；不能拿 active 数或正残差数代替。
4. 如果健康的题目确实产生了丰富选择分歧，但信用仍太弱，应把“题目设计”和“信用规则”分开研究。修改 β、失败资格或对成功回答也给选择信用，都属于另一项方法变更，不能悄悄混入本次题组升级。

还要明确，现有训练给一整条回答同一个总优势，并没有只奖励“选择正确”的那些 token。给选择正确、计算错误的回答正总优势，也会把同一个策略权重施加到错误计算部分。这是方法本身的权衡：丰富题目可以提供更好的比较机会，却不能单凭优势符号证明模型只学到了正确的局部步骤。后续仍必须检查答案收益、运算退化与旧任务保持。

一个只用于理解机会的近似：令 a 是单条回答成为“合格失败、P=PASS、S=PASS”的概率，b 对应 S=FAIL。假设 G8 内独立，则两类都出现的概率为：

\[
1-(1-a)^8-(1-b)^8+(1-a-b)^8.
\]

它还没有扣除 75% 已知覆盖门槛，也没有处理实际回答相关性。若 a 接近零，单独增加 b 仍无帮助。这解释了为什么“选择竞争”和“后续计算”要独立设计。

## 4. 题库应该控制的六条轴

| 设计轴 | 应控制什么 | 避免的替代品 |
|---|---|---|
| 可读性 | 柱高间距、标签长度、图例、并列是否清楚 | 靠模糊像素制造 P 错误 |
| 选择规则 | 排序列、方向、k、端点、并列顺序、筛选条件 | 只增加文本长度或措辞陷阱 |
| 错误策略竞争 | 错列、错方向、错边界、错数量的集合与正确集合重叠程度 | 所有干扰规则都得到同一集合 |
| 执行负担 | 单列求和、均值、逐项差值、符号、正确分母 | 巨大数字、超长运算、截断 |
| 选择对答案的影响 | 错一项后答案变多少、是否发生抵消或碰撞 | 只保留选择一错答案必错的题 |
| 可观测性 | 完整最终采用集合、命名数值来源、明确最终表达式 | 由 gold 或最终答案反推采用集合 |

生成器先决定语义关系，再生成满足关系的数值。比如先规定正确 top-k 与错列 top-k 重叠 k−1 项或 1 项，再构造两列的排序；不要只独立随机两列，最后碰运气看它们是否形成有用竞争。

这些结构标签是开发侧信息。不能把“这是错列陷阱”“答案对边界非常敏感”等标签送给模型。未证实这些轴完全独立时，要记录实际重叠与数值关系，不能把约束构造直接称为严格正交的全因子实验。

## 5. 六类具体题组

### 5.1 排序列 × 取值列：先解决角色绑定

同一个世界做四道题：Alpha 排序/Alpha 计算、Alpha 排序/Beta 计算、Beta 排序/Alpha 计算、Beta 排序/Beta 计算。

当前 pilot 只有 Alpha→Beta、Beta→Alpha 两个分支，同时改变了排序列和取值列。完整二乘二设计能更清楚地区分“选错列”和“算错列”；交叉列本身不是新能力，新增的是可控竞争与完整对照。

例子，按 January 到 June 排列：

| 列 | Jan | Feb | Mar | Apr | May | Jun |
|---|---:|---:|---:|---:|---:|---:|
| Alpha | 84 | 68 | 55 | 43 | 29 | 16 |
| Beta | 19 | 47 | 68 | 83 | 72 | 54 |

按 Alpha 取前三，求 Beta 均值，正确集合 Jan/Feb/Mar，答案 **134/3**。

- 错按 Beta 排序：Mar/Apr/May，答案 **223/3**。
- 选择正确，但错误聚合 Alpha：答案 **69**。
- 选择正确，但把均值算成和：答案 **134**。

这些路径对应不同缺陷，最终数值也不同。题库应预先平衡同列与交叉列、同向与反向的两列排序关系；不能让“总是选另一列”成为新捷径。

### 5.2 可读的排序边界 × 错选影响

固定 Alpha=`[88,73,60,48,27,12]`，前三与第四之间相差 12。取前三求 Beta 均值，控制 March 与 April 的 Beta 差值为 0、1、20、65。

对均值任务，一换一的错误满足：

\[
y_{\text{wrong}}-y_{\text{correct}}=(v_{\text{in}}-v_{\text{out}})/k.
\]

大影响例 Beta=`[29,46,82,17,69,54]`：正确答案 **157/3**；错把 March 换成 April 后是 **92/3**。选择边界清楚，错选仍有实质后果。

零影响例 Beta=`[29,46,55,55,69,54]`：上述错误集合与正确集合都给出 **130/3**。必须保留这种诊断对照：**答案正确不保证采用集合正确，S 不同也不保证这道题的答案有差别。**

这四例只是受控构造示例，尚非仅改变答案影响的单因素对照。改变 Beta 还会改变重复值与反向匹配歧义、图中数值可读性、误按 Beta 排序得到的集合，以及答案是否为整数。正式对照要配平或逐项记录这些因素；不能把四例结果之差全部归因为答案敏感度。

这条轴用于检验选择是否与任务结果相关，而不是保证模型产生错误。优先使用清楚的间距；窄间距只留作有限诊断，不再作为主要扩充手段。

### 5.3 多元素并列：让确定的规则真正竞争

印刷顺序为 May、June、April、January、February、March。Alpha=`[80,58,58,58,22,11]`，Beta=`[31,47,68,83,72,54]`。

按 Alpha 取前三、求 Beta 均值：

- 按既有“印刷顺序破并列”规则：May/June/April，**146/3**。
- 错用日历顺序：May/January/April，**182/3**。
- 错把并列项全部纳入：四项，**229/4**。

它测的是离散规则，不依赖把两个近似柱高猜成谁高谁低。可平衡并列块位置、需要保留的并列项数量、方向与印刷排列。

限制：r6 检查最终集合，不能证明模型内部真的执行了破并列规则；如果文字说明方向错误但集合恰好正确，现有 S 可能仍 PASS。不能把集合正确包装成完整程序正确。月份顺序只是第一批可表达例子，新类别词汇需要另行检查抽取支持，不能直接扩词后宣布 UNKNOWN 已解决。

### 5.4 有符号差值：为正确选择保留自然的后续失败机会

Alpha=`[87,74,61,49,31,17]`，Beta=`[89,47,82,16,68,54]`。按 Alpha 取前三，求逐项 Alpha−Beta 的均值。

正确集合 Jan/Feb/Mar；逐项差值 `[-2,27,-21]`；答案 **4/3**。

| 错误路径 | 答案 | 选择是否可能正确 |
|---|---:|---|
| 错按 Beta 排序 | −20 | 否 |
| 把差值取绝对值再平均 | 50/3 | 是 |
| 把减法反过来 | −4/3 | 是 |
| 除以全部 6 类，而非选中的 3 类 | 2/3 | 是 |

同图配套单列 Beta 均值、差值求和、差值均值、改按 Beta 排序的差值均值，便于分别观察选集合与做计算的变化。`value=diff` 已受当前 oracle 支持。

这里不应只选“正负几乎抵消”的特殊题。正式生成分布应预先包含全正、正负混合、大小不同的合计、整数与非整数均值；这些是难度与迁移轴。不能观察模型回答后只保留最容易产生残差的符号陷阱。

**这是最值得优先验证的执行轴，但仍只是机制假设。** 人工写出正确集合加错误算式，并不代表模型会自然产生足够多这样的回答。

### 5.5 区间端点 × 条件筛选：扩展到多决策节点

January 到 August：Alpha=`[70,67,58,41,66,28,81,20]`，Beta=`[20,26,22,41,37,50,30,65]`。

题目：从 February 到 July，排除起点、包含终点，只保留 Alpha>Beta 的类别，求差值均值。

- 正确：March/May/July，`(36+29+51)/3=116/3`。
- 错含起点：加入 February，**157/4**。
- 错删终点：剩 March/May，**65/2**。
- 忘记筛选：五项，**94/5**。
- 集合正确却除以筛选前的五项：**116/5**。

这比纯 TOPK 多了端点与条件两个决策节点，当前 INTERVAL oracle 已支持。但它属于新任务覆盖，不能混称为原 TOPK pilot 的原样继续。

必须检查回答可观测性：若同时列出“初始区间”和“最终保留集合”，不能把两个正确的不同阶段集合误判为互相冲突。当前 r6 并不是完整的多阶段集合状态机；自然回答的阶段归属需要专项核对。还要注意，筛选与区间相交通常可以交换次序，不能把等价的处理顺序判为推理错误。

### 5.6 k × 方向：防止固定半数与互补捷径

8 类，Alpha=`[42,86,57,21,74,35,63,12]`，Beta=`[66,24,78,43,51,87,19,60]`。交叉 k∈{2,3} 与 largest/smallest，分别求 Beta 均值：

| 选择 | 正确集合 | 答案 |
|---|---|---:|
| 最大 2 类 | February、May | 75/2 |
| 最大 3 类 | February、May、July | 94/3 |
| 最小 2 类 | August、April | 103/2 |
| 最小 3 类 | August、April、June | 190/3 |

当前 pilot 的 k 总是 n/2。新题不要让正确策略长期退化为“取一半”或“把另一半排除”。本类主要是数量、方向与泛化对照，不预先假定它会带来最多信号。四题仍是四个独立 G8，不合并。

## 6. 真正的组合任务：值得设计，但需要第二层实现

上面的 24 道例题均可由现有两套 oracle 计算。更丰富的程序组合可以进入后续设计，但不能只给旧 query 加字段冒充已支持。

### 6.1 先筛选，再排序，再聚合

用 5.5 的世界：先保留 Alpha>Beta 的类别，再从保留项中按 Beta 选最大的 4 类，求差值均值。

- 正确：May/July/February/March，答案 **157/4**。
- 错误地先在全图取 Beta 最大 4 类，再筛选：只剩 May，答案 **29**。

这里两个顺序确实不等价，提供真正的程序顺序竞争。需要分别记录筛选后集合与排序后集合，分清“筛选错”与“排序域错”。正式数据还应预先覆盖筛选前后候选数、k 的可满足性、空集与不足 k 的定义；不能让很多样本只有一个确定的失败出口。

### 6.2 按派生量排序

用 5.4 的世界，按 Alpha−Beta 最大选 2 类，求 Beta 均值。正确选择 April/February，答案 **63/2**；误按 Alpha 选 January/February，则是 **68**。

它要求把读图、求差、排序、取另一列绑定起来。它也使“计算”成为选择的上游，因而需要重新定义哪个标签负责派生量错误；不能继续把 P/S/O/E 当作自然无重叠的因果分解。

### 6.3 比较两个独立选择结果

用 5.1 的世界，分别计算 Alpha 最大 2 类与最小 2 类的 Beta 均值，再算前者减后者：`33−63=−30`。两组都选对但减法方向错、只选对一组、错误复用一组，都应能区分。

这类任务需要两个有角色的集合，不能用当前一个“无序最终集合”的 S 标签覆盖全部过程。

**实现边界：** 当前 TOPK 不支持 filter 或 `selection_series=diff`，也不支持双集合聚合。尤其旧 `validate_query` 不拒绝所有多余字段，额外写入 filter 可能被静默忽略。新组合任务必须使用严格 schema、新的两套 oracle、证据充分性定义与测量版本。当前交付的离线题例脚本先严格拒绝超出本例 schema 的字段；没有修改冻结 oracle。

不建议现在把上述三类全塞进同一次训练。先用现有语义验证“题目竞争 × 执行轴”的设计是否改善自然组内信号，再单独验证组合语义，能更清楚地知道是哪项改变起了作用。

## 7. 可读性与可观测性必须单独处理

### 7.1 事实表不是当前图像输入

题解中的数字表是开发规格，不是模型已获得的信息。当前 `sr_f3_ce/rendering.py` 的标准图**没有柱顶精确数值标签**。因此，“整数事实表定义清楚”不能推出“模型从图中精确读取没有困难”。

第一层题组沿用现有图形形式时，应优先扩大无并列处的清楚间距，并控制文字拥挤。若增加柱顶数值或使用表格作输入，会显著改变感知负担，应登记为新的输入条件。

可用少量成对开发题比较标准图与数值表：它用于定位信号损失是在读图还是规则执行，不能将表格结果冒充视觉任务提升。所有配对输入、重排、改名和数值变体应共用构造 root，并留在同一 split。

### 7.2 简短、命名、明确采用，比长篇推理更有用

理想的 work 信息顺序是：最终采用的类别 → 排序列或选择条件 → 每个采用类别对应的取值 → 一个最终表达式。需要的是可核对的采用记录，不是长篇理由。

但 `CONTRACT_V2` 的 work 当前是可选项。把它改成必填、要求固定槽位，甚至只加一句“请明确报告最终集合”，都属于提示干预，必须单独标记。新增顶层 selected 字段更会改变原生协议。

建议分开回答两个问题：

1. 原提示下，新题本身能否改善自然信号？
2. 相同新题，在明确采用声明的提示下，UNKNOWN 是否下降，信号是否仍存在？

规范输出也可能把缺证失败改成 J=1，反而缩小失败信用层。这是有价值的发现，应保留，不能为了保持残差而继续鼓励缺证。

### 7.3 r6 的判定边界

- P=PASS 只保证提交的非空 evidence 真实，不保证读取完整，也不保证 work 每个数值都正确。
- S 主要验证最终采用的类别集合，并校验显式声明的排序列；不是完整程序验证器。它仅覆盖 INTERVAL/TOPK 的相应语义。
- 自然算式可使 S 已知，而 O/E 仍 UNKNOWN。最终答案错误不自动等于 E=FAIL。
- 错误规则文字与正确集合可能同时出现。r6 不独立校验所有方向、k、阶段描述，不能把 S=PASS 宣传成每个选择步骤都正确。
- 缺失、冲突、无法支持的表达继续 UNKNOWN；不能用 gold 或答案补出采用集合，也不能用 AI 回填后混进程序判定统计。

构造回答可以用于检查这些边界，不能冒充自然样本或独立的人类审核。新版本若补充规则、阶段或运算标签，必须保留旧 r6 结果并单独报告，不回写已完成实验。

## 8. 怎样扩成题库而不变成“挑会出错的题”

建议使用一个受限的任务语法：

`事实世界 → 选择条件 → 采用集合 → 取值映射 → 聚合 → 最终答案`。

当前兼容层的选择条件仅使用支持的 TOPK/INTERVAL；组合层另设 schema。生成步骤如下：

1. 先指定能力轴与错误规则对照，例如错列、错方向、边界替换、漏筛选、错分母。
2. 用排列与数值约束构造事实世界；记录正确集合与错误规则集合的重叠、边界间距、答案碰撞。错误规则只是审计侧程序，不是伪造的学生回答。
3. 让一个 root 派生少量有解释力的题目对照；保持题面短且自然。不枚举所有轴的笛卡尔积，以免大量重复简单题稀释预算。
4. 数值与模板均按预先固定的分布抽取；如约束无解，记构造失败并按预先规则处理，不能看模型表现后补抽。
5. 两套独立 oracle 核对确定性答案、定义域和充分证据模板。无额外模型调用或全盘哈希扫描。
6. 生成失败、模糊边界、证据不充分、UNKNOWN、答案碰撞均进入统计。不能只保留“parser 能看懂且 SELECT 有残差”的题。

对多样性的要求不仅是题面数量：应报告有信号的**独立 root 数、每父模型覆盖、错误类型分布**，防止几十个信号组都来自同一个世界反复暴露。当前汇总缺少信号组的 qid/world 明细，下一次需要在已有生成中顺手记录这些标识，而不是为补统计额外调用模型。

建议在 S 已知且协议有效的回答中，将“选择正确、答案错误”进一步分成：充分证据与可核对运算失败、充分证据但运算机制未知、证据不充分。协议或技术失败留在完整分母的独立排除类；当前 r6 对无效协议的 S 保持 UNKNOWN，不能把它计为已知的选择正确失败。

## 9. 下一次验证应该怎样回答问题

本稿没有提交 GPU 作业。下面是探针设计建议，不是新的冻结实验或已获收益。

### 9.1 先验证自然信号，再决定是否值得训练

保留旧生成规则的新世界作基线，与新题族在相同父模型、采样设置、G=8 下比较。不要把上轮已训练模型与新父模型不加区分地混合。

一个可预算的小开发版本是：3 个父模型 × 6 个预先定义的层 × 每层 8 个 root × 每 root 2 道对照题 × G8，合计 **2,304 条回答、0 次优化器更新**。六层可为旧分布基线、角色绑定、受控边界/答案影响、多元素并列、选择后差值运算、区间条件；k/方向轴在各 TOPK 层中平衡。24 道公开例题仅供实现验证，不纳入独立信号确认。

这个规模是开发诊断建议，可能不足以支持稀有信号的精确区间。不能把它自动当充分统计功效或训练启动许可；实际层、提示条件、预算和准入阈值需要在观察新输出前冻结。若另加表格或明确 work 条件，应明确替换哪些配额或另列预算，不能暗中翻倍。

### 9.2 固定报告完整漏斗

每个父模型、每层至少报告：

| 指标 | 要回答的问题 |
|---|---|
| J 成功率、答案正确率、有效完成率 | 是否只是增加无意义失败？ |
| 合格失败数、known 覆盖及排除原因 | 信用资格在哪一步丢失？ |
| 同题 G8 的 P=PASS/S 正反混合率 | 是否真有选择比较机会？ |
| 信号 root 数与跨父模型分布 | 是否只集中于少数重复世界？ |
| S 正确/J=0 的充分证据比例及运算状态 | 是否仍靠缺证制造失败？ |
| 全 J=0 且有信号的组数、正总优势失败数 | 当前公式是否给含正确选择的失败回答正总优势？ |
| SELECT−EVID、SELECT−SHUF 的 L1 与实际置换数 | 方法之间是否产生了实质不同的信用？ |
| 选择错但答案相同、表面规则矛盾、UNKNOWN 分型 | 是否把结果正确或解析覆盖误当过程正确？ |

对同一批真实回答可以离线重放 J/EVID/SELECT/SHUF 的信用公式，不需要为这一步额外生成回答。它检验干预差异，不能替代各臂真实训练的因果比较。

不要把新的已知 S 比率作为唯一验收指标，也不要通过强制 SHUF 每组都改变来放大对照；均匀置换本来就可能不改变标签。

### 9.3 用预先约定的失败诊断决定下一步

- 失败增加但 UNKNOWN 也增加：先定位可读性或抽取表达；继续加难不是结论。
- known 上升，但 active 组仍无 S 混合：说明题目没有制造同题策略竞争，应调整构造关系。
- S 混合增加，但正残差仍几乎全是缺证：没有解决目标问题，应加强自然的选择后执行对照。
- 自然选择比较丰富，仍几乎没有正总优势：这是信用规则限制，不能继续单靠难题修补。
- 信号来自少数 root 或一个父模型：只说明局部机会，不能宣称稳定可训练。
- 信号覆盖较广、失败类型健康且干预差异明确：才能考虑新的小规模固定预算训练，比较 J/EVID/SELECT/SHUF，并保留旧任务和 ChartQA。

“较广”“足够”在此是设计目标，尚不是数值验收门槛。应在正式信号确认前把最小实用效应、独立 root 覆盖与允许的退化写成数值，避免看到输出后再定成功标准。单个训练路径的 world 条件置信区间不能替代训练随机种子重复。

## 10. 数据分区与解释边界

至少区分四种用途：设计开发、自然信号确认、训练、最终 ID/迁移测试。一个 root 的重排、改名、换列、改聚合、改渲染全部同分区。仅检查事实表精确相等不足以阻止派生世界泄漏；使用构造谱系编号，不需要重复全盘哈希。

已打开的旧 B_CONFIRM 和本次 F′ 测试仅作历史回归证据，不能用于挑下一轮题目或恢复为未见测试。新确认集观察后若改 parser、模板或筛选条件，应重新标为开发证据；不得保留“独立确认”名称。

确认集用来检验生成器整体的自然信号，不能按其中每道题的表现筛训练题。训练世界要独立生成，方法臂共享已冻结的题目暴露安排。最终测试还应包含未用于开发的规则组合与渲染/措辞变化，分别报告 ID、组合迁移、旧保持，不能混成一个总分掩盖退化。

## 11. 优先级与这次交付的范围

**优先级一：完整角色绑定 + 可读的选择竞争 + 有符号执行轴。** 这些主要使用当前 oracle 能表达的语义，最直接对应失败信用层缺少正确选择失败的问题。

**优先级二：多元素并列与区间条件。** 它们提供离散规则分歧，但需要认真核对阶段表述的可观测性，避免把难度提升变成更多 UNKNOWN。

**优先级三：筛选再排序、派生量排序、双集合比较。** 这些更接近丰富的组合推理，值得作为后续能力方向；需要先完成新语义和测量设计，不能靠旧 query 隐式扩展。

本次交付已完成：

- 详细的机制诊断、题型设计、反例、测量边界与后续验证建议。
- 24 道具体开发题，含 9 个事实世界、6 个构造 root、正确集合与精确答案。
- 11 条错误规则演算，其中包括错误集合但相同答案的对照。
- 24 道题的手工答案、现有主 oracle 与独立 oracle 一致；另行核对全部手工选择集合，避免答案碰撞掩盖错集；当前 G8/β 下混合成功组的失败优势界限核对。
- 独立的离线构建脚本，不修改原训练、判定器、冻结参数或任务池。

尚未完成、也不宣称完成：新题的图片渲染检查、自然回答可判定率、组内信号密度、训练收益或 C 的正式门控认证。这里提供的是更明确、可实现、可证伪的设计，而非用构造题解证明模型已经具备学习机会。
