## 3. 术语与三个必须分开的判断

### 3.1 信号的含义

| 名称 | 含义 | 不等于什么 |
|---|---|---|
| `value_correct` | 最终数值答案按任务规则是否正确 | 不等于完整任务成功 |
| `J` | 原生二元联合成功信号，同时涉及答案、格式/完成情况及证据要求 | J=0 不一定是选错或算错 |
| `certificate_truth` | 提交证据中的事实真实性 | 不等于证据足以验证完整答案 |
| `certificate_sufficient` | 证据是否满足现行充分性模板 | 不等于选择过程是否局部可观察 |
| `P` | 非空 evidence 中读数的真实性标签，PASS/FAIL/UNKNOWN | 空证据不能自动 PASS；非法映射可能 UNKNOWN |
| `S` | 回答最终采用的对象集合/已声明选择关系是否符合 query | 不从最终答案正确倒推 S=PASS |
| `O` | 运算类型、对象和顺序的测量 | 本轮 C 不直接用 O 加奖励 |
| `E` | 外显执行过程/等式的测量 | 等式自洽不代表选对对象或完成任务 |
| `UNKNOWN` | 目前无法可靠判定 | 既不是 FAIL，也不是 PASS |
| `world` | 一张图对应的底层事实表 | 同 world 的不同题目、渲染或多次采样不算独立世界 |
| `block` | b0/b1/b2 三个固定父模型块 | 不是把每条回答视为训练种子重复 |
| `G8` | 同一题在同一策略下采样 8 条回答的优势组 | 不是 8 个独立 world |

### 3.2 必须分别回答

1. **测得出来吗？** 回答是否表达了可观察过程，判定器是否正确读到了它？
2. **有机会产生额外信用吗？** 即使标签正确，同组被允许比较的回答中是否存在有用差异？
3. **学了以后有用吗？** 真正运行 C 后，新增信用能否提升未参与设计的终点，并胜过恰当对照？

目前主要卡在前两项，第三项尚未进行。程序测试通过也不等于这三项都通过。

## 4. 原 C 的真实公式：请基于这个分析，而不是只分析 J+λS

### 4.1 共同资格层 F

每题一组 8 条回答。合格失败层定义为：

```text
F = {i :
    J_i == 0
    and protocol_valid_i
    and finished_i
    and certificate_sufficient_i is True
    and task_defined_i is True
}
```

规则：

- `|F| < 2`：该组所有额外项为 0。
- F 中任意一条的 P 或 S 为 UNKNOWN：该组所有额外项为 0。
- 四臂使用完全相同的资格计算，不能 EVID 使用更多回答、SELECT 使用更少回答。
- 原生 J 的优势仍照常存在，额外项为零不是删除原生学习信号。

### 4.2 四个臂

令已知标签 PASS=1、FAIL=0：

```text
J:            不增加额外信用
EVID:         s_i = 0.5 * P_i
SELECT:       s_i = 0.5 * P_i + 0.5 * P_i * S_i
SELECT_SHUF:  在 F 内、相同 P 的层中打乱 S，再计算 SELECT 的 s_i

d_i = s_i - mean_F(s)   if i in F
d_i = 0                otherwise

A_i* = A_i^J + 0.25 * d_i
```

**加完后不再标准化、白化或重新居中。** 原生优势由生产代码计算，保留原来的 loss、KL/TIS 等实现。

因此，只要资格和标签条件满足：

```text
SELECT − EVID = 0.125 * (P_i*S_i − mean_F(P*S))
```

几个直接推论：

- 不需要整个 G8 都是 J=0；混合成功组中的失败子集也可能有新增信用。
- 同组 F 内 P*S 恒定时，新增差异仍为零。
- F 内 P 全为 FAIL 时，无论 S 怎样变化，SELECT−EVID 都为零。
- F 内 P 全 PASS 时，EVID 的这部分居中残差为零；SELECT 是否不同取决于 S 是否变化。
- `J=0 且 S=PASS` **不等于** 实际获得正额外残差；仍要考虑资格、P、全组已知及组内均值。
- 参考材料里的 scalar 候选 `J+λS` / `J+λPS(1−J)` 可另行分析，但不能用其结果替代上述正式 C 的重放。

### 4.3 原训练与门槛

原 C 登记为：3 个父模型 × 2 个重复 × 4 臂，共 24 条路径；每条 32 次更新，每次 16 题×G8=128 条回答，共 98,304 条训练回答。

每步固定 12 道 C 新题和 4 道旧 TRAIN_RL 保持题；同一重复四臂共享题目曝光，但各臂生成自己的 on-policy 回答。各臂从原父模型开始，不使用 LZ 训练终点。

**原 C 使用固定曝光和 G8，并不是自动把 LZ 的动态采样器套在四臂上。** 如果新版要让所有 C 臂使用 LZ，这是可以讨论的新设计，但它会改变题目曝光/G，必须说明怎样公平比较、怎样解释机制。

原信号门槛：实际 C 训练探针中，SELECT 相对 EVID 的最终优势增量绝对值超过 `1e-8` 的组，INTERVAL 和 TOPK 各至少 24 组、各覆盖至少 8 个独立 world；每 block 至少 8 组。此外还有测量可靠性要求。它们是事前操作性门槛，不是科学定律，可以讨论新协议，但不能追改旧结果。

## 8. 代表性案例：请设计能处理它们的定义，而非只提高覆盖数字

### 案例 A：明确选择，但句式不被 v1 支持

```text
Feb and Mar are selected.
```

v1 为 UNKNOWN；若类别明确且没有后续冲突，v2 可按集合与目标比较。目标集合不同也必须能 FAIL，不能仅支持正确集合。

### 案例 B：全部算过，最终只采用一部分

```text
Jan: 10-1=9;
Feb: 13-3=10;
Mar: 19-5=14;
Mean=(10+14)/2=12
```

若映射完整、唯一，最终采用的是 Feb、Mar，不能把 Jan 也纳入；2 是分母，12 是结果，都不是被选择数据。

### 案例 C：相同数对对应多个类别

三个类别的 Alpha/Beta 均是 10/1，work 只有：

```text
10-1=999; Count=3
```

不能据此声称识别了三个不同类别的最终选择。需要对象身份和最终使用证据；等式本身也错了。

### 案例 D：结果值恰好也是图中的数据

Beta 值为 `[2,3,5]`，work：

```text
Sum=2+3=5
```

不能因三种数值都出现在文本中，就认定三个对象均被选择；不能因为题目 k=3，就挑出这种解释。

### 案例 E：真实 TOPK 回答正确，但不满足完整证据模板

实际 C 探针 `b0/g00024/d01`：

| 类别 | January | February | March | April | May | June |
|---|---:|---:|---:|---:|---:|---:|
| Alpha | 59 | 17 | 42 | 89 | 25 | 68 |
| Beta | 87 | 38 | 47 | 49 | 38 | 59 |

任务：选 Alpha 最大的三个类别，对其 Beta 求和。

```text
The three categories with the largest Alpha values are:
April (89), June (68), and January (59).
Summing their Beta values: 49 + 59 + 87 = 195.
```

evidence 只列这三个类别的 Alpha/Beta。数值答案正确，但没有给出其他类别的 Alpha，现行模板不能据此排除遗漏竞争者，于是 sufficient=0、J=0，也被排除在额外信用层之外。

这个案例问的是：**完整答案的证据充分性，是否应成为所有局部选择信用的必要条件？** 改掉它可能提供更多机会，也可能奖励不完整或有投机性的过程；需要定义和对照，而不是直接删除条件。

### 案例 F：最终集合似乎对，答案仍错

实际 `b0/g00015/d04` 的 work 最后明确说包括 January、February、March，不包括 April；答案却为 24，属于数值错误。v1 未识别这种叙述。

它说明值得研究“选对但答错”的样本，不代表这种样本在同组里足够多，更不代表新方法已经有学习收益。

### 案例 G：真实性与非法映射的边界
