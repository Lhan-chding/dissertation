## 筛查判定

固定六家族各索引0/1的两个旧DEV_CAL根，两个因子、四视图、两draw、三个父，共576行。
每父×因子96行，V、S-known、B-known分别须至少87行；六格共18项全部满足。
只有全部576行、原始轨迹和身份完整且无未解决技术错误时才评价这个门。
科学未知与技术失败分别保留；S/B可读但错误仍计入known，不计为正确。
原始EOS不改成balanced；主A、J及辅助语法/信用口径不变。

只有一个提示候选。失败即停止新版本扩展，保留全部行；不改模板、seed、长度或阈值重试。
通过仅为 `SCREEN_PASS`，不是总体90%可判的置信证明，也不构成G8信用门或训练准入。
576是登记回答行数，不是576个独立实验单位；共同seed和重复anchor的相关性明确保留。

## 如何判断题组是否有用

1. 有限候选数学覆盖、绝对区分、碰撞揭露和语义边界是设计检查，不能等同真实模型错误覆盖。
2. 筛查报告完整A/J/V/S/B、UNKNOWN、结束原因及家族/强造碰撞分层。
   固定12根中6根为强造碰撞，占50%；不能推广到原DEV_CAL的37.5%或TRAIN的1/3。
   两draw不填充成G8、不计算原COND/SHUF支持门，也不新增“P1必须更好”的门。
3. 通过后，独立完整确认集才测原G8信用机会、有限库对实际错误的预测、库外/不可判比例，
   保留oracle-only对照、全部父模型和不利层。四视图配对不代表模型共享隐藏推理过程。
4. 最终数据训练价值由固定六臂训练后、未见COMPOSITION上的D0及不确定性回答；
   F0/F1、交互、强对照与保持性同时报告。无训练不能把“尚未证明”写成“无效”或“有效”。
