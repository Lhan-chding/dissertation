# SR-F6 实施前纠错与边界

2026-10-27。所有决定在首次 SR-F6 模型输出之前登记。原包完整保留于 `package/`，SHA-256 为 `738fb9f69f330936e579933522cae1262e119560bacaac8aa47514b0a8776ffc`。用户要求理解设计并纠正可能的错误；本文件区分原方案、实施纠错和真实执行证据。

## 不变的研究合同

保留六臂、三个固定 J6 父、每父三个训练重复、72 更新、128 回答/更新、G8、λ=.5、S/B 等权、共同 FP32/1536 token、最终答案主指标及四项双侧主比较。原 F5 FAIL 保持。CPU 通过不能使 GPU 阶段自动通过。

## 实施修正

1. **原生 J 无损投影。** 原参考 `json.dumps(default=str)` 会将 Decimal 字面量转成引号字符串，真实 F5 评分可由 1 变 0。生产投影只删除原文中的 bindings/aggregate 字段，保留旧字段原始字节，并回归至少 300 个六家族夹具及字段变异。
2. **主测试独立构造。** 原参考在 COMPOSITION 中同时拒绝 P0/P1 的别名，导致最终使用的普通 P0 测试受未用优化 P1 选择影响。修正为只构造、审核实际四个普通视图，保留登记种子和候选库无别名要求。原 192 roots 中 7 个受此缺陷影响。纠错不是按模型输出改题；新旧数学产物和摘要均留存。
3. **可判性与信用资格分开。** 一个新增字段格式错误不应抹去其他可读字段的诊断标签。字段分别盲抽取；V 不合格或未完成仍禁止全部辅助信用，不能借 UNKNOWN 改变资格。
4. **训练实现不能直接复制旧上限。** F6 的合法 G8 辅助系数可达 .4375，旧 F5 的 .25 限制和 selected 局部 mask 均不适用。F6 采用独立整序列目标，KL 一次；原生 λ=0 的损失与梯度须回归。
5. **随机顺序独立。** 原参考训练顺序只有 repeat 随机流，三个父共享顺序；主方差公式却不含父间协方差。加入 parent 到顺序派生流，保留每个父×重复内六臂共同顺序和原 draw seed。先导使用 DEV_PILOT root ID。六臂执行顺序在父×重复块内预随机并冻结。
6. **诊断步歧义。** 04 写 1/12/36/72，06 写 1/4/8/12/36/72。采用全集 1/4/8/12/36/72；这是同批、更新前的测量，不新增训练曝光或更新。
7. **保持性声明补全。** LEGACY/ChartQA 的确认性比较为 U11 对对应父模型，阈值分别 −1pp/−2pp，两个单侧检验 Holm；同时给 97.5% 单侧 Bonferroni 下界。全部其他臂对父的差值仍完整报告为描述性结果，不能据未校正结果宣称所有臂共同保持。零方差为 NA，不自动宣布非劣。
8. **门必须绑定实际证据。** 原参考启动器只是文件一致性示例，不能充当生产准入。生产门额外核验阶段、来源、完整配置/代码/数据身份、实际命令和返回码、每项所需证据及完整普查分母；仍不把 hash 当成证据真值的独立证明。
9. **图像尺寸。** 旧 renderer 是 1024×768，不能当成 F6 要求的 1280×896。F6 使用独立固定尺寸 renderer，原图几何检查与真实 processor 后视觉审查分别记账。

用户随后要求避免冗余哈希：全量内容核验只在来源绑定、数据冻结、归档验收等必要边界执行。阶段检查复用已验证内容清单与本地核验缓存；文件元数据变化才重新计算对应内容哈希。元数据只决定缓存是否失效，不能替代科学内容身份。禁止每个回答/每次状态检查重复读取整套模型权重或数据。

机器可读登记在 `sr_f6.contract.AMENDMENTS`。配置仍保留原包科学数字，不修改原包文件。
