# 06｜生产训练、数值一致与事务恢复

## 6.1 固定运行条件
Qwen3.5-9B，3个原J6父 adapter，基模/浮点图像输入/current/ref/generation全部FP32；冻结父模型作为每条路径KL参考。继承父LoRA结构；新AdamW：lr=1e−5，betas=(0.9,0.999)，eps=1e−8，weight_decay=0，constant schedule，global clip norm=1。adapter-only训练，dropout=0；不得暗加教师CE、grammar decoding、重采样过滤或长短回答筛选。

每题temperature=1、top_p=1、top_k=0、max_new_tokens=1536。1536是共享的新输出上限，所有臂及本轮父评测一致；与F5不同，不能把跨轮差值当本方法效应。超过上限的回答保留分母，finish状态影响J，不补采“完整答案”。

4 roots×4 variants×8 draws=128序列/更新，16个独立题内G8。variant不混成32样本的GRPO组；每题单独原生居中。每条路径72更新，288训练roots各一次。训练根顺序按重复种子生成，每12步覆盖每家族8roots；同一父/重复的全部六臂共享根顺序和采样种子。

同seed是方差控制，不保证更新后原文相同，也不能把相同计数当参数相同。P0/P1不同图像可能使采样分叉；单题draw seed由父、重复、步、槽、variant、draw派生，不含arm。

## 6.2 一次更新严格顺序
1. 锁定当前checkpoint和RNG；完整收集本步128条，保存实际prompt/image摘要、原始token IDs、采样logprobs和finish；即使J=0也保留。
2. 用冻结parser/scorer计算A/J/V/P/S/B/E与oracle见证。按qid×父×policy hash验证每组正好8条。
3. 计算原生A^J与本臂c，记录COND/GLOBAL/SHUF反事实统计但仅本臂c进入梯度。置换只一次，种子由路径/步/组派生。
4. 使用真实采样token，生成时的同一chat template、图像预处理和特殊token。padding/prompt不进loss；EOS属于实际完成token。不得通过重新encode整个字符串替代token轨迹。
5. microbatch=1，128个序列loss各除128后累积；每个序列内按实际完成token长度平均。不得按有效信用条数重算分母。KL只一次，辅助λ只一次。
6. 在任何optimizer更新前完成概率一致、有限性、梯度诊断；全局梯度裁剪一次，optimizer.step一次。禁止在一个128批次中偷偷更新多次。
7. 原子保存新adapter、optimizer、scheduler、全部RNG、采样计数器、已消耗qid表、信用和更新摘要；提交COMMIT.json后步号才递增。

公式见04与`objective.py`。本包单次更新继承F5：ratio以当前参数detach为旧值，前向为1，TIS修正采样/训练差异。它不是多epoch PPO，不声称clip提供多epoch信赖域。

## 6.3 数值检查与诊断
每步记录sampler/train的mean/max/分位数和超过0.01、1、5 nat的token计数；mean>0.01、max>5 nat、TIS触顶比例>1%均为阻断警报，任何非有限值立即阻断。还要逐步保存reference−current分位数和KL总量，不能用sampler/train差来解释reference/current的极值。

不静默截断log-ratio、不mask异常token继续跑、不把失败步换成新的回答。出错先存原始token、概率、精度、batch形状、缓存状态、kernel环境；使用同一只读诊断复现。科学配方已冻结后若必须修改数值目标，原路径结束并标FAIL，不恢复成“同一正式实验”。

登记诊断步1、4、8、12、36、72：在同一批次固定8个qid/共64序列上，用同一前向与同一参数顺序分别计算native、aux、KL向量范数、内积/cosine、合成梯度与实际更新范数。诊断不optimizer.step、不改变RNG；所有臂都做。辅助范数很小不直接推出效果小；不得把不同步最大范数相除叫剂量。

单独记录：c的L1/L2、非零比例、J分层零和、TIS后实际梯度、裁剪前后范数。零和是系数性质，不保证各任务完全无干扰。

## 6.4 事务与故障恢复
run_id包含experiment/parent/repeat/arm；同run只能一个worker持独占锁。缺COMMIT的部分步：恢复**上一已提交**checkpoint，优先重用与其hash/RNG严格匹配的已完成rollout，不能跳过/重复optimizer。

step0/12/36/72保留永久checkpoint，其余事务checkpoint可保留两代，但原文/信用/更新不可删。恢复验证按adapter、optimizer tensor、scheduler、CPU/CUDA/python/numpy RNG、token、logprobs、credit、step计数与日志内容逐项比较。

内容身份用SHA256/规范化tensor摘要；共享文件系统st_dev、inode不是科学身份。跨节点路径相同或inode相同均不足以证明内容相同。b0/U11恢复验证只支持所验证路径，不冒称所有路径跨硬件bitwise一致。

集群TimeLimit是作业调度约束，不是科学训练预算。壁钟中断只续跑剩余登记步；不得增加更新数。默认单GPU worker并行数1，提交前读取实际队列和权限，不取消无关作业。配置中的account/partition/qos仅是已有环境值，必须核对真实可用性，不能通过改模型/精度绕过资源限制。

## 6.5 正式顺序与测试锁
用预登记随机顺序在每个父×重复块中执行六臂，平衡执行时间；不能始终先跑主候选、效果好才跑控制。每条正式路径从父模型而非先导端点开始。

36步仅跑独立DEV_EVAL一次固定96题，用于透明轨迹记录，不用于早停/调参/选择checkpoint。所有54条72步端点提交前，服务器不允许任何模型访问正式TEST图像/问题；完成后一次解封统一评测。数学oracle审查测试数据不等于模型测试揭盲，但人工发现题目错误必须在模型访问前更正并更改数据hash。
