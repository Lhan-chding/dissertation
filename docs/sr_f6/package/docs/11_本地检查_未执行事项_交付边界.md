# 11｜本地执行与尚未执行

以`qa/VALIDATION_STATUS.json`和各实际日志为准，以下不将程序参考当成服务器运行。

本机执行的类型：读取最新Claude原文与脚本；重跑f14数学检查；新的精确数值/双oracle/语义测量/信用/配对/统计/门控单元测试；构造登记的参考题库并检查有限候选覆盖与跨split泄露；绘制开发示例；重新计算预算；确认NOT_RUN门无法启动。

首次单测有一个fixture超出精确数字分母边界而失败，原日志保留。改的是测试数字，不放宽答案契约，不将初次失败删掉。最终测试数量、PASS数和命令见最终日志，而不是复制以往F5的51/332条计数。

数学反例只验证逻辑，不给模型实验效应。P0/P1覆盖是定义库内的确定性差异，不能当成未见任务准确率提升。CPU图像只验证渲染输出，真实processor后的可读性仍需服务器检查。

## 明确NOT_RUN
真实Qwen加载；实际GPU generation/current/reference数值路径；原生服务器J完整投影回归；真实回答360条盲审核；真实图像processor核验；父模型普查；12步先导；恢复bitwise验证；54路正式训练；任何正式模型评测/显著性/保持结论。

外部LEGACY/ChartQA实际题ID与文件权限需要服务器绑定，当前模板不含伪造ID。生产run root、账号/队列和训练环境虽然沿既有来源填写，但本机没有远程确认，也没有提交任务。

## 为什么仍可交给Codex
研究决定、数据/标签数学对象、控制、预算、门、统计、风险、实际CPU参考都已给出。剩下的是按严格接口绑定已有生产框架，并产生真实证据；不是让Codex自由重新选择科学方案。缺文件或权限时返回可定位缺口，不能用mock回答跨过门。
