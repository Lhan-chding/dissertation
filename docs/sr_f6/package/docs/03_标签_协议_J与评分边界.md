# 03｜标签、协议、J 与评分：逐项堵住混淆

## 3.1 共同输出协议
六臂完全相同，字段：`evidence, selected, bindings, aggregate, answer`，另可带自由文字 `work`。不使用字符串内嵌转义的SELECT/COMPUTE，不把候选池误称最终集合，不按金标从散文中挑一段“最像正确”的列表。

```json
{"evidence":[{"series":"Alpha","category":"Mug","value":12}],
 "selected":["Mug","Lamp"],
 "bindings":[{"category":"Mug","operand":18},{"category":"Lamp","operand":30}],
 "aggregate":"sum","answer":48,"work":"Optional concise working."}
```

上例仅示意结构，单条evidence不被宣称充分。模型可自由安排work，不做教师CE，不新增SFT，不使用语法约束解码。最大输出长度统一1536（相对F5是公开的新共同协议设置）；主比较内部全部相同，不把历史不同协议准确率直接横比。

## 3.2 三类正确性分开
- A：最终答案精确正确。只要求能从一份合法、无歧义的最终JSON提取answer，不要求额外selected/bindings正确或存在。非法/截断且无法提取答案为0；不重采。
- V：共同格式与字段类型有效。不能把“集合必须等于金标”“bindings必须覆盖金标”混入V。
- J：继承F5实际M3联合奖励的答案、证据真实性与充分性、协议和完成条件，再与本轮共同V相交。投影删除本轮bindings/aggregate等新增字段，保留原evidence/answer/selected/work。必须通过原生评分器回归，不以CPU简化评分器替代。

**J不检查S、B或执行语义是否正确。**将一个格式合法的selected或bindings改成错误值，但保持答案和原证据不变，J必须不变。字段缺失或非法类型导致共同V失败，是共同接口要求，不是“选择奖励”。

A、J、V、finish分别存储。J=0不能称为答案错误。A评分不能被新增声明格式的失败拖成0，否则“语义奖励改善答案”会混入协议改善。

## 3.3 两个实际训练事件
|事件|输入及真值|PASS|FAIL|UNKNOWN|
|---|---|---|---|---|
|S 最终对象|selected与查询oracle的最终集合|无重复、集合完全相等；顺序不限|空、重复、额外、遗漏、错对象，且声明可读|声明缺失/不可读或生成无法完整核验|
|B 任务相关取值绑定|bindings与**金标最终集合对应的任务操作数映射**|对象键完整且无额外、无重复，每个operand等于真实世界按题目取出的值|错范围、错列、错差值、错数值、遗漏或重复|范围可核验但operand明确缺失/不可解释，或整体不可读|

B的任务操作数可以是Alpha、Beta或有符号Alpha−Beta。不奖励“任选一个容易对象然后读对”，不允许空列表真值为真。B核验的是任务所需数值映射，不仅是任意已提交事实的真实性。

S与B可以不一致，例如selected写错、但bindings恰好列对真正对象。两者分别反映可观察子目标，不强行把它们等同模型内部步骤；另记 `consistency=1[两份声明的对象键相同]`，不将它单独奖励。

本轮权重固定S:B=1:1。若二者在某组高度相关或分量互相抵消，按实际记录报告，不自动重新加权。正确反馈可能仍有捷径风险，最终由独立答案与泛化评测约束解释。

## 3.4 不进入主信用的诊断
- P：提交证据的真实性；不是完整感知成功率。
- E_raw：模型声明的bindings按其aggregate计算是否等于answer。可在全部数值错误时成立，不能单独当正确进展。
- E_anchored：B通过、aggregate等于题意、答案等于真实所需操作数的聚合。此时代数上等于 B∧正确运算∧A，明显与A重叠，不能当独立新奖励。
- 受控跨题关系：答案变化是否匹配真值关系；必须与绝对正确、整组全对共同报告。模型两题都加90也可能关系一致。
- 声明与使用证据的一致：是外显一致性，不是内部因果忠实性。

## 3.5 UNKNOWN与数值
UNKNOWN记None，不回填0或1。空但完整可读的集合是明确错误，不是UNKNOWN。本轮共同协议禁止bindings中的null或非数值operand；这类回答V=0、J=0，测量记UNKNOWN而不冒称语义FAIL，不能靠输出null逃避负信用。只有可完整核验的生成进入信用；真实缺失率单独报告。

使用Fraction/Decimal，拒绝布尔值、NaN、Inf、重复JSON键与超界数值。主数据本身保证整数/有限小数，但仍接受引号分数的等价精确表示；不通过改变容差制造提升。压力面板可另报预登记近似分，不替代主分。

## 3.6 标签验证不是只看“程序审核PASS”
必须同时有：双oracle、结构变异夹具、gold-blind抽取测试、原生J投影回归、真实回答分层复核。不能只在旧解析器已知的行上检验新覆盖区域。

真实复核抽样：每个父模型×P因子选60个唯一(qid,完整文本)，每家族10个，合计360；优先覆盖A/J/S/B所有实际出现的组合以及UNKNOWN/无效，再随机补足。按root去重上限每root最多4条；不是按row_id取前24条。稀有J1/S0、J1/B0、S1/B0、S0/B1全量列出，超过上限按预登记hash抽样另记总数。

每个审核者独立判断后才看程序标签；回执区分人工、视觉代理、程序。所有存在歧义的条目保存，不事后改成有利标签。360只是覆盖样本，不代表全量分布；按完整数据另报率。
