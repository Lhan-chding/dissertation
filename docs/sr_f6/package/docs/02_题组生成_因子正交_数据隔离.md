# 02｜题组如何构造：不靠猜模型会错什么

## 2.1 实验单位与可见信息
world 是图表真实数据；root 是一个世界与查询及其派生编辑的共同谱系；每个数据因子有 anchor＋3 个编辑视图。P0/P1 anchor 完全相同，编辑视图可以部分重合，禁止为了差异而强制 P0 避开好题。

模型单次只看当前图像、当前题目和共同格式约定。不能看到 world JSON、gold、候选错误规则、coverage、P0/P1 名称、collision 标记、相邻题答案或生成元数据。输入只使用模型可见字段白名单；更改 sidecar 中 gold/factor/root_id 必须不改变 prompt。

## 2.2 世界与任务语法
沿用已验证的六家族、TOPK / INTERVAL 查询、sum / mean、Alpha / Beta / Alpha−Beta。6或8个无自然顺序商品名；印刷顺序随机。数值12,18,…,84；坐标轴0–100，无逐柱数值标签；主答案必须整数或有限小数。主实验不新加难以辨认的图像或数字，不依靠更短输出预算造错误。

|家族|本轮 anchor 的任务结构|错误候选及测量职责|
|---|---|---|
|BINDING|排序列与取值列交叉|错列、错取值角色、选择/绑定不一致|
|IMPACT|固定选择规则后聚合相关取值|选错但数值相同、相关/无关编辑响应|
|TIES|明确印刷顺序破同值|反向破同值、边界成员替换|
|SIGNED|对所选对象算有符号差再聚合|符号、角色、聚合类型|
|INTERVAL|按图上位置定端点，再作正差筛选|端点、漏筛、区间与最终集合混淆|
|K_DIRECTION|不同k与最大/最小方向|方向、k、边界替换|

这只是首个可核验实例；不能声称语义行为等于选择集合。B 进一步核验所需数值及其对象绑定；P与E另行记录。

## 2.3 预先定义的有限错误库
不读取父模型输出来定义错误库。当前参考库：boundary_swap、wrong_value、wrong_aggregate；TOPK 另有 wrong_rank、wrong_direction、k_minus、k_plus、reverse_tie；INTERVAL 另有 toggle_start、toggle_end、toggle_filter；diff任务另有 reverse_difference。

`boundary_swap` 明确定义为：保留正确集合的其余成员，把印刷顺序中的最后一个选中对象换成首个非成员；INTERVAL 优先取区间外非成员。它是一个受控的候选错误行为，不被称为模型实际采取的错误程序。其他候选由任务算子做单点变异。

一个候选在当前编辑池没有任何可区分响应时，记录为 pool blind，不从报告里悄悄删掉。覆盖率分母另外报告“全部登记候选”和“当前池内活跃候选”，避免只显示有利分母。

## 2.4 区分证书：有绝对锚点，也有响应信息
对正确函数 f*、候选 h、编辑 e，保存：

D(e,h)=1[(f_h(e(x))−f*(e(x))) ≠ (f_h(x)−f*(x))]。

这是候选错误相对正确函数的**响应差异**，不是简单“一道编辑题是否答错”。基题的绝对差也保存。对原本碰巧答对的候选，D=1意味着该编辑可揭露它；对基题已经答错的候选，D刻画其对变化的响应区别。

证书只对列出的候选、实际合法编辑池和精确算术成立。不声称恢复模型隐藏程序、不声称排除全部错误、不声称coverage高必然学得好。常数偏差可能位于响应零空间，必须靠绝对正确性排除。

## 2.5 P0/P1 的匹配机制（参考实现已提供）
每个 root 枚举：对 Alpha 或 Beta 的一个单元格做 ±6 编辑。逐项检查取值边界、金标非空、有限小数、保留组合规则、双oracle一致。不能因为模型答错率或信用稀疏而接受/拒绝某题。

把候选编辑按以下描述分桶：编辑列、正负号、绝对幅度、金标集合大小是否改变、金标答案变化量。预登记 seed 随机选择3个不同桶：

- P0：每桶均匀选一个编辑，不查看覆盖率。
- P1：在相同3桶内，枚举三项组合，最大化响应差异覆盖的并集；并列由同一预随机顺序决定。

这样每个配对视图都匹配操作成本和上述真实任务属性。P1 不增加题数、生成次数、oracle调用权限或候选池。P0不是专门挑选“无用题”。

**不能声称难度绝对相同。**哪一单元格被改、候选错误与真实任务的关联，是本来要操纵的因素；它也可能影响模型难度。父模型难度、长度等只描述，不在正式结果后重新匹配，也不据此删除实验效应。CPU覆盖差验证的是操纵存在，不是学习有效。D0识别的是这个覆盖优化生成策略的整体效应，不是把coverage数值与所有难度因素完全分离后的纯因果效应；金标成员是否发生替换等未精确匹配属性必须另行汇报。

## 2.6 碰撞比例与范围
训练每家族48 roots中，每第三个anchor（16个）构造对 boundary_swap 的数值碰撞，共96/288=1/3。修改非成员的取值，使该候选与正确函数在anchor上同答案，同时保留正确选择；独立oracle及编辑见证必须验证。

这是**设计的候选碰撞比例**，不是模型自然侥幸率；未强造的anchor也可能偶然与其他候选同答案。实际候选碰撞和实际模型的 A/J/S/B 事件分别记录。首轮不要求父模型出现20%–40%错误，不为满足错误率筛题。

构造碰撞需要合法边界与不改变真实选择；最多256次按登记数学约束重建。禁止看模型后选更容易制造显著效果的候选。此次构造聚焦边界替换，其他错误类仍进入覆盖和测试；不把该受控子层外推为自然数据发生率。

## 2.7 划分与独立组合
同一root所有P0/P1编辑和渲染都在同split。跨split还检查忽略名称、忽略顺序后的两列事实多重集，防止重命名泄漏。所有旧F4/F5公开测试病例只作开发知识。

训练中全局排除以下六种连接，而非只在某个家族排除：
1. Beta排名＋Alpha取值＋mean；
2. Alpha排名＋diff取值＋smallest＋mean；
3. 排名边界同值＋smallest；
4. diff取值＋k4＋mean；
5. INTERVAL＋positive_only＋mean；
6. k4＋smallest＋mean。

COMPOSITION每家族32 roots；每个root四个视图都满足对应保留组合。使用独立种子、普通合法随机编辑生成确认测试，不用P1最优化挑有利测试。主面板排除在登记**活跃有限候选库**内的答案碰撞；不能简称为排除了所有可能错误的“零碰撞”。

CLASSOUT另设未参与覆盖最优化的双算子错误与双格编辑±12；具体内容只按2.9，首轮不再增加右到左呈现因子。需独立oracle和清楚语言。它是次终点，不和主COMPOSITION混合。

## 2.8 图像与人工/程序审核
生产渲染固定1280×896、同字体尺寸、同柱宽与图例位置。原图每6单位高度≥30像素，processor后的柱间距、字体框另记。不要将程序几何检查写成人类读得懂。

先每家族抽8张开发图（48张），含两个类别规模、同值、负差、端点和两列角色互换；审核必须针对实际processor图。审核者来源写 human/vision-agent/program，不虚构人工。没有图像检查或发现题意歧义，停止生产数据发布。

本包提供数据/证书参考实现与开发样例，不提供未核验的生产CLASSOUT或旧数据下载替代品；这些属于 Codex 的明确交付任务。


## 2.9 CLASSOUT的唯一实现规范
48新roots（每家族8），seed=2026102718。原任务规则仍取合法非保留组合，以隔离“新输入编辑/错误类”与COMPOSITION；不强造碰撞，不最大化P1覆盖。

每root使用4views：anchor，以及3个不同的双cell编辑。一次编辑在不同类别的两个格子分别施加±12；两格可同列或跨列，按固定seed在全部合法候选中均匀无放回抽取。数值在[12,84]、答案有限小数、集合非空非全、双oracle一致，三个编辑互异；所有视图与其他split的世界指纹隔离。训练只允许单cell±6，所以该编辑目录未进入训练。

类外诊断候选是两种查询运算同时错：TOPK为错rank+错direction、错direction+错value、k+1+错aggregate；INTERVAL为toggle-start+toggle-filter、toggle-end+错aggregate、错value+错aggregate。这些组合不参与P1编辑选择。它们只是明确的有限类外探针，不能覆盖所有未建模模型行为。

类外主报告仍看真实答案A；候选签名匹配允许UNKNOWN与多重兼容，不强制归因。测试构造不筛除“模型不犯这些错”的题，也不按类外候选匹配率挑选checkpoint。
