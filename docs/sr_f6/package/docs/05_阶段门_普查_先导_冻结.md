# 05｜阶段门、父模型普查、先导与冻结

## 5.1 先说明哪些决定现在固定
本包固定科学目标、六臂、题组规则、反馈公式、λ、正式 72 步、三个训练重复、主终点及多重比较。服务器阶段只补充真实路径身份、数据/图像 manifest、环境版本、测量与数值回执；不能根据效果重新选择剂量、种子或主指标。`DESIGN_FROZEN_CPU_REFERENCE_ONLY` 不是服务器授权回执已齐。

**停止的含义分开：**工程不合法 → 修复并保留事故；预定操纵/信用无法实施 → 报告当前设计不可估计；正式结果接近零 → 报告区间与精度；正式变差 → 报告负结果。后三种不得伪装成数值故障来重跑。

## 5.2 SOURCE_BINDING
读取 F5 recipe_v2 作为只读来源，核验本包 source manifest；定位原 Qwen snapshot、三个父 adapter、tokenizer/processor、原 J/证据充分性代码、实际 optimizer 和 generation 代码。每个对象记录路径、文件清单和内容 SHA256；不只记录 git 名称。

本机保留的 F5 `sr_f12_training.py` 与 `sr_f4_task_contract.py` 用于理解与对照，不自动证明服务器正在执行同一份代码。原运行失败记录不可删除、改名为成功或并入本轮分母。

固定 adapter 参数可训练列表、LoRA 配置、各父 checkpoint hash；参考策略为对应冻结父模型。任何真实路径与配置不同：输出差异，不擅自换父模型。不得把父模型优化器状态带入新路径。

## 5.3 DATA_AND_MEASUREMENT
本门分两段：先完成CPU/来源/生产接口预检查，允许采集已登记DEV_CAL普查；再从该普查中取360条真实回答完成审核，才签最终PASS。不得为了“先有审核再普查”另采一批未记账数据。PARENT_CENSUS与测量门的最终回执都齐全后才能进先导。

必须完成：双 oracle；全局组合隔离；同根跨 split 排除；两因子编辑成本与问题语义匹配；前缀/提示不含 gold；旧 J 投影一致性；真实 tokenizer、processor、真实生成 token 对齐；Oracle 标签不依赖 gold 引导的抽取；所有正式测试图像/问题在模型访问前封存。

生产 J 回归：至少 300 个程序生成夹具覆盖六家族，逐一比较旧原生 J 与新增字段投影后的旧 J；再对其中每个保持 V 合格地修改 selected/bindings 的内容，验证 J 不会意外随 S/B 真值变化。新增 V 的字段类型约束单独列出；它们是所有臂共享的协议变化，不能拿差异冒充旧 J 完全未变。

绘图检查至少 48 张开发图（每家族 8），同时查看原图与**真实 processor 后可视化**。核查每个数值是否对应正确柱、图例是否遮挡、裁切和刻度是否可读。审核者身份必须写明 HUMAN / MODEL_VISUAL / PROGRAM，不能把程序回执叫人工审核。没有实际视觉审查能力时标 NOT_RUN 并阻止正式启动。

标注审核至少 360 条**不同原始回答**，每父模型×数据因子 60 条，六家族各10；每 root 至多4条。预先按 PASS、FAIL、UNKNOWN 与 A/J 分层，稀有状态不足则全取并报告缺额，不能复制补满。原文、盲抽取结果、oracle、判定见证和复核方法同存；抽取器与判定器的同源一致不等于独立真值验证。错误的 oracle、假 PASS、标签使用 gold 反向抽取均为阻断问题。

## 5.4 PARENT_CENSUS：先推理，不训练
3父×2因子×48开发roots×4views×8draws＝最多9,216回答。仅用 DEV_CAL；训练/正式测试不可用于选择阈值。精确相同图像、prompt、父模型与 seed 的重复调用可缓存，但报告实际调用数；缓存副本不是独立抽样。每次输入只含一道题，不给兄弟题答案。

逐组保存 A、J、V、P、S、B、E_raw、E_anchored、finish、known mask、原生优势、三种反事实信用、置换结果。最小汇总：
1. 六家族×父×因子的 A×J×S×B×证据状态表；J=0、A=0分别计算。
2. 全零J、全一J、混合J组内的语义变化；非零信用组、存在可交换差异组、单次实际置换改变组分别计数。
3. 在所有样本、V合格样本和标签已知子集中分别报分母；正/负信用对应何种 A/J 状态。
4. P0/P1覆盖差、任务难度和输出长度；禁止按模型表现删除根或重新平衡。
5. 候选行为签名拟合与未使用编辑预测，仅开发诊断。仅“原题对、变体错”叫脆弱响应，不自动叫碰巧答对或已识别错程序。

预登记支持条件如下，不使用任务正确率目标：
- 每父×因子 V 与 S/B 各自可判比例 ≥90%，这是本轮测量可实施性要求，不是能力门。
- 每因子在三个父模型合计的 576 组中，COND 非零组 ≥24，至少12个不同 roots、3家族、2父模型。无需每父每窗口全部通过；也不要求 S/B 每个分量都非零。
- 两个因子合并的 SHUF 实际改变至少12组、涉及至少6 roots；不重抽置换种子直到改变。
- P1−P0有限候选覆盖平均 ≥0.05，且至少1/3训练roots严格增加。该操纵门检查生成器，不看模型效果；P0不能被有意择差。

这些覆盖数是**本轮最低可实施暴露范围**，不是统计功效证明，也不是普遍语义信息定理。低于门槛，输出 `INSUFFICIENT_REGISTERED_EXPOSURE`，保留现有数据并停止本轮正式启动。不得自动改为更难的任务、改变 λ、换seed或删父模型；数据单因子实验可作为另一个独立提案，但不是本合同自动降级后偷偷继续的路径。

## 5.5 RUNTIME_PILOT：不以方法成功作为门
3父×{U10,U11,C_SHUF}×1开发重复×12步，共13,824回答；DEV_PILOT与DEV_CAL不交叠。b0/U11另做step4恢复至12，共1,024条恢复生成，单列执行验证，不算第四重复。

父模型及9个端点在 DEV_EVAL 的96题×2draw评测，共2,304回答。只报告差值和区间，**没有“J必须显著高于父”“SHUF必须不显著不同于J”“U11必须领先”这样的门**。随机梯度信用可能有优化后果，其影响是对照结果。

通过条件：数值/事务/恢复有效；U11合计至少12个非零组、8roots、3家族；至少2父模型出现“step≤10非零干预→更新→下一次新生成→后续非零干预”。不要求每四步达到任意小计，最后一步孤立一次不算反馈闭环。SHUF的实际变化照实记录，不要求其效果为零。

12步只能核查实现和开发方差，不能据其小效应外推72步必小于1pp，不能用一个开发重复估计同父训练重复方差。正式3重复/72步现在固定，不依先导显著性增加。记录指标分辨率与预算局限，不能声称具有未经证明的80%功效。
