# Codex：从这里开始

## 任务
执行SR-F6“可验证语义信息的数据与反馈学习价值”实验。主问题保持宽；本轮只做一个P0/P1×J/固定oracle反馈的2×2，外加P1上的C_GLOBAL和C_SHUF两个固定对照。不重新开展方向讨论，不自行换成控制器、纯数据选择或只碰撞HARD实验。

## 先读
`docs/00_最终决定与一页合同.md` → `docs/01_Claude建议取舍与核心纠错.md` → 02–07 → `docs/08_Codex实施任务与产物.md`。完整参数以`configs/experiment.json`和公式章节一致为准，若两者不一致必须停下报错，不自行选有利版本。

## 第一批可执行工作
1. 解压到新的开发目录，先运行本包CPU命令。检查`MANIFEST_SHA256.json`，保留来源和原失败日志。
2. 只读绑定现有F5 recipe_v2的模型、父adapter、native scorer与生产runtime；不要写入F5运行根，不改变F5 FAIL判定。
3. 按08的T00–T03实现生产适配、数据/图像和测量。当前`src/srf6_ref`是CPU参考，不含真实Qwen trainer；不得声称已经有生产训练入口。
4. 实际来源/数据/测量预检查通过后，用DEV_CAL做父模型普查；用其中360条完成真实测量审核，同时签署两个最终门回执，满足05的登记条件再做12步先导。原始数据和负结果必须留存。
5. 无显著性或“shuffle必须无效”通过条件。实际证据齐全、配置身份一致，`launch_guard`允许后才可启动54条正式路径。

## 固定设置
Qwen3.5-9B、b0/b1/b2原J6父、三个独立重复、6臂、每路径72更新、128回答/更新、G8、λ=.5、S/B各.5、整序列信用、共同FP32/1536token、KL一次。主A不检查新增语义字段；J不检查S/B真值。所有主四格内数据/反馈因子必须真正正交。

## 禁止
伪造PASS/人工审核；默默换父模型或scorer；把J=0叫答案错；换种子追求差异；按效果增步/选checkpoint；按模型输出选择P0差例；奖励两错一致；把F5恢复样本算新重复；把CPU检查算GPU实验；升级服务器依赖以迎合本包无版本的CPU便利requirements。
