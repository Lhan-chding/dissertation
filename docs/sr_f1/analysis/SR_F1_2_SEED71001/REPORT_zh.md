# SR-F1.2 第一种子描述性分析与QoS澄清

## 范围与核验

仅 seed71001 的既有训练日志与 TRAIN_FIT 第32/64/96步记录。四臂各32题×4采样×3时点，共1,536条；原登记槽位、逐组及聚合hash通过，使用生产官方评分器逐条复算与原score完全相同。固定32题来自27个根，每题型8题。没有读取TEST、生成新回答、选择检查点、修改奖励/学习率/训练步骤或操作无关作业。不能把训练拟合结果解释为泛化、保留能力或三种子显著性结论。

## 观察及限制

1. A臂出现明显的答案/证据分离：TOPK共32条答对31条，但P与J均仅3条；整体31条“答对但证据未通过”。这是当前训练面板的观察，不能据此断言因果机制或测试集证据退化。
2. GATE与A答案均123/128，但J分别121/128与92/128，相差29条（22.656个百分点）。因此只看答案正确率会掩盖本面板的主要差异。
3. DEC在本面板第96步J最高，但只比GATE多3条（2.344个百分点）。32题/27根、单种子并不足以判定DEC最终优于GATE；同题四次采样并非128个独立实验单位。
4. J臂第96步13条“证据通过但答错”，其中CROSS有8条；瓶颈表现为证据通过后仍有答案错误。不能将其自动归因为数学能力下降。
5. 固定96步是冻结终点，不根据下表回选第32/64步，不追加调参或新臂。尚未取得相同面板的共同起点测量用于这里的配对比较，不拿MONITOR不同题集合充当TRAIN_FIT基线。

## 训练诊断

全96步平均格式失败率：A0.732%、J0.529%、GATE0.724%、DEC0.448%；每步128条，原失败均保留。终点KL分别0.01780/0.01812/0.01954/0.01126。实际优势数组全部为零的步骤分别8/9/4/26，最后16步分别1/1/0/12；DEC后期较常出现本批次无PG优势信号，KL仍可更新参数，不能说优化器停止或凭损失标量为零判定梯度为零。它与拟合面板较高分同时出现，但不构成因果证明。

第一种子平均每步秒数：A371.91、J324.10、GATE319.53、DEC354.65；采样和训练各占大约一半。当前第二种子的耗时必须独立统计，不能用这里的速度替代。

## 老师QoS的实际配置

实时`sacctmgr show qos`：`MaxSubmitPU=5`；`MaxJobsPU`、`MaxTRESPU`、`MaxTRES`为空；`GrpTRES=gres/gpu:pro6000=8`，其他列出的GPU类型额度为0。

- 5是每用户在这个QoS下运行中加排队中的作业总数，不是5张GPU。CPU作业若使用这个QoS也会占作业名额。
- QoS合计PRO6000资源上限为8张，是整个QoS共享上限，不是承诺本实验独占8张。
- 一个作业可以申请多卡；例如1作业4GPU在作业计数上仍为1。单作业/单用户资源字段为空表示本QoS未单设这些上限，仍需满足节点、分区、账号等其他约束和实际可用资源。
- 当前实验额外五物理卡guard来自先前明确的用户范围和冻结部署规则，并非QoS原生限制。这次询问未改动该guard或正在运行的训练。四卡真实计算由四个独立单卡臂完成；多申请GPU本身不会自动把现有单卡训练变成并行计算。
- 用户要求不关注无关任务；今后只在提交必须时检查必要的资源额度，不读取或讨论无关任务内容，不修改无关任务。
