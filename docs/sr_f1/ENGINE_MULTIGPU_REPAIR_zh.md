# SR-F1.1 多GPU加速修订

## 用户授权与资源规则

2026-10-10 用户明确要求：能用多张卡提速就必须用多张卡，老师的 QoS 还有余量时增加，最多5张。所有本实验GPU继续使用 `soujanya-poria-startfund-2026-03`。按该QoS实际GPU占用、排队及未知提交预留核算5张上限；不把其他QoS的无关作业算入，也不取消、修改或重排无关作业。此条取代旧单GPU实现及原始包的单卡worker资源分配，不更改科学实验矩阵。

本次开始实施时，实时队列显示：本实验196227占1张PRO6000；无关作业196002在同一老师QoS占1张。因此本轮目标为本实验4张、合计5张。实际释放前须重新核实作业、QoS、GPU数量、highmem和主机内存。ENGINE及有梯度的训练路径使用固定已认证卡数；只需前向的评价仍用1张，按依赖并行。当前运行进程不能直接热加卡；经验证的资源变更在维护重启或后续作业边界生效。

## 已观察的性能问题

旧单卡 ENGINE 的首批128条回答已生成，首个优化器更新尚未完成。第一批前3条序列从参考前向到下一条参考前向分别约93、96、75分钟；259-token梯度序列除48GiB主机内存激活外，还写出75,277,728,928字节HDD派生暂存，并按原计算两次反向读取。第4条序列不等于第4次更新。旧作业没有出现新的失败，维护原因记录为性能加速。

## 实施范围

GPU0继续执行原数值计算，辅助GPU按原dtype、storage span、shape、stride保存激活。辅助GPU预算每张80GiB，满后使用原48GiB CPU层和独立HDD层；完整图、两次反向、参数版本检查和清理保持。不会使用DDP或改变梯度累加顺序、采样、损失、学习率、768-token上限、五臂×三seed×96步。

新增 `ENGINE_MULTIGPU_REPAIR.json` 追加绑定原I/O修订、原源码副本、注册身份、旧作业和保存证据；不重写任何原冻结或旧修订。原单卡检查点的CUDA RNG拓扑不冒充多卡状态；保留旧完整路径和成本后，新多卡ENGINE完整重做连续4步与独立2+2验收，不拼接部分梯度、不重复消费旧一次性恢复例外。科学训练与TEST继续受原门禁控制。
