# SR-F1.1 基线并行与自动交接

## 授权和固定预算

用户要求后续基线测量也使用多张GPU并行提速，ENGINE通过后自动接续；所有GPU使用 `soujanya-poria-startfund-2026-03`，当前用户在该QoS内运行、排队及未知提交的GPU预留合计最多5张，不改动无关作业。

原基线任务及依赖保持 `ENGINE → BASELINE → 15个科学训练任务`。基线生成槽位仍为6,784：MONITOR 4,096、五种诊断视图2,560、TRAIN_FIT 128。保留每条槽位的qid、draw、协议、视图、输入、采样seed、温度、token上限、公共零LoRA和评分器；不读取TEST或增加样本。

## 执行与恢复

保留原注册中唯一BASELINE任务。首次提交前读取老师QoS实际余量，选择最多5张可用GPU，将卡数和容量证据写入不可覆盖的 `BASELINE_PARALLEL_ALLOCATION.json`。单次Slurm分配内启动N个独立Python子进程，每个进程仅可见其中一张GPU，各自加载公共起点模型。按原有顺序索引对N取模分片，槽位与seed不变。运行中的拓扑不热改；续跑使用同一已认证卡数。

每片独占原始JSONL，逐条落盘。已生成记录恢复时通过身份与输入哈希校验后跳过，不重复采样。所有原始错误和失败保留。父进程只有在全部分片、回执、原始记录哈希及6,784条精确覆盖通过后才完成BASELINE。原发布审计直接遍历各片文件，不另建会导致重复计数的合并文件。缺失、重复、跨片、身份变化或技术失败均阻断后续科学训练。

## 不中断ENGINE的交接

候选源码与CPU测试先放在独立目录。新的CPU交接程序在调度锁内核实旧控制器身份并只终止本实验旧CPU控制器；GPU ENGINE原作业、原源码和全部检查点保持。交接程序只观察并核验ENGINE，不调用会提交串行基线的旧调度循环，也不创建会中断训练的STOP文件。

只有ENGINE退出队列、Slurm为COMPLETED/0:0、完成标记及连续4步对独立2+2完整验收均通过，且基线及下游仍无attempt时，交接程序才保存旧源码、追加 `BASELINE_PARALLEL_REPAIR.json`、激活已测试候选并启动新调度循环。原 `REGISTRATION.json`、冻结、旧修订和历史ENGINE资源对象保持。激活意图和阶段回执持久化，未知状态不触发重复提交。
