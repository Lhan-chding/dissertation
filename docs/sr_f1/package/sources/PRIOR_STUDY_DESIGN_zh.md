# 下一版研究设计候选：诊断究竟能否帮助给出更有效的反馈？

日期：2026-10-09。这是讨论用设计，非Codex执行授权；不覆盖F2。标记：[C]Claude原稿，[R1–R8]配套全文核查，[M]本轮数学检查；未标为来源的“建议”均是本轮方案。

## 0. 想得到的实质性结果

我们希望别人能够从这项研究学到：面对某类定量视觉推理任务，如何区分“最终奖励遗漏了有用差异”“给了细反馈却仍缺正确支持”“题目并没有要求模型学会目标行为”，以及哪种处理真正改善不带辅助信息的新任务。

不以另一个gate名字或分支预测率为最终产物。也不要求对每类错误都有唯一的内部机制解释。

## 1. 一组完整、可计算、包含语言语义的题目

### 1.1 语义世界

下表只是程序真值，不直接交给原始图表任务中的模型：

| 月份 | 系列A | 系列B |
|---|---:|---:|
| March | 30 | 20 |
| April | 42 | 50 |
| May | 26 | 14 |

由同一世界渲染可读图表。原查询：

> 对A大于B的月份，求这些月份A的数值之和。

执行结构为：`lookup(A,B) → filter(A>B) → select(A) → sum`。符合条件的是March和May，答案56。

### 1.2 同根题族

| 成员 | 精确改变 | 真实答案/行为要求 |
|---|---|---|
| v0 原任务 | 无 | 56 |
| v1 表面等价 | 颜色/图例顺序/布局变化，但对象指代不变 | 56；证据含义不变 |
| v2 无关信息 | 增加不参与条件的系列C | 56 |
| v3 相关证据变化 | April的A从42改成60 | 116；参与集合增加April |
| v4 运算变化 | 原世界保持，sum改成mean | 28 |
| v5 边界条件对 | April的A改成50，分别问“大于”和“不小于” | 严格大于为56；不小于为106 |

v5不是简单的另一种表面改写，而是查询语义不同的独立变换类型。空集、并列最大、单位、否定范围和除零应有清楚契约；尚未支持的情况不由自然语言生成器随意加入。

**价值：**同一程序库覆盖定位、条件理解、比较、筛选与聚合，能够检查目标任务中的组合行为。这比只把图画模糊来制造错误更接近有意义的任务能力。

这些手工示例可直接用普通算术复算；本轮未渲染它们、未让Qwen回答，也不是新数据集的实测结果。

## 2. evidence＋answer需要一个明确的“证据契约”

第一版继续用两个顶层字段，但不能把“答案贡献项”与“证明筛选正确所需的证据”混为一谈。

在上述查询中，只列A_March=30、A_May=26，足以加出56，却不能验证它检查了April是否应被排除。首版可以明确要求：

> evidence列出用于判断筛选条件及计算答案的A、B两系列三个所问月份的六个读数；不要求生成自然语言推理链。

对应标准实体键集合为六项。读数应精确对照真值，不把模型报出的值作为新真值。以后若接受更紧凑的证书，需要预先定义可接受证书集合或验证谓词，不按一个唯一参考字符串排斥等价解。

示意输出：

```json
{
  "evidence": [
    {"series": "A", "month": "March", "value": 30},
    {"series": "B", "month": "March", "value": 20},
    {"series": "A", "month": "April", "value": 42},
    {"series": "B", "month": "April", "value": 50},
    {"series": "A", "month": "May", "value": 26},
    {"series": "B", "month": "May", "value": 14}
  ],
  "answer": 56
}
```

明确提示证据覆盖范围会改变原来完全自由问答的任务，这是需要报告的协议差异。所有训练对照采用同一协议；另外在不要求evidence的普通问答协议下检查答案迁移，不能把格式收益等同于整体能力收益。

评分器至少记录：字段有效性、实体集合正确性E、逐所需证据的数值正确比例p、答案正确A、J=完整证据与答案都正确。额外/重复实体、空列表、非有限数、单位、JSON布尔与数字混淆均需有明确处理。C只作外部一致性诊断，不独立奖励“自洽的错误世界”。

## 3. 数据生成和诊断视图

### 3.1 生成器

程序固定类型化查询及世界规则；LLM可以提出程序草案、场景或语言表达；程序独立执行给出真值。LLM回译与原程序一致是过滤证据，不是自然语言无歧义的充分证明。

同一测量/训练批次对模型不泄露隐含根ID、真值侧表、奖励及变换标签。训练、监测、开发、锁定测试按完整根家系隔离。逻辑组合、表达模板、渲染风格还有各自的留出身份。

### 3.2 有限诊断视图

| 视图 | 向模型提供的信息 | 可以观察什么 |
|---|---|---|
| 原图＋问题 | 无额外帮助 | 真正目标表现 |
| 对象指示 | 相关对象键或合法定位线索 | 获得选择线索后的行为变化 |
| 真值读数 | 程序给定必要读数，原查询保持 | 已知证据下能否执行查询 |
| 可执行子题 | 相同规则的筛选/比较/算术子问题 | 局部任务中有没有正确/部分正确支持 |
| 无关提示控制 | 等长度但不提供所需证据 | 上下文、长度和风格影响 |

有帮助的视图不是免费信息，计入监测或监督成本。不同视图在独立上下文采样，不把同一题前一条真值答案塞进后一条测量。普通图任务的成绩与辅助视图成绩分表。

这些差异测的是信息供给条件下的行为，不直接恢复“纯感知/纯计算”的内部因果分解。找到一个有效辅助视图，也不能推断同名奖励一定最有效；训练匹配要检验。

## 4. 测量到底输出什么

每个题族×查询结构×视觉条件输出：

- 各语义事件联合分布、分母、有效根、字段覆盖及不确定性；
- 当前同通道G组中各奖励的对比率、分支率和分量std；
- 候选优势在每类真值结果上的W±、粗奖励同分内部的信用变化；
- 相关/无关变换表现和不同信息供给视图的差；
- 标准字段NLL、奖励可用率、实际调用与监督权限等共有信息。

原始逐轨迹分数、组件联合结构、采样设置及实际最终优势全部保留。不能因为题族的错误多，就把全部题都加到训练里后仍称测量分布代表自然任务总体。

## 5. 一条足够具体、但不过度庞大的方法路线

### 5.1 快反馈库：先用相同原始任务数据比较

| 反馈 | 明确作用 | 必须对照的风险 |
|---|---|---|
| R_A | 最终答案 | 混淆答案对但证据错 |
| R_J | 精确目标联合正确 | 稀疏与零对比 |
| 固定部分正确反馈 | 如J+β(1−J)s，0≤β<1，s来自已验证要求 | 部分正确可能改变目标权衡；单样本排序不保证策略收益 |
| GDPO式组件处理 | 逐组件归一化及其真实批次处理 | 信用可能组合抵消或放大，需记录最终优势 |
| 有界门控精化 | 主J有对比时保留失败内部的小量真值区别；无J支持时条件性使用证据/读数 | 参数耦合可使J下降；D类组仍可能没有信号 |

先比较这五类，是为了选择一个真实有效的固定反馈，而非预定最后一种获胜。固定部分正确反馈不能因为“简单”就删除。

### 5.2 慢测量如何进入奖励：不必退回大规模训练响应搜索

一个可讨论的最小设计是：数据曝光和反馈库固定，按预先规定的短监测窗口更新每个题族的**反馈模式**，而不是改变所有数据比例、奖励参数和优化器。

模式库只保留：精确目标反馈、证据优先的部分反馈、已选的分组件反馈；若所有信号都缺支持，仅标记“需支持”，不通过多乘一个权重假装解决。模式数量和选择规则必须在开发后冻结。

候选策略可以从很小的决策表起步：输入只包含可估的持续性错误构成、反馈分辨率和信息供给改善；规则阈值与置信处理只在开发集定。**“读数错多→某奖励最好”仍是经验假设**，不能从标签直接推出。第一版也可以保持模式固定，只比较细粒度奖励；无需为了名字里有“状态”而强制做动态策略。

若主要研究价值最终来自可靠题组与固定反馈获得的显著迁移，不应仅因没有动态控制器就否定它；要与R1/R3/R4/R6/R8的功能和结果范围正面比较。

### 5.3 真正检验诊断增量的四个对照

在相同真值、相同候选反馈、相同原始数据流与相同监测预算下，比较：

1. 开发集上选定的最佳固定反馈；
2. 只看A/J、常规难度和支持量的反馈选择；
3. 加入细粒度语义诊断的选择；
4. 将诊断在相同类型/难度的题族间置换后的选择。

置换只改变“诊断用到哪个题族”，**绝不把错答案当训练真值**。输出模式总量若会受置换改变，需要使用分层受限置换或另外报告模式数量匹配对照，不能让某方法因获得更多高成本支持而看似更好。

第2项尤其重要：诊断比随机选择好，不代表它比简单难度/联合正确率好。LMOPD已经做过路由匹配相关对照[R5]；本研究要证明的是当前可验证诊断和有限反馈设计的实际价值，不是声称首次做路由。

## 6. 计算支持的独立实验身份

Claude提出的文本给值/计算子族保留于测量库；若需训练它，单独比较：

- 固定比例的正确计算支持；
- 语义诊断匹配的正确支持；
- 同量、同难度、但诊断匹配关系打乱的正确支持。

三者真值都正确，支持量/额外上下文/教师或程序成本同口径。主终点是撤去这些帮助后，原始图像问题和新查询组合是否改善。

不要在反馈比较过程中看到D占比高，就只给某一个臂补计算题，然后将变化全部归因于门控。也不要因为纯RL无对比就把教师轨迹混入学生on-policy组而不声明。

## 7. 一个有意义但可管理的实验安排

### A. 工具与任务核验

生成规则、证据契约、自然语言歧义、渲染可读性、原始协议、真值泄漏检查。先用有限读数确认测量支持，不按结果无限加难。

### B. 固定数据上的反馈比较

运行5类快反馈，不展开全部数据×全部reward×全部mode。主要回答：更精确和更稠密的反馈，在这个任务族里是否提高J及原始任务表现？选择标准在开发集固定。

### C. 核心诊断价值比较

只有需要声明“语义状态指导训练”的增量时，执行§5.3四类策略。新根和必要的新表达组合上先固定策略，再观察训练与测试结果。无需事前预测整个参数空间或任意数据配方的响应。

### D. 支持迁移验证（条件性独立块）

需要额外支持才能继续时，采用§6。教师/程序支持本身就是干预，和奖励内容分别记账。

H、根数、重复数不是本轮冻结内容。正式计划必须按效应关注量、训练噪声、监督成本和新协议支持确定；GPU小时没有研究停止阈值，但仍有明确的实验完成范围。不得把“没有GPU时间上限”理解为无限追求显著结果。

## 8. 主要终点不只是自造题的门控率

**首要：**未见原始完整任务的J和A，必须同时报告evidence协议与普通答案协议；逐语义操作/变换类型报告。

**迁移：**完整根未见、新查询组合、新语言表达、新渲染分别核验；至少一项不依赖本生成器的相关公开任务或另一载体作为外部检验。若外部数据没有证据真值，只报告A及可核验子集，不强造J。

**作用来源：**反馈匹配与置换差异、成本、奖励和实际优势的变化；观察是否只减少易于评分的表面错误。

**不利结果：**改进集中于某一任务而另一任务下降，不能用宏平均抹掉。用户允许某些能力权衡时，要事前声明目标和容忍范围，不必一律坚持所有指标不降。

**统计：**同根变体相关、同训练种子相关；多次生成提高评分精度，不构成多个训练重复。未发现显著差异不自动等于方法严格等价；本轮结束，不按结果临时换主要终点。

## 9. 什么会让这个方向有意义，什么还不够

有意义的组合证据：有代表性的目标任务确实改善；细诊断比已有固定/简单适应方法更会提供反馈；撤去支持和格式要求后有迁移；费用与收益可解释；至少一个场景说明细奖励或支持何时不值得用。

不够的证据：branch比例预测准确；一个特定组的优势更细；只在模板变换题上提高训练reward；小门控略胜明显弱基线；将不同论文的复杂模块拼起来后不做贡献拆分。

如果严格验证发现“好题组＋简单J已经足够”，结论也可以很有价值，但论文定位应成为目标任务/学习条件的实证研究，与R8等直接比较，而不是强行保留动态语义控制的新名词。

## 10. 给其他模型的一句话任务

请评估这套方案能否产生有用的学习结论和实际能力改善；选择最有判别力的一组实验，指出还缺的必要对照。不要要求每个组件都无先例，也不要因为只有组合创新就免除证据责任。
