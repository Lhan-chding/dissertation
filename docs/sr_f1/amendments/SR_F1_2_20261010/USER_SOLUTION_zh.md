# SR-F1.2 提速修复与设计补充（交Codex执行）

Oct 10, 2026 · @Louis

## 0. 结论先行

**120天不是实验本身需要的，是训练代码为一个不必要的数值要求付出的代价。** 每次更新约2小时，其中约92%花在训练前向上：对每条回答逐个token重放生成过程并保留全部计算图（一条回答约99 GB激活，所以要借3张卡存），再对同一张图做两次反向。这样做是为了让训练时的概率和采样时的概率完全一致。但合同规定每批采样只更新一次，此时可以直接用训练前向自己的概率做“旧概率”，概率比恒为1，这个一致性要求也就不再需要。

**修复后的预计：每次更新约6–12分钟（现在约120分钟）；每条训练路径单卡、约10–20小时；单卡路径可以4–5条并行。主实验约1.5–2.5天，连同代码修改、起点测量和终点评价约4–6天。** 这是外推，第一个实测数字来自§6的技术核对。

改动分三类：

1. **删掉的（多余操作）**：逐token缓存重放；只为记录诊断量而做的第二次反向；采样器一致性硬门槛；一条路径占4卡；ENGINE的逐位恢复和压力测试；终点的MONITOR重测；偏移面板上的答案协议；PART臂降为可选。
2. **改的（效率）**：整句批量前向加一次反向；同一题的8条回答批量生成；每条路径单卡、多条并行；按种子优先顺序跑，第一波结束就有完整的各臂对比。
3. **补的（严谨与对齐）**：LoRA扩到语言模型全部线性层，并加“策略是否真的动了”的预登记检查，保证空结果可解释；采样偏差用截断重要性采样统一修正；用起点的语义状态表预登记“各奖励在哪类题起作用”的预测，把SR-F1和核心想法连起来；答案协议也加预填。

不变的：模型、数据和根、奖励定义、组大小、步数、KL、主终点与自助法、TEST封存。对比族因PART降级由5个变为4个（§4.3）。

**当下要做的两件事：** 立即停掉正在跑的ENGINE（它在验证一条将被替换的路径，剩余11–13小时都是浪费）；空出的卡马上跑起点测量，因为它只用生成，不依赖训练路径，可以和代码修改同时进行。

## 1. 时间账：每次更新的2小时花在哪里

数据来自 SR\_F1\_1\_MULTIGPU\_TIMING\_20261010\_1211、SR\_F1\_1\_MULTIGPU\_FIRST\_UPDATE\_20261010\_1350、SR\_F1\_1\_MULTIGPU\_SECOND\_UPDATE\_20261010\_1608 和 SR\_F1\_1\_ENGINE\_FIRST\_FORWARD\_20261010\_0619。

| 环节 | 实测 | 占一次更新的比例 |
| --- | --- | --- |
| 采样：128条回答逐条生成，平均206个token | 609秒（每条4.76秒） | 约8% |
| 训练：128条回答逐条做参考前向、梯度前向和两次反向 | 约6,574秒（每条约51秒；attempt0004单条47–63秒） | 约92% |
| 一次更新合计 | 第1步7,183秒，第2步7,397秒 | 100% |

训练阶段，每条回答要做四件事：

1. **参考概率**：把可训练参数换成起点参数，沿采样时的缓存解码路径逐token重放一遍（不求导）。
2. **当前概率**：沿同一条缓存路径再重放一遍，每个token一次模型调用（一条259个token的回答 = 1次1,023个token的预填 + 258次单token调用），并保留全部计算图。
3. **第一次反向**：`autograd.grad(policy/128, retain_graph=True)`，只为记录“纯策略梯度范数”这个诊断量，结果不参与更新。
4. **第二次反向**：对总损失（策略项 + 0.02·KL）反向，这才是真正用于更新的梯度。

第2件事保留的计算图约99 GB（338,954个张量），一张卡放不下。attempt0003把它溢出到CPU内存和磁盘，单条5,288秒；attempt0004借3张卡存激活，降到约60秒，快了92倍，但仍是每条一分钟，而且一条路径占4张卡。

**为什么要逐token重放。** 代码里有一道硬门槛：训练前向算出的token对数概率必须和采样时记录的几乎一样（平均差 ≤ 0.005 nat、最大差 ≤ 0.05 nat，否则抛错终止）。Qwen3.5的24个线性注意力层，逐token解码时用递归算法，整句计算时用分块算法，bf16下两者数值不完全相同，整句前向过不了这道门槛，只好把解码过程原样重放。

**120天怎么来的。** 约2小时 × 96步 ≈ 8天/路径；一条路径占4卡，而配额上限5卡（其中1卡被无关作业196002占着），只能一条接一条跑；15条路径 × 8天 ≈ 120天。因果链是：一致性门槛 → 逐token重放 → 超大激活 → 每条路径4卡 → 只能串行。切断第一环，后面几环都不复存在。

## 2. 必改一：训练计算路径

**2.1 旧概率取训练前向自己的值。** 合同规定每批采样只做一次优化器更新（epochs\_per\_rollout = 1），所以计算梯度的那一刻，“旧策略”和“当前策略”是同一组参数。令 `old_t := stopgrad(logπ_train(y_t))`，则 `ratio_t = exp(logπ_t − sg(logπ_t))` 的值恒为1、梯度恰为 `∇logπ_t`；(0.8, 1.2) 裁剪永远不会触发（代码保留，clip\_fraction 应恒为0，正好当自检）。这在数学上就是现在想要的目标函数，只是不再要求训练前向去复刻采样器的数值。

**2.2 采样偏差用截断重要性采样修正。** 剩下的只是采样器（递归解码）与训练器（整句分块）之间的数值差，即行为策略与目标策略略有不同。标准做法是截断重要性采样（TIS；Yao et al., NeurIPS 2025, “On the Rollout-Training Mismatch in Modern RL Systems”）：每个token的策略项乘以

`w_t = min( exp( sg(logπ_train,t) − logπ_sampler,t ), C )，C = 2`

所有臂都用，C在修正案里事先固定。删除0.005/0.05的报错门槛，改为每步记录平均|Δ|、p99、最大|Δ|和w被截到C的token比例。只保留一条“查错”门槛：平均|Δ| > 0.01 nat 时报错——这么大的差只会来自代码错位（比如预填的“{”没进训练输入、位置编码错了），不会来自bf16数值。

**2.3 目标函数：与现在相同，只多一个w。**

`L = (1/128) Σ_i (1/|y_i|) Σ_t [ −w_{i,t} · A_i · ratio_{i,t} + 0.02 · k3_{i,t} ]，k3 = exp(ref−cur) − 1 − (ref−cur)`

128条回答等权、回答内对token取平均、每个token的k3 KL，都与现有 `sequence_objective` 一致；优势 A\_i 仍由 `reward_advantages` 给出，训练器里不再归一化或裁剪。

**2.4 前向怎么算。**

- 用 `mm_core/vl_runtime.py` 里已经审计过的整句teacher-forcing路径（`sequence_forward`：`use_cache=False`、`logits_to_keep`、fp32 `log_softmax`、每次前向前清 `rope_deltas`），把它扩展成一次算同一题的多条回答。
- 同一题的8条回答prompt完全相同，只需在回答末尾**右侧**补pad（线性注意力和卷积都是因果的，右补不影响前面的位置）；不要左补。传attention\_mask，让每行单独计算mRoPE位置；pad位置不进损失。
- 只在回答位置算 lm\_head 和 log\_softmax（`logits_to_keep` = 组内最长回答长度+1），不对1,000多个prompt位置算24.8万维的词表。
- 微批：先试每批4条、不开梯度检查点；放不下就改为2条、1条。微批大小只影响速度、不影响梯度（各条损失求和后除以128），在技术核对里定下后所有臂相同。估计单条激活约10 GB，4条约40 GB，加上18 GB模型，一张96 GB的卡够用。只有连1条都放不下才开梯度检查点——HF只在 `model.train()` 下启用检查点，此时须确认所有dropout为0、train与eval两种模式输出一致。
- 参考概率：同一条整句路径、`no_grad`，参数仍用现有的 `reference_parameters` 交换，不改。
- 只做一次反向：删掉 `autograd.grad(..., retain_graph=True)` 那次诊断反向。梯度诊断改用 `clip_grad_norm_` 返回的总范数；“优势全为0时策略梯度为0”改为一次性单元测试（KL系数置0、优势置0 → 梯度严格为0），不再每步做。
- `cached_training_forward` 留在仓库里但训练不再调用。rollout记录里的采样概率只叫 `sampler_logprobs`；训练时算出的 `train_logprobs` 只存统计量（试跑第1步逐token保存，供§4.4的移动量检查用），避免两种概率混用一个名字。

**2.5 预计。** 由已有生成记录拟合，1,022个token的预填约0.5秒；整句约1,230个token的前向与之相当，约0.6秒；反向约为前向的2倍；再加一次参考前向，单条约2.5–3秒，128条约5–6.5分钟（现在约110分钟，快17–22倍）。一条路径只需1张卡。

## 3. 必改二：生成批量化与并行

- **同一题的8条一起生成。** 用 `num_return_sequences=8`；若它对图像输入的展开有问题，就手动把同一prompt复制8行（含 `pixel_values` 和 `image_grid_thw`）。prompt完全相同，不需要任何填充。`generate` 里“每次调用只生成1条”的限制只对训练采样和评测采样解除。
- **逐行截停。** 平衡JSON截停按行判断（参考实现 `BalancedJSONStop` 已经返回逐行布尔，HF会把停下的行标记为完成、之后补pad），每行回答截到自己的停止token；`finish_reason`、`truncated` 逐行记录。
- **逐行记录采样概率。** 从 `output_logits` 按行、按各自长度取被选token的 log\_softmax；“没有未登记的logits变换”这项检查也逐行做。
- **随机种子。** 每组用登记的第一个种子（或该8个种子的哈希）作组种子，记录（组种子，行号）。同一步、同一槽位在各臂之间仍用同一个组种子，所以第1步各臂拿到的是同一批回答，配对性保留。代价是不能再单独逐位复现某一条回答；审计依据是已落盘的原始token、文本和哈希。
- **长度上限保持768。** 预填后回答中位193、p90 265、最长276个token，从未触顶；一批只跑到组内最长那条停下，上限高不花时间，也就不必为此改合同。
- **预计。** 每组约8–12秒（8×1,022个token的预填约1–2秒，加组内最长约270步、每步25–35毫秒），16组约2–3分钟/步（现在约10分钟）。加上§2的训练，每步约6–12分钟，宽的一端留给torch回退核可能比估计慢的情况。

**并行方式。** 一条路径一张卡，4条路径同时跑；若作业196002释放第5张卡，用它跑评测或可选的PART。

**评测也批量。** 默认同一题的K个样本一批（与训练采样同一套代码）。想更快可以跨题批量（左补pad），但必须先过§6的一致性检验；不过就退回同题批量，评测时间约翻倍，仍在预算内。

**可选加速（只在实测单步 > 15分钟时考虑）。** 安装 flash-linear-attention 和 causal-conv1d 快速核，8个全注意力层由eager改为sdpa。必须在科学运行前决定，所有臂、所有评测一致；否则不动。

## 4. 设计补充：让想法、目标和设计对齐

**4.1 想法与SR-F1的位置。** 整体想法是两块：先测出模型的语义状态（每类题上证据集读对、读值读对、证据与答案同时对的概率，以及同一题8条回答里这些事件有没有差异），再用这些语义事件构造奖励去指导训练。SR-F1是“指导”这一块的第一个实验：奖励固定、不随训练调整，只回答两个问题。

- **Q1（主问题，决定论文主张）**：在同样的题、步数和算力下，用语义事件做奖励（J、GATE、DEC）是否比只奖答案（A）更能提高TEST\_ID上的联合正确率J？在加入语义信息的几种方式里，分层的GATE是否既胜过只奖J、也胜过加权求和的DEC？
- **Q2（次问题，把“测量”和“指导”接起来）**：训练前测出的起点语义状态，能否事先说出每种奖励会在哪类题上起作用？

取舍标准很简单：不服务这两个问题、或者只是工程保险的操作，删掉或降级；能让结论更可解释、又几乎不花算力的，补上。

**4.2 逐项对照**

| 设计元素 | 服务于 | 决定 |
| --- | --- | --- |
| A臂（只奖答案） | Q1的基线 | 保留 |
| J臂（只奖联合事件） | Q1：只奖联合事件够不够 | 保留 |
| GATE臂（J有组内差异时以J为主、失败者之间按读取质量微调；J无差异时先用E、再用p\_read分高下） | Q1：本文方法 | 保留 |

**4.3 对比族。** 主对比由5个改为4个：J−A、GATE−J、GATE−DEC、DEC−J。按根的自助法（5,000次，种子812901）和多重比较的校正方式沿用原方案，只是对比族变小。若PART跑了，PART−J和GATE−PART作次要对比报告。“分层 vs 加法组合”这个理论上最关键的比较，由GATE−DEC承担。

**4.4 LoRA范围与学习率：补的是可解释性。** 现在的LoRA只挂在8个全注意力层的q、v上（16个模块），24个线性注意力层和全部MLP都动不了。Thinking Machines的“LoRA Without Regret”发现：只挂注意力层明显不如挂全部层（尤其MLP），即使参数量相当；RL对秩不敏感（秩1也行）；LoRA的最佳学习率约为全参数微调的10倍，训练步数少时更高。范围太窄的风险是96步后各臂都没怎么动，结论分不清“奖励没用”还是“适配器动不了”。改为：

- 目标模块：语言模型各解码层里的全部线性层（全注意力q/k/v/o、线性注意力的各投影、MLP的gate/up/down），不含视觉塔、merger/投影器、lm\_head和词嵌入。Codex列出实际模块名写进修正案。
- r=8、α=16、dropout 0、B初始化为0不变；学习率从5e-5起（现为1e-4；可训练模块从16个增加到两百多个，同一学习率下函数变化大得多，是否回到1e-4由下面的试跑规则决定）。
- 新的共同起点 SRF1\_2\_COMMON\_ZERO：B=0，所以输出与基座完全相同，技术核对里用32条回答验证对数概率逐位相等（最大差 = 0）。也因此，§6第1步的起点测量不受这项改动影响，可以马上跑。
- 学习率规则（事先登记，只看移动量和稳定性，不看J或A）。试跑用GATE臂、ENGINE根和现成的8步输入流、非科学种子：
  - 出现非有限值，或第5–8步格式失败率 > 20%，或第8步每token KL（k3）> 0.05 → 学习率改为2e-5；
  - 否则，若试跑第1步那128条回答在第0步和第8步策略下的平均每token |Δlogπ| < 0.01 nat → 学习率改为1e-4；
  - 否则保持5e-5；
  - 最多调一次。调过之后用新学习率再试跑8步，只看稳定性；仍不稳就停下来报告，不再自动调整。选定的学习率用于所有臂和所有种子。

**4.5 预登记预测：把测量和指导接起来，不多花一条生成。** 起点测量（MONITOR K8 + 诊断视图K8）产出起点语义状态表，也就是我们说的 semantic prob state 的第一个版本。对每个题型族 f 记录：A、E、p\_read、P、J的均值；组内（8条）信号可得性——A有差异的题比例 s\_A、J有差异的比例 s\_J、J全为0且E有差异（或E全为1而p\_read有差异）的比例 s\_G（即GATE的分层信号能派上用场的比例，与 `gate_one` 的分支一一对应）；P=1中A=0的比例 D\_f（读对了却算错）；gold\_values视图下的A。科学运行开始前写下：

- **P1**：按起点 A−J 差距把题型族分为三档。高档（例如THRESHOLD：A≈0.9、J≈0.4–0.5）里，J臂相对A臂的J增益大于低档。理由：答案奖励在这些题上近乎饱和，组内没有区分“读对”和“读错”的信号。
- **P2**：按 s\_G 分三档。GATE相对J臂的J增益，高档大于低档。理由：GATE只在J没有组内差异、而E或p\_read有差异的组里比J臂多出信号。
- **P3**：把 D\_f ≥ 0.5 且 gold\_values 视图下A比原图提高不到0.1的题型族记为“计算瓶颈”，其余为“读取瓶颈”。GATE−J 的增益在计算瓶颈族里小于读取瓶颈族。理由：GATE多出的信号只奖励读对，不奖励算对。
- **机制核对**：GATE路径前8步里落在纯语义分支（evidence、readings）的组所占比例，与按TRAIN题型族比例加权的 s\_G 预测值相差不超过10个百分点。

增益一律用TEST\_ID上第96步减起点、3个种子平均、按根自助法给区间。这些是次要分析，不影响主终点；但论文能不能说“测量指导了训练”，而不只是“换了一个奖励”，就看它们。

**顺序与验收：**

0. **立即停掉 ENGINE\_attempt0004。** 保留全部记录（它是旧路径耗时的证据），释放GPU。它在验证一条即将被替换的计算路径，剩下的11–13小时没有用处。
1. **起点测量（与第2–5步并行）。** 在共同起点（零LoRA，输出即基座）上、按SR-F1.1协议（预填“{”+平衡截停）跑 MONITOR K8（4,096条）和五个诊断视图 K8（2,560条），产出§4.5的起点语义状态表（按题型族）。可以先用现有逐条采样器，3–4卡约2–4小时；批量采样器就绪后，剩余部分换用它即可（两者是同一分布的样本）。TEST保持封存。
2. **登记 SR-F1.2 修正案。** 内容 = 本文§2–§5的全部改动及理由，附代码提交哈希，在任何科学路径开始前冻结。
3. **改训练路径（§2）。** 验收（CPU单测）：五种优势（A/J/PART/DEC/GATE）都走同一个损失；优势全0且KL系数为0时梯度严格为0；ratio恒为1、clip\_fraction恒为0；w在C处截断；右补pad的多行结果与逐行结果一致。
4. **改生成（§3）。** 验收：逐行截停、逐行采样概率、逐行finish\_reason正确；同组8行的prompt张量哈希一致；组种子在各臂之间相同。
5. **改LoRA与学习率（§4.4）。** 验收：可训练参数只在语言模型解码层的线性层里；视觉塔、投影器、lm\_head、词嵌入冻结（沿用现有检查）；SRF1\_2\_COMMON\_ZERO与基座的对数概率最大差 = 0。
6. **GPU技术核对 + 8步试跑**（GATE臂、ENGINE根、非科学种子、1张卡）。全部通过才能进入科学运行：
   - a. 批量 vs 单行：16条回答的teacher-forcing对数概率，平均|Δ| ≤ 0.002 nat、最大 ≤ 0.05 nat（只为抓位置、pad、mRoPE错误）。
   - b. 采样器 vs 训练器：报告平均、p99、最大|Δ|和w被截断的token比例；平均|Δ| > 0.01 nat 即报错；截断比例 > 1% 时先查原因再继续。
   - c. 每步loss、KL、梯度有限；参数确有变化；Adam矩非零。
   - d. 恢复：第4步提交后杀进程再续跑，参数、Adam状态、调度器、游标、RNG的哈希与提交时一致；不要求重新生成的回答逐位相同。
   - e. 计时与显存：8步的采样/训练分项时间、显存峰值；据此定下微批大小（所有臂相同）。单步 > 15分钟才考虑§3的可选加速，并在科学运行前定死。
   - f. 按§4.4的规则定学习率。
   - g. 评测引擎：纯答案协议使用预填和平衡截停；若采用跨题批量，左补pad路径对32条回答的teacher-forcing对数概率满足 a 的同一阈值，否则退回同题批量。
   - h. 写出 `TECHNICAL_CHECK_SR_F1_2.json`（PASS/FAIL及以上全部数字），取代 `train_path` 现在要求的ENGINE通过文件。
7. **预登记预测。** 用第1步的起点状态表写下§4.5的P1–P3和机制核对（含各题型族的分档结果），冻结。
8. **科学运行，按种子优先分三波。** 第1波 = 种子71001的A、J、GATE、DEC四条路径，各占一张卡同时跑；第2波71002；第3波71003。若第5张卡可用，PART的3条路径与第3波同跑；否则主结果完成后再决定。每8步提交检查点（不变）；第32/64/96步保存适配器并做训练拟合。
9. **终点评测**（§5的表）。可以趁后面波次训练时用空卡先评已完成的路径，但TEST结果在12条主路径全部结束前不汇总、不查看。
10. **报告。** 主终点与4个主对比；P1–P3和机制核对；每步耗时；采样器–训练器差异统计与截断比例；任何偏离修正案之处。

## 7. 不改的东西与风险

**不改：** 模型与精度（Qwen3.5-9B，bf16，原生模板，非思考模式）；数据、根与各题池；SR-F1.1协议（预填“{”+平衡截停、严格解析）；评分器与事件E、p\_read、P、A、J的定义；五种奖励的定义与参数（PART β=0.5，GATE κ=0.25，DEC权重\[1, 0.5, 0.5\]）；组大小8、每步16题、96步；T=1、top\_p=1、top\_k=0、max\_new\_tokens 768；每个token的k3 KL，系数0.02；梯度裁剪1.0；AdamW其余超参与常数调度；主终点（TEST\_ID上第96步的J）与自助法；TEST封存；不执行模型生成的代码。

**一处更正：** 预填前的格式基线以官方 237/247 = 95.95%（Wilson 92.71–97.79%）为准，我之前给的239/247没有复现；两处差异中confirm那条是证据实体重复，不是答案类型问题。格式门槛（252/256、500/512）照样通过，不影响任何决定。

**风险与对策：**

| 风险 | 对策 |
| --- | --- |
