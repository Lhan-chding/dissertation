## Q4：首次新 GPU 提交前的边界

1. 最新冻结源码在服务器完成全仓工程验收；显式排除读取封存confirm的旧测试，单列排除状态。
2. Q1/Q2完整非pilot原件通过技术核验，不要求复杂方法先胜过全部基线。
3. 生成准确 SOURCE_BINDINGS、Q4_BRIDGE_PLAN 和 Q4_STAGE_LOCK；核验旧9B模型、数据、运行环境和日志概率容差。
4. 交付准确 sbatch 命令、输出位置、逐类调用清单、历史实测依据与新V3吞吐未知部分。
5. 收到用户首次GPU明确授权后，才创建新的授权绑定并提交。原 pending 绑定保留。
6. 同节点两张PRO6000、两个独立进程；worker0历史初始原点，worker1历史warm原点。每worker六bank、十二probe、64初始draw；仅scratch候选Adam。
7. 实际设备UUID、显存、同原始动作跨卡token/sequence logp、独立pilot、MIX/DIRECT、原件与真实调用计费全部核验后，才生成桥接回执。Q4的64-draw参考不作精密建模确认。

恢复前验证已有完成worker原件及其实际null UUID，为未完成worker避开重复UUID；模型加载前再次核对实际CUDA UUID。两个worker完成后独立CPU合并；令牌不同、退出码0均不能替代跨卡回执。
