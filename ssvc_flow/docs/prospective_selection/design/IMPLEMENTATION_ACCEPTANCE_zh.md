# 实现与验收清单

目标是防止影响结论的错误，不重复大型形式化检查。

## 1. 数据与信息权限

- [ ] source384/continuation192仅来自train，六层均衡且场景/真值不重叠。
- [ ] P/D/T按元数据选取，paired接口保留base_scene_id；T未参与调参。
- [ ] Z0/Z1/Z2/Z3共享同一批P输出；高层不额外得到更多样本。
- [ ] Z2能恢复完整奖励向量分布，非只提供总分；Z3包含新repair结构。
- [ ] PreDecisionPacket拒绝OutcomeRecord、未来H8/H32结果、训练后的参数和测试回报。
- [ ] 分类器输入不包含lineage ID、未来run路径、recipe最终得分；task ID仅用于固定探针对齐。
- [ ] 不将同lineage的两个checkpoint拆到开发/调参/测试不同角色。

## 2. 数学与语义

- [ ] X⊆A⊆V，四类之和1；边际恢复恒等式通过。
- [ ] C支持来自精确关系计数，不随float阈值改变。
- [ ] trend关系全满足错误恒等式通过。
- [ ] F/B/M和X、coord_accuracy关系通过；非法用独立atom。
- [ ] 同奖励向量、不同B的例子确实可区分，Z2不能看到B。
- [ ] 核PSD、相同经验分布核值一致；sqrt经验频数无大量伪先验质量。
- [ ] alpha scale是K+n*alpha I，训练缩放不从测试集重估。
- [ ] R0的目标差值为0，共享R0相关性以原点/lineage块处理。
- [ ] 0.005只控制预测近似平局，不写成统计等效。

## 3. 真实训练路径

- [ ] 新旧R0/R4/GDPO/SAW在固定CPU bank上优势、loss、更新一致。
- [ ] DIRECT_REPAIR_R4单独命名和五通道日志，不修改旧R4定义。
- [ ] B4/K8、token mask、Lnorm64、单次update、clip/Adam/epsilon都按配置。
- [ ] 每分支自己的当前策略采样，不混用其他分支rollout。
- [ ] 分支起点恢复参数、Adam、RNG、模型mode/buffer与位置状态。
- [ ] 源sampler与新branch sampler明确分开，所有recipe的branch题序相同。
- [ ] 全零优势仍执行显式零梯度Adam；CPU测试覆盖动量非零情况。
- [ ] H8评估前后训练随机状态相同；有无诊断不会改变未来训练序列。
- [ ] 中断恢复不重复提交optimizer step，不将未提交attempt混入权威结果。

## 4. 学习与前瞻选择

- [ ] 全部静态8动作都用于开发，不能只保留旧D2赢家。
- [ ] 四层同样6个alpha，调参目标为动作选择后的J。
- [ ] BestStatic只由开发/调参决定。
- [ ] 所有测试决定在对应未来训练任务创建前写出。
- [ ] 冻结selector测试期间不更新；test集合不进入归一化/超参数选择。
- [ ] 同动作选择复用同一run；不同动作只因当前advantage相同不能预先合并完整训练。
- [ ] 两个future repeats先平均再统计；最终有效N按lineage计。

## 5. 精度与统计

- [ ] 运行冻结前precision planner，输出目标效应、SD来源、N_req、选定N和剩余MDE。
- [ ] 用MC预算而非全模型参数数目决定每题采样；写出全实验SE而非假定每题精确。
- [ ] 不做可选显著性停止；最终N/m在测试结果出现前锁定。
- [ ] 主比较只有Z3−Z2/H32；次要四比较Holm，不把上千坐标当主假设。
- [ ] 四cell分层配对t/lineage bootstrap区分固定panel与场景外推；功效规划不平均同源两anchor。
- [ ] zero variance、缺失结果、未采到X、同策略零差异都有明确定义。
- [ ] all-UNKNOWN不会伪造safe，也不会阻塞正常研究性对照训练。

## 6. 工程流程

- [ ] 一次原件导入检查、分支起点恢复检查、阶段版本记录；无每step9B哈希。
- [ ] 最多5个单卡项目作业；4卡自动降并发。
- [ ] 不同selector引用同一实际run；样本和模型不重复复制。
- [ ] 主评估不依赖额外teacher/LR全量评分。
- [ ] 没有把CPU fixture通过宣称为真实9B实验通过。
- [ ] 输出准确CLI及实测吞吐；不以计划参数冒充已完成更新数。

## 7. 必测反例

1. 两状态奖励分布完全相同但修复结构不同。
2. 修复结构不同但所有动作排序相同：不能伪造信息价值。
3. Z3仅是Z2的确定变换：理想信息价值无新增。
4. 两selector选择相同动作：结果引用同一run，差值0。
5. 未冻结试图运行测试branch：拒绝任务。
6. 修改E/T结果后再次`choose_action`：选择必须不变，或feature API根本无法访问结果。
7. eval RNG进入训练RNG：测试应失败并定位。
8. 源R0/R1配方或step能解释误差：四层均提供这些已知元信息。
9. 带图任务全部采到X：报告观测饱和，不称真实概率为1。
10. 中断后复用同checkpoint：不重复写入sample或多算实验N。

## 8. 测试执行频率

新增模块单元测试开发时持续执行；训练路径改变时执行相关旧回归；交付前一次完整可运行回归。明确缺失fixture和未执行项，不为获得一个绿色总数伪造文件。每个GPU branch不再跑一次全仓测试。

GPU smoke最低覆盖：实际模型加载、两个配方各2步、至少各一个图像/纯符号输入、评估后训练状态不变、保存恢复。smoke与正式source起点分开，不能污染正式训练。
