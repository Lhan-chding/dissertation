# 本轮计划概览

## 目标

证明或否定：在奖励选择前，了解模型“怎样修错、是否改坏原来正确信息”，能否比完整的奖励分布与历史统计，帮助选择更好的下一段强化学习操作。

## 与此前最重要的区别

- 不再先要求一个精细的全概率预测器，也不要求低维。
- 不是看到H32结果后选赢家；先冻结选择，再真实训练，最后在独立面板验证。
- 最强信息基线得到逐题完整X/A/V/C分布、任务分层和历史，不只给它一个accuracy。
- 新语义结构是否有用，要与直接增加修复奖励的简单方法比较。
- 调奖励后的主要目标仍是pX，不通过把自己的结构指标放进总目标制造优势。

## 核心实验

1. 复用旧端点，在原E面板复核语义现象；重建信息冗余目录。
2. 用12个开发lineage和4个调参lineage、各两个原点，收集八个静态配方与三个比较方法的真实32步结果。
3. 用同一组前置样本训练四层小型选择器：总体矩、分层矩、完整奖励分布、额外修复结构。
4. 冻结后在至少12个独立测试lineage作出前瞻选择；每个原点两次未来训练重复。
5. 主要比较是“修复结构”相对于“完整奖励分布”的实际H32收益。

## 精度与资源

主目标尺度设为1pp平均选择收益，不要求每道题/每个群体都先证明1pp非劣。测试seed数与评估采样量在测试前，依据开发方差和Monte Carlo噪声决定。近似平局、统计区间和安全保证分开。

最多5张PRO6000，默认一任务一卡；source、分支和评估并行。每个原点/配方/重复只训练一次，不因多个selector选中同动作而重复。减少重复哈希、全仓测试和冗余似然评分。

完整开发矩阵需要实质计算，首次4个开发lineage完成即交付结果和实际工期，不等大矩阵结束才能讨论方向。测试动作并集去重后再排队。

## 可能得到的结论

语义结构真的改善未见原点选择，才支持更丰富的概率状态。若只改善解释，不改善选择，或者直接修复奖励已经足够，应据此收紧方法。若两选择器经常作相同决定，报告真实的零增量，而不是改变测试目标。

本轮不直接宣称在线SSVC、连续权重最优或逐步安全；它验证从语义建模到训练决策的关键连接。
