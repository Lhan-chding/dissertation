## 变量目录与冗余

| 变量 | 定义与条件 | 能否从完整奖励信息恢复 |
|---|---|---|
| X | 精确四坐标世界正确 | 奖励通道 |
| A | 确定执行器的答案正确 | 奖励通道 |
| V | 严格合法四整数输出 | 奖励通道 |
| C | 满足的可靠关系数 / 可靠关系总数；非法为 0 | 奖励通道，保留精确有理数 |
| S、W、I | A−X、V−A、1−V | 完全可恢复，不构成新增信息 |
| C=1 且非 X | 完整 event×C 直方图直接恢复 | 可恢复；trend 还满足 2E[C²]−E[C]−pX |
| F | 唯一损坏坐标是否被恢复 | 一般不能由同题 event×C 恢复 |
| B | 原来正确的三个坐标中改坏几个 | 一般不能由同题 event×C 恢复 |
| M | 相对原观测改动的位置个数 | 一般不能由同题 event×C 恢复 |
| copy、single_edit | M=0、M=1 | 可从 M 恢复 |
| coordinate_accuracy | 合法输出 (F+3−B)/4；整体性能统计非法按 0 | 可从 F/B 与合法性恢复 |
| damage_any | 合法条件下 B>0 | 可从 B 恢复 |
| X 与 F/B | 合法时 X 当且仅当 F=1 且 B=0 | F/B 与 X 非独立 |

非法输出的 F/B/M/copy/single_edit/damage_any 为缺失，不把非法 B=0 当作保留了正确坐标。修复直方图使用 INVALID atom。DIRECT_REPAIR 的非法 Bdamage=1 属于奖励定义，不混入合法条件下的 B。

## 真实原始行核验结果

事件计数：X=29,766，S=801，W=5,235，I=1,062；trend 子集 12,288 条。下列逐行恒等式以整数或 Fraction 精确算术检验，绝对残差总和均为 0：

- S=A−X、W=V−A、I=1−V。
- trend 的 1[C=1 且非 X]=2C²−C−X。
- 合法输出 X=1[F=1 且 B=0]。
- 合法输出逐坐标正确数/4=(F+3−B)/4。

## 暴露与权限边界

历史 `access.jsonl` 有 2 条 dev 读取记录（2026-09-08，P3 frozen dev），4 条 calibration 读取记录（2026-09-09，R1 reference/smoke）。本次检查范围内没有 confirm 读取条目；原 D2 面板 manifest 写有 `sealed_confirm_read=false`。**日志中没有记录不证明从未读取**，本报告不把 confirm 的全历史暴露状态写成已证实未见。数据协议应结合可审计的来源与其他暴露证据作出相应标注。

原 D2 面板记录排除 720 个训练场景、24 个旧 R3 场景、3 个 debug 场景（部分排除集合重叠），prior_discovery 为空；原 P/E 各 36 场景，两种 interface 共 72 prompt。具体排除 ID 和面板 ID 已保存在机器审计的 exposure 字段，供新数据协议复用。本次在旧根目录全部 O* 端点的 LOOK manifests 中未发现 E 结果；缺失范围限定于已检查目录，不能推断其他未检查位置不存在 E 评估。后续 E 一旦有已看过的记录，必须标为外部面板复核。

## 数值与可复现性

关系分母不使用浮点阈值重分箱；上述恒等式用有理数检验，均无数值残差。低样本条件桶保留样本与缺失，不宣称零频率就是概率为零。不估计这 42 个桶的稳定条件互信息，不从诊断差异推断行动价值。

入口为 `src.prospective_selection.history.audit_history(config, out)`：服务器配置提供 `history_root`、`history_panels_path`、`history_access_path`；离线可提供 `history_import` 指向 collect_history 生成的 JSON/GZIP。只做首次导入审计，不要求每个 bank 重复执行。针对性测试 `tests/test_prospective_history.py` 已通过 3 项，覆盖真实定义的同奖励不同修复反例、严格重解析/重复样本拒绝、P 不能复用为 E、样本数不足拒绝。

当前可支持的结论仅为：奖励事件和部分诊断量存在确定冗余；真实旧输出存在奖励标签未包含的修复结构。是否改善新训练原点上的前瞻奖励选择，必须等待冻结后的独立实验。
