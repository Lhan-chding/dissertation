# 本轮计划概览：把可验证的协议互补转化为原协议学习

**2026-10-06｜新实验设计，尚未产生本轮模型结果。**

## 1. 这次要跨过哪一步？

现有实验已经发现：同一道修复题，换一种不增加答案信息的呈现或输出协议，可能得到原协议没有产生的正确解；用可靠验证器挑选正确结果，可以利用这种互补。但这些结果来自已参与开发的题，且推理组合成功不等于模型本身在原协议下变强。

本轮分开检验：

**新题上的互补 → 固定预算的正确样本发现 → 规范化的原协议监督学习 → 新题上的O0单次表现。**

不再把PTLC必须成立、低维预测器必须准确、复杂状态选择器必须胜出设为前提。本轮也不新建动态奖励控制器。它是在检验：改善“可用于学习的正确样本”这一环，能否为后续RL提供有效基础。

## 2. 为什么现在用SFT，而不是把变换回答塞回旧GRPO？

L11回答要逆排列，多个不同字符串又会被规范成同一个JSON，之后还只保留验证成功的回答。这样获得的是新的筛选数据分布，不能把原生成log-prob直接放入旧PPO比率。

本轮先采用明确定义的监督微调：模型输入一直是O0；标签是验证得到的规范正确世界；只对回答token计算损失。求解器全标注作为特权参照并行进行，不要求先“证明可学”才允许发现实验。

在相同题集上，solver标签与验证后的self标签完全相同，所以合并训练，不因标签来源名称不同重复一臂。

## 3. 四个主要对照

| 训练臂 | 正确标签如何获得 | 问题 |
|---|---|---|
| SELF_O0 | 每题16次O0生成中通过验证的题 | 普通筛选自训练基线 |
| SELF_MIX | 每题8次O0＋8次预定补充协议 | 多协议是否找到更有训练价值的成功集合？ |
| SELF_SINGLE | 每题16次验证集选定的最佳单协议 | 是否只是某一种协议更好，而非互补有用？ |
| GOLD_ALL | 全训练池的求解器正确标签 | 当前监督设置在充分标签下怎样表现？不是上界 |

主父模型上另有随机同规模、同family×污染位置组成的GOLD_MATCH_MIX，以及只保留共同回放贡献的REPLAY_ONLY。所有主要SFT配置、步数和目标一致。

小规模R0_RESET32只用于了解主奖励继续训练的上下文结果，不与SFT宣称严格同计算预算的胜负。

## 4. 新数据必须明确改变数值范围

旧D/P/U22都不能继续充当清洁确认集；剩余旧continuation没有目标符号cross/trend。历史0–49的trend在去除反转后仅392个不同真值集合，继续排除大量已用实例会遇到容量限制。

因此本轮登记新的合法域内分布：**真值0–99、观察0–99**，任务关系与单错唯一修复不变。它不是历史ID复现，也不是自动的结构OOD。

新T384、V96、E384个基础符号实例；另设96个保持性提示。按完整真值数值集合保守去重，任务的所有协议变体始终在同一基础实例里。生成前先报告历史排除后的容量，不足不静默改规则。

## 5. 模型与规模

复用S96、REP96两个现有R0源训练检查点，不重新训练源轨迹。每个主要流程两个“发现＋优化”重复；不是四个独立基座。

最多20次SFT，每次256步；另有4次32步R0参照。最多5张PRO6000，一卡一独立任务。严格相同的训练view可以合并；空发现集返回父模型，计入端到端结果，不填入求解器标签。

上限约205,504条新增回答、5,120次SFT更新和128次RL更新；与旧88分支不同，大部分训练不需要在线生成。无额外大规模似然重评分。先实测吞吐，不承诺完成天数。

## 6. 先交付什么？

第一批交付新数据分布、teacher发现覆盖、SFT因果mask/梯度验收、S96一个repeat的四个主要臂的训练与V诊断。其余任务按已冻结矩阵推进，不能看到早期哪个差就删哪个。E结果封存，不用于中途修改方法。

最后回答四个问题：互补有没有在新实例上成立？同预算有没有发现不同成功集合？它们有没有改善原协议？若没有，失败发生在发现、拟合、迁移还是保持性？

## 7. 这轮不承诺什么？

不承诺低维状态成功，不承诺所有奖励问题被解决，不承诺SFT结果就是内部“真实推理能力”，不把任一负结果判为架构不可学。2个百分点是解读参考，不是自动停止/追加采样阈值。精度以题级和运行级差异报告，不再设置每一小组都必须证明1个百分点非劣的统一门槛。
